# v2.118 - Archive health in the Operator portal

## Scope and source

Add Operator-only `/api/operator/archive-health` and a separate static SSR page
at `/operator/archive-health`. The page shows the observer timestamp, creation
time/age of the newest accepted first-attempt scheduled Archive on main, and all
four existing Archive warning states with fixed first checks and a runbook link.
Refresh obtains a new snapshot without JavaScript or automatic refresh.

The API reuses the existing trusted private Prometheus origin and feature switch.
One instant query reads only four fixed numeric fields using bounded 30-minute
`last_over_time` history, preserving duplicates for validation. A concurrent rules
read filters one group and excludes per-instance active-alert payloads. Each
request has a five-second total transport/body deadline and a 32 KiB limit;
at most eight metric samples and four rules are parsed. Redirects, cookies,
pagination, credentials and automatic retries are absent from this transport.

Application owns validation and age calculation. Prometheus query samples must
be nonfuture and at most 60 seconds old. The observer's own timestamp must be
nonfuture and at most 30 minutes old; old timestamps produce Stale even when a
current query returns them. A failed observation masks retained success values.
Missing, duplicate, nonfinite, negative or inconsistent values produce Unknown.
Known absence of an accepted success keeps age unknown; zero age remains valid.

The rule snapshot is independent. It requires exactly the four known identities,
group/component/severity, healthy evaluations and Inactive/Pending/Firing states.
The oldest evaluation must be nonfuture and at most 60 seconds old. Stale or
unusable rules do not display purported current inactive states. An available
observation can coexist with a firing delay warning. UI age is recalculated from
the validated timestamp; neither manual runs nor reruns refresh schedule age.

## Security and compatibility

Existing Operator policy and stable-subject validation protect the API and page
before source reads. The BFF keeps bearer tokens server-side; its response has
an explicit 16 KiB body bound and seven-second deadline. Both surfaces use
no-store. The Web projection independently validates time, identities and shape.
Provider text, annotations, addresses, paths, run/object identifiers, unknown
fields and secret material are never reflected. Public/Reader surfaces retain
their current behavior. An old API's missing endpoint yields Unknown in new Web;
old Web does not depend on the additive endpoint.

This R1 release updates only API/Web with independently verified digests. The
existing observer, rules, thresholds, schedules, exporter pin, B2 keys, IRM,
game/agent, database and permissions remain unchanged. Rollback restores only
the recorded previous API/Web digests and exact deployment inputs. There is no
migration, archive write, queue mutation or durable-state conversion.

## Interpretation

The existing three/18-hour thresholds and five-minute warning holds are displayed
as guidance, not recalculated into provider warning states. A successful workflow
does not independently validate its stored object, source completeness, external
notification delivery or an achieved SLO. Separate Recovery remains necessary.
The portal does not dispatch, retry, acknowledge, silence or change policy.
