# v2.112 - First checks for Operator game-host warnings

## Scope and compatibility

Add static first checks, evidence-preservation notes and fixed runbook section
links to the existing 17 warnings on `/operator/game-host-health`. Unknown and
Stale snapshots, including an unavailable whole-page read, have separate
guidance. A general guide link remains available when the fresh list is empty.
Unknown warning names cannot provide a guide URL.

The existing Operator authorization, BFF token boundary, no-store response,
static SSR and manual Refresh behavior remain unchanged. Strings are rendered
as text, not raw HTML. All guide destinations are fixed application constants;
no name, description, component or provider text becomes a URL. Grafana links
retain their independent private access and sign-in.

Only Web runtime changes (R1). API/contracts, rule catalog, collectors, database,
game/agent, notification delivery, credentials and permissions are unchanged.
The Web remains compatible with the accepted v2.111 API. Rollback replaces
only Web with its accepted v2.111 immutable digest; no durable state changes.

See the [triage guide](game-host-warning-triage.md). It describes observation,
not permission to restart, clean, replay, capture a backup or modify a journal.
It links the existing owning runbooks rather than changing their policy.
