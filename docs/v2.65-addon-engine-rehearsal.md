# v2.65 - Движковая репетиция обновления addon

Статус: репетиция выполнена, PR #313 слит; полный PR CI и post-merge CI прошли.
Срез проверяет workflow v2.64 на настоящем ReHLDS с неизменными weapon addon
0.23.0 и 0.24.0. Production installation, новые addon packages и изменения
игрового поведения не входят в этот этап. Первое production применение
workflow остается отдельной R3-приемкой следующего addon release.

Этот документ сохраняет результаты v2.65. Текущий engine-драйвер обновлен
для перехода 0.24.0 -> 0.25.0 с постоянным включением поиска; его точные
пакеты и новые результаты находятся в [readiness v2.76](v2.76-readiness.md).
Для повторения исторического сценария использовать ревизию v2.65 и ее входы.

## Runtime probe

[addon-runtime-probe.py](../ops/gameserver/addon-runtime-probe.py) выполняет
только `goldsrcops_weapons_status` и `goldsrcops_stats_status` через RCON на
`127.0.0.1`. Порт задается в проверенном hook, DNS и удаленные адреса не
поддерживаются. Перед production использованием отдельно проверить доступность
существующего local listener; этот срез не меняет bind/firewall сервера.

Ожидаемые версии задаются root-only JSON mapping из одного-двух manifest SHA-256
в версии. SHA-256 самого mapping закреплен в hook. Для каждого запроса берется
новый challenge; лимиты - 4 секунды, 8192 байта на datagram, 16384 байта на ответ.
Повторных отправок команды нет. Требуются однозначные строки с ожидаемой
версией, enabled addon, готовыми nVault/индексом и нулевыми счетчиками ошибок.
Отсутствие строки, другая версия, поврежденный или чрезмерный ответ отклоняются.

Пароль поступает только через stdin из существующего доверенного локального
источника. Его нет в аргументах, environment, результате или диагностике.
Probe не создает credential store. Ошибки выводятся одной безопасной строкой.
Непустой `error_*.log`, symlink или более 128 error files в явно указанном
AMXX logs directory блокируют приемку. Старые ошибки также блокируют проход:
скрипт не удаляет их и не объявляет их несущественными автоматически.

Пример тела root-owned frozen acceptance hook для [v2.64](v2.64-addon-upgrade-workflow.md):

```bash
# EXPECTATIONS, EXPECTATIONS_SHA, LOG_DIRECTORY и PORT фиксируются в hook.
# SECRET_READER - закрепленный локальный reader существующего secret.
# Он читает secret заново при каждом вызове hook: preflight/candidate/rollback.
set -Eeuo pipefail
"$SECRET_READER" | python3 -I -B "$SOURCE/ops/gameserver/addon-runtime-probe.py" \
  --expectations "$EXPECTATIONS" --expectations-sha256 "$EXPECTATIONS_SHA" \
  --error-directory "$LOG_DIRECTORY" --port "$PORT" "$@"
```

Hash этого hook и mapping входят в freeze. Исходники probe и его policy module
размещаются вместе с проверенным source tree. Сохранение process identity,
A2S, payload/receipt hashes, baseline и rollback по-прежнему проверяет внешний
workflow; отдельный probe не заменяет эти проверки. Это probe только weapon
addon. Map-menu и внешний monitor/Grafana не считаются покрытыми этим срезом.

## Изолированный стенд

[game-addon-upgrade-runtime.sh](../tools/smoke/game-addon-upgrade-runtime.sh)
проверяет SHA-256 архивов ReHLDS 3.15.0.896, ReGameDLL 5.30.0.814,
Metamod 1.3.0.149, AMXX 1.10.0.5481 и ReAPI 5.24.0.300 и распаковывает их
в одноразовый контейнер. Контейнер запускается с `--network none`, без
опубликованных портов; все входные mounts read-only. Нужен подготовленный
engine image с CS 1.6 base files, Python 3, Bash, jq, gosu и 32-bit runtime.
Движок работает от непривилегированного пользователя `steam`.

Закрепленные manifest hashes:

| Пакет | SHA-256 |
| --- | --- |
| 0.23.0 | `4e1e3a7de8280c6d4c7df7f250f351cef1b07417123412ef5beb2806107c4c31` |
| 0.24.0 | `03950d9b54e20718fcb836891652b8879e1ec03a02837f420492d3a12bedef61` |

[Драйвер](../tools/smoke/addon-upgrade-engine.py) повторно использует setup
изолированного v2.64 fixture. Systemd, prepared-host metadata и агент остаются
контейнерными адаптерами; start/stop, A2S, RCON, plugin, nVault, installer,
receipt, phase journal, transition lock и baseline helper настоящие.
Подтверждения действительного systemd/SSH окружения этим не заявляются.

Отдельный [AMXX fixture](../tools/smoke/amxx-addon-upgrade-vault.sma) создает
синтетические записи статистики, языка, основного оружия, пистолета, HUD,
рекорда серии и имени. Он работает отдельно от product plugin. После переходов
nVault перечитывается отдельным процессом AMXX, а bytes закрытых vault
сравниваются с исходными. Это сохранность записей, не клиентская проверка
применения языка/оружия/HUD после reconnect.

Проверены три перехода:

1. Принятое обновление 0.23.0 -> 0.24.0 с согласованием baseline.
2. Отдельный frozen plan 0.24.0 -> 0.23.0 с обратным baseline.
3. Отказ дополнительного условия после успешного runtime probe кандидата;
   workflow возвращает 0.23.0, исходный baseline и `rolled-back` без pending.

Дополнительная отрицательная проверка заменяет binary на диске кандидатом
при продолжающей работать 0.23.0. Probe отклоняет кандидат; fixture возвращает
исходный binary до начала настоящего перехода. Disk hash не подменяет
доказательство загруженной версии.

Для воспроизведения скомпилировать AMXX fixture закрепленным compiler 5481 в
`addon_upgrade_vault.amxx`. Подключить к контейнеру каталоги: `/repo` - checkout,
`/runtime` - два engine zip, `/assets` - два AMXX tar.gz и Metamod/ReAPI zip,
`/compiled` - fixture, `/previous` и `/candidate` - content пакетов из таблицы.
Entry point: `bash /repo/tools/smoke/game-addon-upgrade-runtime.sh`.
Все mutable state и случайный fixture RCON secret остаются внутри контейнера.

## Проверки и границы

Локально выполняются движковая репетиция и направленные отрицательные проверки
probe. В required CI добавлены семь probe tests и проверка shell syntax.
Настоящий engine rehearsal не включен в hosted CI: ему нужны предварительно
подготовленные base game files и закрепленные packages. CI не выдается за
движковую приемку. Application source не менялся; полный локальный .NET/browser
suite не повторяется, required full PR/post-merge CI остается обязательным.

Визуальная приемка v2.63, первый успешный weekly timer и игра вдвоем остаются
независимыми. Рабочий сервер, его source tree, backup и расписание не меняются.

Локальная финальная репетиция завершилась `ADDON_ENGINE_REHEARSAL=passed`:
приняты upgrade и planned rollback, отказ кандидата завершен `rolled-back`.
После каждого перехода проверены фактически загруженная версия, согласованный
baseline и точное совпадение bytes закрытых vault. Завершающий отдельный
AMXX-процесс перечитал все синтетические записи. Pending и AMXX error logs
отсутствовали. Probe отклонил candidate binary на диске при работающей 0.23.0.

Семь probe tests, все 18 прежних workflow cases, pinned compiler validation,
shell syntax, actionlint 1.7.12 и документация прошли. Локальная проверка ссылок
охватила 159 файлов и 934 ссылки. Полный локальный .NET/browser suite не
повторялся; эти проверки выполнены required CI.

Production source/игра/агент, данные и расписание backup не менялись.
Пакеты, release tags и container images не публиковались. Первый production
запуск workflow и визуальная приемка v2.63 остаются независимыми следующими
проверками; успешная изолированная репетиция не выдается за их выполнение.
