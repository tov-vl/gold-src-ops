# v2.28 Fast Re-entry Loadout

Status as of 2026-09-25: local implementation and focused checks complete;
the public pilot host still runs the accepted v2.27 profile. No target switch
or player acceptance has been performed for this revision.

## Product Boundary

Fast respawn currently returns a player with the classic starting equipment.
The next playable step gives both teams the same MP5 primary weapon on spawn
and refills its backpack ammunition. It retains the current pistol, spawn
protection, team rules, buy rules, five-map rotation, and event pipeline.
Weapon menus, progression, ranks, bots, custom spawns, and continuous
Deathmatch are not part of this slice.

The pinned ReGameDLL_CS `5.30.0.814` provides
`mp_t_default_weapons_primary`, `mp_ct_default_weapons_primary`, and
`mp_refill_bpammo_weapons`. The new profile sets both team defaults to
`mp5navy` and the refill switch to `1`. The existing active filename and
`mapchangecfgfile` remain unchanged; the new source file is a separate,
hash-bound revision rather than an in-place edit of `fast-reentry-v1.cfg`.

## Transition And Recovery

The persistent guard accepts only the exact v2.27 and v2.28 fast-profile
hashes. `fast-reentry-transition.sh --upgrade-loadout` is plan-only without
`--apply`. On apply it requires the accepted v2.27 profile, exact retained
classic backup, settled agent state, and independent external zero-player
A2S and read-only RCON gates. It stops the game, replaces only the profile
and matching hash-bound markers and guard, then restarts the two independently
guarded services. A failed mutating step restores the exact classic profile,
starts only guarded services, and leaves both boot entries disabled pending
recovery. Queue, spool, and identity are not reset. The v2.27 source remains
available in Git, but automatic failure recovery targets the recorded classic
backup, not an unverified fast-profile snapshot.

This game-host switch is R3 because the boot guard and recovery boundary are
involved. It requires a separate reviewed host decision after repository CI.
Do not edit the installed profile in place or use the persistent-agent
rollback as a mode switch.

## Evidence And Remaining Gate

- Profile smoke accepts both exact revisions and rejects changed or
  unreviewed hashes.
- Transition smoke covers activate, upgrade, restore, external postcheck
  refusal, partial installation, and classic rollback with queue and spool
  evidence retained.
- A disposable network-isolated server with pinned ReHLDS and ReGameDLL_CS
  started and reported `mp5navy` for both default-primary cvars and `1` for
  backpack-ammo refill. This proves configuration application, not that a
  player's inventory visibly contains the weapon.
- After an approved host switch, one short player join, team selection, death,
  respawn, weapon/ammo observation, and exit is sufficient for the narrow
  loadout claim. An independent external A2S and guard check closes the gate.
  No additional map cycle or multi-round soak is required for this MVP claim.
