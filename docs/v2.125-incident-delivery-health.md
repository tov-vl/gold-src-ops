# v2.125 - Incident delivery in the operations overview

## Scope

Extend `/operator/health` with two independent read-only cards: the incident
outbox and receiver provider queue. Existing API/receiver contracts, server-side
clients and authentication are reused. A linked ten-second deadline also covers
body reads, independently of the HTTP response-header deadline. Each
configured source is requested once; all six reads start concurrently and share
the caller cancellation token. Expected source failures isolate that source.

Outbox facts show dispatcher configuration, pending/processing/dead-letter
counts and the oldest pending time. Receiver facts add Web access, CatchUp/Live
mode, provider worker configuration and unreviewed dead letters. CatchUp is
displayed as catch-up / sandbox, separately from the provider worker state;
it suppresses new provider work, not necessarily earlier queued work.

Missing, future, pre-epoch, inconsistent or negative observations are Unknown.
Queue snapshots older than 60 seconds are Stale. Invalid or stale counts never
become zero. Pending requires a nonfuture oldest timestamp no later than the
snapshot; zero pending requires its absence. Counts are not added, avoiding
overflow. An unreviewed count cannot exceed dead letters. Raw receiver mode
strings and provider error text are not reflected.

Disabled Web receiver access sends no receiver request, shows Disabled and
leaves its facts Not queried. A configured but disabled worker still shows its
observed queue. Empty queues and enabled workers never prove delivery or email
receipt. This incident notification path is separate from Prometheus to
IRM/email; no new combined health or notification-success result is computed.

The page retains Operator authorization, no-store, static Refresh, independent
source/rule times and fixed detail links. The existing text report still contains
only game-host, Archive and polling snapshots and performs a separate read.

## Delivery boundary

R1, install only Web. No API/receiver installation, schema, queue mutation,
worker enabling, provider configuration, new permission/secret, monitoring rule,
game/agent or Archive cadence change. Preserve the prior Web digest, exact env
bytes and fourteen other container identities/restarts. Rollback restores only
that Web boundary; unknown drift or uncertain operations require reconciliation.
Stable promotion must reuse accepted candidate digests without rebuilding.

## Verification and readiness

Focused cases cover all 64 configured-source failure combinations, six-read
concurrency/cancellation, disabled access without a request, exact freshness,
invalid dates/counts/mode, empty/large queues and independent worker/mode state.
SSR checks cover role denial without reads and ordinary Refresh. Browser checks
cover JavaScript-disabled desktop/mobile, partial failures, fixed detail/return
navigation, token boundaries and no horizontal overflow.

The audit-enabled local quality gate passed restore, format, a warning-free
build, 1810 tests and dependency audit. Its 67 opt-in browser cases are reserved
for hosted CI. Focused checks passed 107 cases, including response-body deadline
and caller cancellation; the actual JS-disabled desktop/mobile fixture passed.
Scoped InspectCode completed with zero errors and zero warnings. All 61 notes
were reviewed; retained conventions and cancellation-test exceptions are recorded
privately. No suppression was added.

Required PR/main CI, immutable publication, independent Web-only runtime and
authenticated overview acceptance remain release gates.
Fixtures do not prove live failure handling, provider delivery, email receipt,
future Archive cadence, Recovery or an achieved SLO.
