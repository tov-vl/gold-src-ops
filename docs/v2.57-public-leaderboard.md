# v2.57 - Публичный топ-10

## Граница среза

R2: addon 0.23.0, API и Web. Публичная страница `/leaderboard` показывает
готовый топ-10 `/topall`: позицию, сохраненный ник, ранг, убийства и смерти.
Сортировка addon (убийства убывают, смерти возрастают, приватный ключ разрешает
равенство) остается источником порядка. SteamID и ключи не передаются.
Счетчики, пороги рангов, nVault schema и игровые сохранения не меняются.

## Контракт чтения

Фиксированная серверная команда `goldsrcops_leaderboard_snapshot` читает общий
кеш после обычного bounded refresh (не чаще пяти секунд). Не пишет в vault,
не меняет игровые настройки и не выполняет клиентские команды.
ASCII-кадр версии 1: `GSLEADER 1 <unix-seconds> <count>`, от нуля до десяти
`GSLROW <position> <rank-0-4> <kills> <deaths> <utf8-hex-name>`, затем
`GSLEND 1 <unix-seconds> <count>`. Пустое имя обозначается `-`.
Недоступный индекс или отключенный addon: только `GSLEADER 1 unavailable`.
Время обозначает получение снимка кеша, а не последний бой или запись на диск.

API читает раз в минуту с трехсекундным timeout через существующие регистрацию
сервера, secret reference и ограниченный UDP RCON transport. Источник - только
сервер из `PublicServerJoin:ServerId`; `PublicLeaderboard:Enabled` по умолчанию
false. Наличие незавершенных операторских команд пропускает этот проход.
Самплер не добавляет команд в очередь и не пишет в PostgreSQL. Его отдельное
UDP-соединение не меняет сериализацию операторских команд; гонка с новой
операторской командой безопасна, поскольку экспорт не имеет игрового эффекта.
Новые credentials, permissions и публичный RCON не требуются.

Парсер принимает только полный кадр не более 2048 символов, непрерывные позиции,
правильные ранги и порядок счетчиков, строгий UTF-8 и имена до 31 байта.
Время должно быть от двух минут назад до 30 секунд вперед. Поврежденный или
обрезанный ответ не публикуется. Имена HTML-экранируются SSR; SteamID-подобный
ник заменяется на "Игрок". Ответ `/api/public/leaderboard` содержит только
state, CapturedAtUtc и десять безопасных строк. Браузер не обращается к API/RCON.

## Свежесть и восстановление

Процесс API хранит только последний валидный снимок в памяти. Успешный снимок
не старше трех минут имеет состояние fresh; неудачный проход или возраст больше
трех минут - stale. После суток данные удаляются из публичной проекции.
Явно недоступный источник очищает кеш сразу. Перезапуск API начинает с unavailable
до первого успешного чтения. Ошибки логируются без ответа, имени, адреса или
секрета. Повтор - только следующий плановый проход, без немедленных retries.

Rollback: вернуть записанные предыдущие API/Web digests и предыдущий addon.
Установку addon выполнять только после свежего empty-server preflight.
Миграция/restore, смена сохранений и перезапуск прочих компонентов не нужны.
Совместимость: старый API игнорирует новую команду; новый API со старым addon
показывает unavailable. При mixed-version Web отсутствующий endpoint дает
понятное состояние недоступности и сохраняет ссылку на `/play`.

## План доказательств

- Изолированный engine: полный экспорт, совпадение с кешем, tie order, UTF-8,
  пустой/недоступный индекс; чтение не меняет сохранения.
- .NET: строгий парсер, bounded snapshot, свежесть, сбои, cancellation,
  server/credential binding, публичный контракт и SSR escaping.
- Браузер: anonymous navigation, fresh/stale/unavailable/empty, desktop/mobile
  без overflow, токенов и прямых browser-to-API запросов.
- Локальный Quality Gate, required CI, immutable artifact checks; production
  empty-server addon rollout, API/Web rollout и bounded read acceptance.
- Первая недельная backup, v2.55 real-client, игра вдвоем и личные уведомления
  остаются независимыми от этого среза.
