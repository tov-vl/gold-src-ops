# v2.91 - Required map-menu engine smoke

Status on 2026-10-21: released in `main`; required product and post-merge CI passed.
Hosted artifacts independently verified.

## Scope and release boundary

The required `Container Smoke` check extends the v2.90 engine suite with two
map-menu cases: the real player-language provider and client-language fallback
without that provider. They execute the existing map addon source inside the
pinned, disposable ReHLDS/ReGameDLL runtime. No production plugin, dictionary,
addon version or server configuration changes. Weapon addon remains 0.36.0;
map addon remains 0.2.0.

Risk is R3 for CI policy. The authorized delivery covers ordinary push, product
PR, green required CI, squash merge, post-merge CI and a final evidence PR.
No application tags, image publication, addon publication or production rollout
apply. Reverting the CI change restores the v2.90 gate without player-data
recovery. The initial base is `ff2faf6bfb830487f1f35f89899bb7bf5ad5260d`.

## Coverage and isolation

The two cases require different commands, log files and completion markers.
Each asserts whether the language provider must be present; its absence cannot
silently skip provider checks. The provider fixture includes the real weapon
addon and its language native. Both runs use two synthetic clients in an
isolated engine, with only the designated fixture client bypassing bot exclusion.

The scenarios check:

- RU/EN current-map labels and their UTF-8 bytes;
- manual language sharing, unset/unsupported client language and disabled
  provider fallback;
- stale-language menus, cancellation, invalid/current-map selection;
- the managed profile's five-map cycle, reordered/truncated/extra entries and
  an unexpected mapcycle path;
- native voting policy, disabled addon, spectator and ordinary bot guards;
- one-based native map IDs, native single-player refusal, a recorded vote with
  two synthetic clients, and no forced map change from one of two votes;
- actual native `timeleft` forwarding for RU and EN, including spectators.

`engine-ci.py` transfers nine hash-bound binaries, including the map product,
map fixture and provider fixture already built by `Map Menu Compile`. Source
identity now includes the map dictionary and compiler script. The case plan
rejects duplicate log commands, unknown plugins and duplicate companion plugins.
Each engine process replaces its plugin list, so the fallback case cannot inherit
the provider from the preceding process.

The obsolete standalone map runtime setup now only prepares map inputs for the
shared runner. It renders the actual managed mapcycle and uses the same pinned
archives, image digests, no-network/no-published-port container, read-only inputs,
unprivileged engine user, 45-second process and 600-second suite limits.
The archive and image pins are unchanged from v2.90.

All 20 positive cases require 31 exact success markers and no AMXX errors.
The existing deliberate assertion remains mandatory. A second actual engine
negative test requests provider coverage while deliberately omitting that plugin;
the harness requires the precise missing-provider assertion and failed runner
result, with successful owned-container cleanup. Setup failures cannot substitute
for this assertion. Both negative evidence directories and the positive evidence
are retained for seven days, including failed CI runs.

## Local verification

Use the [v2.90 commands](v2.90-engine-ci.md#local-command), additionally compiling
the map product plus `amxx-map-menu.ps1 -RuntimeFixture` and `-ProviderFixture`
into the same compiler cache before packaging. The integration test also creates
an output directory whose name has the suffix `-map-provider`; all outputs must
be new directories. Python 3.12 or newer and Docker are required.

Local verification passed on 2026-10-21:

- All nine binaries compiled with the pinned AMXX/ReAPI toolchain. The initial
  fixture compile rejected a Pawn boolean-tag mismatch, corrected before testing.
- Ten runner tests, the CI routing contract and tracked documentation checks passed.
- The complete engine suite passed: 20 cases / 31 markers in 172.433 seconds.
- The intentional assertion was rejected in 69.393 seconds; the missing-provider
  assertion was rejected in 48.661 seconds. Both exact failures were verified.
- All owned containers were removed; no nonempty AMXX error log was present in
  the successful suite. Image/archive pins match v2.90; cached inputs were rehashed.

Full hosted CI passed restore with NuGet audit, formatting, build, tests, the
vulnerable-package report, container checks and browser checks. The unchanged
.NET suite was not repeated locally. No C# code changes; InspectCode is not
applicable.
