# v2.64 - Проверяемое обновление addon

Статус: инструмент слит в main; required PR CI и post-merge CI прошли.
Класс R3 для будущего исполнения: orchestration остановки/запуска игры,
обновления addon и согласования recovery baseline. Этот срез поставляет
операторский инструмент и тесты. Production rollout нового addon не требуется:
0.24.0 и отложенная визуальная приемка v2.63 остаются отдельными.

## Граница

[addon-upgrade.py](../ops/gameserver/addon-upgrade.py) объединяет существующие
installer, проверки сохранений и baseline helper. Поддерживаются enabled
schema-2 weapon-selection и map-menu: новый binary, необязательное изменение
словаря, неизменные config/loader. Первая установка, отключение, удаление,
смена схемы, gameplay и restore не входят в этот workflow.

Все исходники из одной проверенной ревизии размещаются вместе в root-owned
source tree, включая `player_data_schedule.py`, `player_data_manual.py`,
`player-data-baseline.py`, `player-data-bundle.py`, оба guard и существующие
installer/persistent dependencies. Обновленный `player-data-scheduled-capture.py`
должен быть установлен до первого использования workflow: он блокирует capture
при незавершенной addon operation. Не копировать только новый entrypoint.
Текущий production source этим срезом не обновляется; совместимую установку
source tree и первое настоящее исполнение принять при следующем addon release.

## Frozen plan

Владелец хранит JSON вне Git, в закрытом root-owned каталоге. Поля:

| Поле | Значение |
| --- | --- |
| `schema` | `1` |
| `operationId` | Новый идентификатор `[a-z0-9-]`, до 64 символов |
| `kind` | `weapon-selection` или `map-menu` |
| `previous`, `candidate` | Объекты `directory` (абсолютный путь к content) и `sha256` (точный manifest hash) |
| `baselineSha256` | Заранее проверенный hash текущего backup baseline |
| `acceptance` | Объект `path` и `sha256` проверенного read-only Bash probe |

SHA-256 всего JSON передается отдельно. Все manifest/payload и probe проверяются
до остановки; symlink, неподходящие права, чужой baseline и измененный config
отклоняются. Plan не содержит credentials или произвольной shell-строки.
Probe получает два аргумента: kind и manifest hash. Он обязан проверить реально
запущенную версию, загрузку plugin и AMXX errors именно для этого артефакта,
понимать обе версии и завершаться за 45 секунд. Disk hash сам по себе не заменяет
такую приемку. Probe выполняет только чтение, использует существующий закрытый
доступ и не выводит credentials. Его успешный exit является явной доверенной
границей оператора, а не автоматическим доказательством корректности любого probe.

```bash
sudo -n --preserve-env=SSH_CONNECTION python3 -I -B "$SOURCE/ops/gameserver/addon-upgrade.py" \
  --plan "$PLAN" --plan-sha256 "$PLAN_SHA256"

sudo -n --preserve-env=SSH_CONNECTION python3 -I -B "$SOURCE/ops/gameserver/addon-upgrade.py" \
  --plan "$PLAN" --plan-sha256 "$PLAN_SHA256" --apply

sudo -n python3 -I -B "$SOURCE/ops/gameserver/addon-upgrade.py" \
  --plan "$PLAN" --plan-sha256 "$PLAN_SHA256" --inspect
```

Первый вызов проверяет plan/host без остановки и без execution claim. Служебные
lock files могут создаваться. SSH context сохраняется явно; ожидаемый оператор
берется из prepared host marker. Подмена host paths через GOLDSRCOPS environment
не допускается. `--inspect` читает только сохраненный статус, даже если текущий
runtime уже не соответствует исходному plan.

## Этапы и результат

1. Взять schedule, backup и transition locks в существующем порядке. Transition
   lock остается у родителя и передается installer через проверенный inherited
   descriptor; другая операция не получает промежуток между stop и приемкой.
2. Создать закрытый execution claim и журнал. Проверить прежний addon/baseline,
   runtime и немедленно перед stop запросить занятость через локальный A2S.
3. Остановить только игру. После подтвержденной quiescence записать hashes двух
   vault и присутствующих journal, установить точный package, сравнить закрытые
   сохранения и остальные baseline invariants. Raw player data не сохраняются.
4. Запустить игру, дождаться A2S и выполнить frozen acceptance probe. Агент
   должен сохранить свое runtime-состояние.
5. Согласовать baseline через существующие `prepare/apply`, сохранив отдельные
   create-only before/after evidence. Проверить guards и неизменность runtime
   во время обновления baseline, затем завершить claim как `accepted`.

Подтвержденный отказ до stop заканчивается `refused`. Подтвержденная ошибка после
установки допускает `rolled-back` только после сверки известного installed package,
повторного empty-server gate, возврата предыдущего addon, независимой приемки и
обратного согласования baseline. Текущие player files сохраняются, restore нет.
Если игрок уже вошел, rollback не останавливает сервер автоматически.

Timeout, signal, неизвестный artifact, drift закрытых сохранений или неудачный
rollback оставляют `reconciliation-required` и pending. Повтор этого или другого
plan заблокирован; scheduled capture также запрещен. Журнал содержит фазу до
каждого эффекта, безопасную категорию ошибки и результат. Ошибка SSH не означает,
что операция не началась. Не удалять pending ради retry: сначала независимо
сверить host, артефакт, сохранения и baseline и записать решение оператора.

Один plan выполняется не более раза, в том числе после `refused`. Новый разрешенный
проход получает новый operationId и заново проверенные hashes. Плановый откат
уже принятого release - отдельный plan с переставленными пакетами. Не более
52 локальных записей workflow, без автоматического удаления.

`accepted` относится к game host и backup baseline. Control-plane monitor/Grafana
и реальная клиентская приемка остаются независимыми release gates. Инструмент
не запускает backup, не меняет weekly ledger/timer и не активирует уведомления.

## Проверка

Изолированный Linux fixture использует настоящие installer, receipts, nVault
файлы и baseline helper; systemd, процессы и version probe заменены синтетическими
адаптерами. Проверяются upgrade/rollback обоих addon, busy, отказ installer,
ошибка после baseline update, чужой lock, сохранение lock, отсутствие SSH context,
повтор/чужой pending, timeout, failed start, вход игрока перед rollback и drift
player files. Это не production или игровой engine acceptance.

Дополнительно проверяются существующие schedule/maintenance и обе installer
fixtures. Полный CI сохраняется из-за изменений orchestration/shared policy;
новый тест включен в Container Smoke. Полный локальный .NET/browser suite не
повторяется: application code не менялся, required full CI остается обязательным.
