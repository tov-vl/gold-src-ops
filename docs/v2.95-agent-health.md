# v2.95 - Local game-event agent diagnostics

## Scope and compatibility

The agent status command passively observes an existing SQLite queue and spool.
It no longer initializes SQLite, migrates its schema or creates spool folders.
Missing/unreadable/unsupported queue state fails closed without a zero-count
health claim. Existing schema-1 JSON fields and queue/spool counts remain;
timestamps, waiting age, spool availability and cycle evidence are additive.
No queue schema or public HTTP contract changes.

The oldest waiting event is the oldest pending or in-flight enqueue, including
backoff. Dead letters remain separately counted. An empty waiting queue has
null age. All age calculations in one status capture use one TimeProvider value.
SQLite read-only access can use ordinary WAL coordination files; this is a
no-business-write guarantee, not a promise of zero filesystem coordination.

Import and delivery publish process-local cycle evidence to one bounded JSON
sidecar next to the queue. Atomic replacement prevents partial reads. One fixed
temporary path bounds failure debris; a pre-existing temporary record is not
deleted or overwritten. Publication errors are logged without secret details
and do not change worker error, retry, lease or cancellation behavior.

| Evidence for an enabled loop | State |
| --- | --- |
| Missing, invalid, future-dated or incompatible record | unavailable |
| First pass started, not yet completed | starting |
| Recent completed idle/progress pass, or an active subsequent pass | running |
| Latest pass failed | failed |
| Latest delivery pass rescheduled work | retrying |
| Latest pass rejected/deferred or dead-lettered work | blocked |
| No activity within its configured budget | stale |
| Loop exited | stopped |

Disabled loops report disabled. A current in-progress pass can outlive the
previous completion while remaining within its budget. Budgets are inclusive:
import uses 10 seconds plus twice the interval plus three queue busy-timeouts
per batch entry; delivery uses 10 seconds plus twice the interval plus two HTTP
timeouts and three queue busy-timeouts per batch entry. These are conservative
diagnostic allowances, not a deadline or an availability SLO.

`LastSuccessfulAtUtc` describes a completed error-free pass, including idle,
not necessarily an accepted HTTP event. A server with no rounds can have live
idle loops. Retry/dead-letter/rejected counts and waiting age must be assessed
alongside liveness. No restart, replay, cleanup, notification or Prometheus
integration is added.

## Verification and delivery gates

- Focused tests cover passive capture, oldest age, old-schema refusal, healthy
  idle, exact expiry, stuck cycles, process restart, corrupt/oversized evidence,
  disabled/configuration mismatch, write failures and bounded temporary files.
- Worker tests exercise idle import, a failed delivery followed by the same-byte
  successful retry, and an import exception that still propagates.
- Full .NET gates and scoped Hint-and-higher InspectCode are required before PR.
- Required product and post-merge CI precede repository completion.

regressions, all 73 focused agent tests passed. An isolated real CLI exercise

floating-point equality, redundant imports/DI syntax and applicable new style
findings were fixed. The second complete scoped pass had zero errors, zero
warnings and 38 notes; the final two-file pass also had zero errors/warnings.

deserialized JSON despite non-null C# declarations. Existing broad exception
handling preserves worker/CLI semantics. Unrelated parser/async suggestions in
Program remain outside this slice. No suppressions or analyzer settings changed;
this is not a zero-findings claim.
