# v2.119 - Bounded source completeness and Archive window diagnostics

## Boundary

This operational release adds an offline diagnostic projection to the existing
read-only 24-hour shadow audit. It does not change the exporter, its reviewed
pin, evaluator, target, canonical-attempt selection, minute assignment or grace
period. API/Web, game/agent, monitors, credentials and Archive scheduling remain
unchanged. There is no B2 write, recovery retry or production service restart.

The report lists missing UTC minute slots and their nearest preceding/following
source completion timestamps inside the selected primary window. It retains up
to seven fractional digits. Missing edge neighbors are null, not interpolated
from another identity or a sample outside the selected window. Two observations
inside one minute cannot compensate for another missing minute.

The existing evaluator remains authoritative. Diagnostics cross-check the
1,440 mature-slot population, selected first attempts, duplicate and ignored
attempt counts against its report before emitting anything. A target miss still
fails the audit, after sanitized diagnostics are retained in the job log and
step summary. Raw JSONL and the temporary evaluator/report files are deleted.

## Coverage input and claim limits

The optional `archive_receipts_json` dispatch input contains a caller-reviewed
receipt manifest: `schema_version: 1`, the exact `exporter_revision`, and up to
20 `receipts`. Each entry has exactly these fields:

```json
{
  "run_id": 1,
  "event": "schedule",
  "window_start_utc": "2026-01-01T00:00:00Z",
  "window_end_utc": "2026-01-02T00:00:00Z",
  "run_attempt": 1,
  "archive_job_succeeded": true,
  "archive_receipt_verified": true
}
```

The example is synthetic. Before supplying a real manifest, inspect the actual
completed first-attempt Archive job and its stored-object receipt, not only the
workflow conclusion. Copy the exact requested window from that receipt. Mark
manual catch-up as `workflow_dispatch`; it never refreshes ordinary schedule
health. The manifest expresses an operator's reviewed evidence, not a signed
provider assertion. This report does not independently authenticate receipts or
verify B2 objects. Independent Recovery remains a separate operation.

The projection clips and unions the supplied requested output windows. It shows
uncovered intervals for schedule-only and schedule-plus-manual receipts, with
open head/tail edges and a completely open window distinguished from closed
inter-run gaps. Ten-minute raw query overlap is
not treated as stored-object coverage. Workflow creation timestamps are never
used to invent window boundaries. Without receipts coverage is Unknown; an
explicit empty manifest reports the entire window uncovered from those inputs.

Input is capped at 32 KiB for receipts, 16 MiB/20,000 records for the source and
1 MiB for the evaluator report. Duplicate JSON members, unknown receipt fields,
reruns, wrong identity, conflicting records and mismatched counters fail closed.
The resulting JSON is capped at 1 MiB and the added Markdown at 512 KiB. Output
contains fixed fields, literal public identity/version values, validated UTC
timestamps and bounded counts. Execution IDs, run IDs, object identifiers,
provider text, HTTP payloads, addresses, paths and secrets are not projected.

## Release and rollback

R3 operational evidence scope: one workflow/wrapper and an offline reporter,
plus their tests and an immutable package. Candidate/stable tags are
`availability-diagnostics-v2.119.0-rc.1` and
`availability-diagnostics-v2.119.0`. Stable must reuse the exact accepted ZIP
bytes and source revision. No application image publication or deployment is
needed for this component release.

Rollback removes the additive workflow/wrapper diagnostics through a reviewed
source change to the recorded prior revision. There is no durable-state
conversion, permission or secret change to reverse. Completed audit evidence
remains history and is not deleted or rewritten. A failed diagnostics gate
blocks acceptance; an explicitly retained, independently confirmed draft target
miss is an SLI observation, not a successful SLO audit.
