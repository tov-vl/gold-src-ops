# v2.29 Weapon Selection Prototype

Status as of 2026-10-04: local default-off prototype compiles with the pinned
toolchain; sandbox packaging and isolated server loading/configuration smoke
passed. Not deployed or released; player inventory remains unverified.

## Product Boundary

The v2.28 MP5 profile remains the host baseline. The next experiment adds a
small primary-weapon choice: MP5, AK-47, or M4A1 for either team. A player
opens `/guns` in chat or `guns` in the console. Selection applies only at
the next living spawn and is retained for the current connection, including
team switches. A reconnect or map change resets the selection to MP5.
Closing the menu keeps the previous choice. Menus do not grant weapons or
refill ammunition during a life. There is no automatic menu on every spawn.

The separate AMX Mod X/ReAPI plugin is disabled by default through
`goldsrcops_weapons_enabled=0`. It does not modify the telemetry producer,
profile configuration, objective items, pistol, knife, immunity, economy,
round rules, or buy rules. Bots, HLTV, and spectators receive no plugin loadout.
The common choices are an experiment, not a multiplayer-balance claim.

## Implementation Boundary

The prototype uses the existing pinned AMX Mod X `1.10.0.5481` and ReAPI
`5.24.0.300`. It uses a shared menu, a post-spawn hook, primary-slot removal,
item grant, and bounded backpack ammunition. A failed selected-item grant
attempts the MP5 fallback once; failures do not restart services or retry a
host transition. No timers, database, credentials, or new .NET API are needed.

References: [AMX Mod X menu API](https://www.amxmodx.org/api/newmenus/menu_create)
and the [ReAPI native declarations](https://github.com/rehlds/ReAPI/blob/5.24.0.300/reapi/extra/amxmodx/scripting/include/reapi_gamedll.inc).

## Focused Verification And Next Gate

The offline compiler smoke is `tools/smoke/amxx-weapon-selection.ps1` with
an existing verified toolchain cache. It passed on 2026-10-03 with warnings
treated as errors. The documentation validator also passed. Compilation is
not gameplay acceptance. On 2026-10-04, an isolated disposable server loaded
the plugin and ReAPI with `running` status, and the diagnostic command reported
`enabled=0`, then `enabled=1`, then `enabled=0`, always with three choices.
No AMX Mod X error log was produced. The container had no external network or
published ports and was stopped after the check. Steam connectivity warnings
were expected in this setup; AMX Mod X also reported engine CRC warnings for
the pinned newer engine. Loading/configuration passed, but spawn, menu, and
inventory behavior were not exercised. One short client session can cover selection, respawn,
and preservation of secondary/objective items; no long soak or repeated
multi-round test is required for this MVP experiment.

## Sandbox Package

`tools/release/build-weapon-selection-sandbox.ps1` builds an offline local
experiment, not a production pilot bundle. Pass the existing pinned toolchain
cache and a new output directory. The output ZIP contains exactly:

- `cstrike/addons/amxmodx/plugins/goldsrcops_weapon_selection.amxx`;
- `cstrike/addons/amxmodx/configs/goldsrcops-weapon-selection.cfg`;
- `manifest.json` with source and payload SHA-256, pinned compiler/module
  versions, default-off state, and `productionInstallSupported=false`.

Existing output directories are refused, not replaced. The package does not
include a plugin list, telemetry configuration, profile, loader, or module.
The focused `tools/smoke/weapon-selection-package.ps1` test passed on
2026-10-03: exact ZIP entries, payload hashes, default-off LF configuration,
and refusal to overwrite the existing artifact. Docker execution was initially
refused by tool policy; access was restored for the 2026-10-04 loading smoke.
Enabled spawn behavior remains open.

For a disposable server already using the pinned AMX Mod X/ReAPI stack,
extract the two payload files and append `goldsrcops_weapon_selection.amxx`
to that server's local plugin list without replacing other entries. Execute
`addons/amxmodx/configs/goldsrcops-weapon-selection.cfg` from its game console.
`goldsrcops_weapons_status` must report version `0.1.0`, `enabled=0`, and
`choices=3`; after explicitly setting `goldsrcops_weapons_enabled 1`, it must
report `enabled=1`. These receipts prove loading/configuration only. Confirm
the plugin is running in `amxx plugins` and has no load errors before any
client check. Do not use these instructions on the active host.

The existing pilot bundle intentionally permits exactly one telemetry plugin.
Do not copy this second plugin into the active host or silently widen that
allowlist. Production packaging and the corresponding guarded install/recovery
boundary remain separate work after the sandbox runtime check. No host mutation or stable
publication is authorized by this local prototype record.
