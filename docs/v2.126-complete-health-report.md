# v2.126 - Complete Operator diagnostic report

## Scope and compatibility

Extend the existing Operator-only `/operator/game-host-health/report` attachment
from three sources to six. Add recorded credential expiry, incident outbox and
receiver queue observations through existing contracts and server-side clients.
The route, fixed filename, plain-text UTF-8, no-store and nosniff are preserved.
The overview download text now describes the full attachment.

Each configured source is read once, concurrently, with the caller cancellation
token and existing bounded transports. Disabled receiver access sends no request.
Expected HTTP, timeout, invalid-data and JSON failures isolate one source as
Unknown. Caller cancellation stops the download rather than creating an Unknown
report. Generation time never makes an older source observation current.

## Projection and limits

The original game-host, Archive and polling sections retain their independent
observation and warning times. Credential metadata reuses the fixed four-purpose
catalog and accepted validation, labels and 180-second freshness. Minute records
retain minute precision and conservative interpretation without invented seconds;
last verification remains separate. Invalid or old metadata does not prove that
access is valid or has no expiry.

Outbox and receiver reuse the accepted v2.125 projections, with independent
60-second queue freshness, validated counts/oldest time, worker configuration,
CatchUp/Live mode and unreviewed dead letters. Unknown/Stale never becomes zero;
disabled receiver facts are Not queried. Counts are not summed. Only validated
values, fixed catalog text and fixed detail links enter the attachment.

The file stays below 32 KiB with all 24 existing warning rules and maximum queue
counts. Raw provider strings, identifiers, addresses, credentials and secret
references are excluded. The report is a new static collection of independent
observations and can differ from the displayed overview. It does not prove
provider delivery, email receipt, Archive object Recovery, source completeness,
future schedule cadence or an achieved SLO. Prometheus to IRM/email is separate
from incident notification queues.

## Delivery boundary

R1, install only Web. API/receiver publication follows the canonical image flow
and does not imply their installation. No database, durable state, worker enable,
queue mutation, monitoring policy, permission, provider, secret, game/agent or
Archive cadence change. Exact prior Web digest and env bytes are retained for
rollback; fourteen other container identities, restarts and protected files stay
unchanged. Stable promotion reuses accepted candidate digests without rebuilding.

## Verification and readiness

Required gates: all 64 configured-source failure combinations, denied roles with
zero source reads, disabled receiver with no request, concurrent reads and caller
cancellation for every source, minute precision, stale/future/invalid payloads,
maximum counts and strict bounded UTF-8. Browser checks cover actual downloads
without JavaScript, desktop/mobile and independent partial failures.

Audit-enabled local quality passed restore, format, a warning-free build,
1893 tests and dependency audit. Its 68 opt-in browser cases were skipped in
the general local command; three separate actual browser fixtures passed.
After test-only inspection cleanup, final focused checks passed 146 cases and
final formatting passed. Scoped InspectCode completed with zero errors/warnings
and 39 reviewed notes. Cancellation-test, established formatting, fluent-map and
conflicting collection-hint exceptions are recorded privately without suppressions.

Required PR/main CI, immutable publication,
independent Web-only runtime and authenticated six-source download acceptance
remain release gates. Fixture evidence is separate from target acceptance.
