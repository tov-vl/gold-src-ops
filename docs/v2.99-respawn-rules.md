# v2.99 - Respawn and protection guide

## Boundary

Addon 0.38.0 extends the private RU/EN `/rules` guide with the current automatic
respawn delay, spawn protection duration and early-removal conditions. It reads
`mp_forcerespawn`, `mp_respawn_immunitytime` and
`mp_respawn_immunity_force_unset` on every admitted request. No gameplay CVAR,
spawn hook, combat behavior, storage format, map addon or application changes.

The existing five-second shared alias cooldown, effective-language projection,
dead-player/spectator access and invalid/bot/HLTV/disabled exclusions remain.
Viewing rules does not load identity, flush preferences, write vaults, refresh
leaderboards or change health/inventory. Existing weapon/reward/rank paragraphs
remain complete inside the previous 1536-cell MOTD buffer.

## Display contract

| Setting | Display |
| --- | --- |
| Valid finite duration in `[-3600, 0]` | Feature explicitly disabled |
| Duration in `(0, 0.01)` | HTML-escaped `less than 0.01` seconds |
| Duration in `[0.01, 3600]` | Seconds rounded to two decimal places |
| Missing pointer, non-finite or out-of-range duration | Settings unavailable |
| Protection removal mode `0` | Actions do not remove protection early |
| Mode `1` | Active actions, including movement or attack, remove protection |
| Mode `2` | Primary or secondary attack removes protection |
| Missing or other mode, including fractions | Early-removal settings unavailable |

Removal text appears only when protection is enabled. The guide reports engine
settings, not a personal countdown or a guarantee of elapsed time from a kill:
the engine also owns death animation, team/joining state and scheduling.
Timing display uses rounded integer hundredths because the pinned native float
formatter produced `2.49` for `2.50` in the isolated engine. Unsupported settings
are not clamped into a different claim, and reading never writes a CVAR.

Semantics were checked against the pinned
[ReGameDLL 5.30.0.814 configuration](https://github.com/rehlds/ReGameDLL_CS/blob/5.30.0.814/dist/game.cfg)
and [player implementation](https://github.com/rehlds/ReGameDLL_CS/blob/5.30.0.814/regamedll/dlls/player.cpp).
Other plugins overriding these engine mechanics are outside this guide's claim.

## Verification and delivery gates

The strict dictionary gate requires matching RU/EN keys and exactly one string
placeholder for each duration. Existing caption, message and UTF-8 limits remain.
Package smoke adds malformed/missing/duplicate duration placeholders. Engine
coverage adds 96 combinations with independent duration values, all removal
modes, disabled/unsupported states, missing pointers, non-finite inputs, complete
text and unchanged CVARs. Existing rules tests preserve pending player state.

`PLAYER_RESPAWN_RULES_SMOKE` is mandatory in the 21-case pinned engine plan.
Runner tests reject missing, failed and duplicate results. Full required CI is
selected because the shared engine plan/runner tests changed. No C# changed;
local .NET/InspectCode are not applicable to this addon slice.

Highest delivery risk is R3: mandatory engine evidence and the established
guarded addon transition. The approved milestone covers ordinary product PR/CI,
merge, exact 0.37.0 -> 0.38.0 package installation on an empty game server,
independent technical acceptance and final evidence PR. Only plugin and dictionary
change in the four-file payload. The exact accepted 0.37.0 package is retained
for rollback; installed workflow files are preserved and hash-bound separately.

Before stop, require a fresh empty-server gate, verified predecessor receipt,
current backup baseline and no addon/agent/backup pending operation. Use one
claimed apply, preserve quiescent vault/journal hashes and agent identity, then
reconcile the backup baseline through the existing workflow. Uncertain outcomes
require inspection rather than replay. No backup, restore or queue mutation is
part of this release.

Local verification passed: 109 matching dictionary keys, 105 package/dictionary
boundary cases, all ten compiled fixtures, 12 runner tests and the complete
21-case / 38-marker engine suite in 166.969 seconds. No AMXX errors were present;
owned-container cleanup passed. Initial local attempts exposed the formatting
defect above; the final suite passed after correction. An earlier Docker image
inspection timed out before any game container; the pinned images were then
obtained and verified. Required CI and production acceptance remain pending.
Real-client RU/EN readability is a separate gate, as are PvP, bots and 24-hour
human activity.
