# v2.30 Spawn Loadout

Status as of 2026-10-04: implementation, focused local checks and required PR CI
passed. The addon was upgraded on the active game host and passed bounded
loading/configuration acceptance. Human menu presentation and multiplayer
balance remain unverified. No stable control-plane release was published.

## Product Boundary

Weapon selection `0.2.0` extends the accepted v2.29 addon. `/guns`, team chat
`/guns`, and console `guns` open the primary menu, then the pistol menu. The
primary choices remain MP5, AK-47 and M4A1. Pistol choices are USP, Glock and
Desert Eagle for either team. Closing either menu retains that slot's choice;
accepting a primary and cancelling the pistol keeps the new primary and the
previous pistol. Chat confirms accepted choices.

The selections apply only at the next living spawn and survive team changes
for the current connection. Reconnect or map change resets them to MP5 + USP.
Each eligible spawn receives 100 armor with a helmet. Backpack ammunition is
MP5 120, AK-47/M4A1 90, USP 100, Glock 120 and Desert Eagle 35. MP5 and Glock
share the same 120-round 9mm reserve; they do not have separate ammo pools.

Both weapon slots are emptied before any new item/ammo grant, preventing
removal of an old Glock from clearing newly granted MP5 ammo. Knife, grenades
and objective slots are not removed. Primary and pistol grants each have one
bounded fallback to MP5 and USP respectively. Bots, HLTV, spectators and dead
players remain excluded. Menus never replace inventory or refill ammunition
mid-life. No automatic spawn menu, buying-rule change, timer, rank, database,
API, telemetry or objective-round change is introduced.

## Bounded Addon Upgrade

The existing package builder retains the two targets and exact payload paths.
Only the product plugin is shipped; the synthetic runtime fixture is never
included in either package. The sandbox remains default-off and the explicit
game-host addon remains enabled by its own configuration.

The stopped-game addon workflow now supports:

```bash
bash ./ops/gameserver/weapon-selection-addon.sh --upgrade \
  --bundle /absolute/reviewed-addon/content \
  --manifest-sha256 <new-reviewed-manifest-sha256> \
  --expected-manifest-sha256 <installed-reviewed-manifest-sha256>
```

Without `--apply`, it remains plan-only and touches no host or endpoint.
Apply requires the existing reviewed SSH operator, persistent MP5 baseline,
inactive game, locks, valid installed receipt, and exact predecessor digest.
The new bundle must have the same verified configuration and loader as the
installed addon. Only its changed binary and receipt are replaced; enabled or
disabled loader state is preserved. A root-only unique backup retains the
previous binary and receipt. Any failed mutating step restores both and leaves
the game stopped for inspection. The installer never manages services.

After a successful upgrade, the previous trusted package can be supplied to
the same operation with the current receipt's manifest digest as predecessor
for an explicit reverse upgrade. A failed target gate requires reconciliation
before any such transition, not an automatic retry.

The telemetry files, persistent guard, original profile, identity, queue/spool,
boot policy and running agent are outside the addon mutation boundary. The
existing boot guard still does not hash-bind the addon; this limitation is not
silently changed into a new boot policy.

## Verification Budget And Limits

Use pinned offline compilation, exact package/content checks and the existing
filesystem fixture extended for upgrade, stale-predecessor refusal, partial
binary failure, final-guard failure, and reverse upgrade while disabled. A
short isolated runtime smoke is sufficient for the changed grant behavior.

`tools/smoke/amxx-weapon-selection.ps1 -RuntimeFixture` builds
`tools/smoke/amxx-spawn-loadout.sma`, which includes the product source and
exempts only its synthetic client from the bot exclusion. It exercises the
real engine/ReAPI spawn and inventory operations for all nine combinations,
ammo, armor/helmet, no mid-life refill, menu cancellation, team change,
preservation of existing knife/grenade/objective items and disconnect reset.
This is not a human menu-rendering, network-client, bot-eligibility,
multiplayer-balance or objective-round result. Compile the normal plugin
separately for packaging; never deploy the fixture.

Required PR CI remains mandatory. Do not repeat the full local .NET suite,
long soak, reboot exercise or an unchanged primary-selection player session.
An active-host upgrade needs one short preflight and post-start A2S/plugin/
receipt/guard check with the previous addon retained. New client presentation
may remain an explicit MVP limitation rather than requiring another owner
session before unrelated development.
