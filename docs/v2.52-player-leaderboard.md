# v2.52 - Общий рейтинг игроков

Статус на 2026-10-09: addon 0.19.0 слит в `main`, установлен на игровом сервере
и независимо проверен. Product PR и post-merge CI прошли. Читаемость MOTD
в реальном клиенте остается непроверенной.

## Граница

R2: `/topall` в общем/командном чате и `topall` в консоли показывают приватный
MOTD с десятью лучшими сохраненными результатами, включая отключившихся игроков.
В RU/EN меню добавлен восьмой пункт; все восемь пунктов помещаются на одной
странице. `/help` содержит новую команду. `/top` сохраняет прежнюю семантику
текущего подключения/карты, `/rank` - прежние пороги рангов.

Порядок: убийства по убыванию, смерти по возрастанию, затем канонический ключ
для устойчивого порядка равных результатов. Ключи и SteamID не показываются.
Нулевые результаты без смертей исключены. Никнеймы экранируются для HTML,
длина каждой отображаемой строки и всего MOTD ограничена. Длинное экранированное
имя сокращается только между целыми UTF-8 символами/HTML entities.

Команда имеет отдельный cooldown пять секунд, доступна умершим и наблюдателям;
боты, HLTV и вызовы при выключенном addon отклоняются. Просмотр не пишет данные,
не читает файлы и не меняет оружие. Общий кеш обновляется по требованию при
изменениях, не чаще раза в пять секунд.

## Совместимость данных

Источником результатов остается `goldsrcops-player-stats-v1`: канонические
ключи `v1:STEAM_0:...`, значения schema 1 и timestamps не мигрируют.
При старте карты до `nvault_open` выполняется ограниченное чтение ключей из
бинарного vault и журнала. Затем штатный nVault восстанавливает журнал;
счетчики для индекса читаются через native lookup из восстановленного состояния.
Удаленные записи пропускаются. Исходные файлы не переписываются парсером индекса,
дополнительного close/open ради индекса в продукте нет.

Пределы: 4096 уникальных ключей-кандидатов, 4 MiB для каждого входного файла,
65536 операций журнала. Формат привязан к закрепленному AMXX 1.10.0.5481:
заголовок nVault 0x6E564C54/0x0200, bounded strings и известные операции журнала.
Поврежденный формат, дубликат ключа в vault, неизвестная операция, обрыв,
лишние байты, недостоверные счетчики или превышение лимита отключают таблицу
до следующей загрузки. Частичный топ не выдается. Обычная статистика сохраняет
свою границу обработки ошибок; неопределенный readback также отключает рейтинг.

Никнейм при подтвержденном входе сохраняется не более одного раза за подключение
в существующий `goldsrcops-player-preferences-v1`, namespace `name:<stats-key>`,
значение `1 <bounded-name>`. Равное значение не переписывается. При поздней
идентификации имя также может сохраниться после успешной записи статистики.
В таблице это имя последнего учтенного входа; изменение ника в текущей сессии
не вызывает поток записей. Пока ника нет, выводится RU/EN подпись "Игрок"/"Player".
Старые результаты импортируются при загрузке без ожидания повторного входа.

Записи языка/оружия и HUD остаются в прежних пространствах имен. Новые файлы
хранилища не создаются: существующий backup двух vault/journal включает имена.
Обратная замена на 0.18.0 сохраняет неизвестные ей name-записи и счетчики;
это подтверждено изолированной проверкой ниже.
API/Web/PostgreSQL, игровой агент, карта, scoring и rewards не меняются.

Формат сверялся с [описанием nVault](https://wiki.alliedmods.net/NVAULT),
[реализацией vault](https://github.com/alliedmodders/amxmodx/blob/master/modules/nvault/NVault.cpp)
и [журналом](https://github.com/alliedmodders/amxmodx/blob/master/modules/nvault/Journal.cpp),
а поведение проверяется на закрепленном бинарном модуле.

## Проверки

Focused engine smoke прошел на реальном nVault: старые/offline записи,
топ-10 и равенство результатов, native enemy kill, disconnect, кеш/cooldown,
RU/EN, UTF-8 и HTML escaping, предельные поля MOTD, replay insert/replace/remove,
поврежденные входы, сохранность исходных значений и timestamps, capacity/refusal.
Продукт и все пять fixtures скомпилированы закрепленным toolchain. Общая
регрессия проверила меню/справку RU/EN, периодический HUD при открытом меню,
сохранение и восстановление настроек, ранги, первую выдачу и девять комплектов
оружия. Leaderboard seed/reload в разных процессах и на разных картах прошел.
Все markers имеют `failures=0`, AMXX error logs отсутствуют; контейнеры
без сети и опубликованных портов, с read-only входами завершены и удалены.

Отдельный recovery rehearsal выполнил цепочку: seed 0.19.0 -> остановка ->
существующий `player-data-bundle.py create` -> restore в новый каталог ->
побайтовое сравнение -> загрузка 0.18.0 с ее dictionary -> загрузка 0.19.0
на другой карте. Предыдущий исходник, fixture и dictionary взяты из
`411af46faf018ae34443842c9de0c41a2274caeb`. После обоих запусков все ключи,
значения и timestamps обоих vault совпали с сохраненным источником. Хеши
неизменяемой исходной копии тоже совпали. Весь сценарий использовал только
синтетические данные в удаляемом контейнере.

Package smoke проверил manifest, точный состав и SHA-256 архива, 55 ключей
RU/EN dictionary и отказ перезаписать существующий output. Loader и включенная
configuration совпадают с принятым пакетом 0.18.0 побайтово.

## Публикация и установка

Владелец подтвердил один пакет v2.52: обычный push, продуктовый PR, squash
merge после required CI, установку addon 0.19.0 на пустом сервере, независимую
приемку, возврат на 0.18.0 при необходимости и итоговый evidence PR.
Граница R2 включает только weapon addon и его RU/EN dictionary. Проверенный
пакет 0.18.0 сохранен; обратная замена сохраняет данные, накопленные к моменту
остановки для отката, и сверяет их хеши перед повторным стартом.
Первый weekly backup 2026-10-11 в 04:00 МСК остается отдельной приемкой v2.50.


## Установка и независимая приемка

[PR #279](https://github.com/tov-vl/gold-src-ops/pull/279) прошел все пять
обязательных checks на подписанной ревизии
`d5cd19786fbc39a69b63db0363dc74af75e540c4` и слит squash merge как
`872a7f72842d09868ba9da29b11d319f838e5a75`. Merged tree совпал с reviewed tree.
[PR CI](https://github.com/tov-vl/gold-src-ops/actions/runs/37917179978) и
[post-merge CI](https://github.com/tov-vl/gold-src-ops/actions/runs/37917566791)
успешны на точных ревизиях с маршрутом `addon-only`.

Свежие A2S/RCON и host preflight подтвердили принятую 0.18.0, пустой сервер,
работающие хранилища без ошибок, прежний baseline и агент, пустые queue/spool.
Исходник и dictionary совпали с reviewed tree; manifest, архив, payload и
переданные операторские файлы сверены по SHA-256. PowerShell/Bash/Python
операторских материалов прошли синтаксическую проверку.

Первый вызов остановился на входном guard: `sudo` удалил `SSH_CONNECTION`.
Отсутствие install claim/log/result, неизменный receipt и активные службы
подтвердили, что установка не начиналась. Передача существующего SSH-контекста
через `sudo --preserve-env=SSH_CONNECTION` позволила выполнить одну установку;
проверки личности, пакет и процедура оставались прежними.

Непосредственный pre-stop A2S снова подтвердил ноль игроков и ботов. Закрытые
stats/preferences vault и присутствующие журналы сохранили хеши через замену
до старта. Установка заменила plugin и matching dictionary; данные не
сбрасывались и не восстанавливались из backup. Durable exit равен нулю.

Отдельные A2S/RCON и host postflight подтвердили три работающих plugin,
weapon addon 0.19.0, восемь пунктов RU/EN меню, готовый leaderboard index с
`errors=0`, прежние schema-1 stores и точные live payload. Map addon,
configuration, loader, baseline, agent invocation и права родителей vault
сохранились; queue/spool пусты, NRestarts обеих служб равны нулю, новых AMXX
error logs нет. Откат не потребовался.

Игра вдвоем, реальная клиентская читаемость MOTD и первый weekly backup
2026-10-11 не включены в пройденную приемку. Образы, теги, API/Web/PostgreSQL,
backup policy и личная доставка предупреждений этим пакетом не менялись.
