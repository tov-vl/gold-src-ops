# v2.39 Player Preferences

Status as of 2026-10-05: implemented, merged and accepted on the active game
host with focused local smoke, required PR CI and independent target checks.

## Behavior

Weapon addon 0.9.0 saves explicit RU/EN and primary/pistol choices in a separate
schema-1 nVault by canonical SteamID. Reconnect and map/plugin restart restore
them; weapons still apply only on spawn. Unset language continues to follow
client language (empty/ru -> RU, otherwise EN). The existing map language native
reads the effective restored override without changing the map addon.

Joining does not write defaults. Late authorization merges only untouched
fields, preserving current-session selections. Bots/HLTV, shared/unknown IDs,
duplicate connected SteamIDs, stale/invalid menu callbacks and disabled addon
cannot write persistent preferences. Unknown identity or unavailable storage
keeps usable session choices. Corrupt records are retained, never reset;
readback failure blocks further writes until reconnect.

Stats/rank schema-1 records, scoring, thresholds, client preferences, global
language, native map voting, first-spawn presentation and boot policy stay
unchanged. No new module, control-plane API, PostgreSQL migration, identity
fallback or language/weapon reset command is included.

Use the current package builder/installer for a binary-only addon upgrade;
dictionary, configuration and loader stay byte-identical. Retain closed stats

The new preferences vault is game-owned state, not an installer payload. Reverse
upgrade retains it for later reconciliation and does not restore player records.
This is the R2 player-state boundary, not a new installer/infrastructure change.

One required product CI pass and one stopped-game installation with independent
A2S/addon/file checks are sufficient. No new credential, tag/image publication,

Stop on unexplained target drift or uncertain failure; no automatic retry.
