# v2.24 Guarded Game-Server Autostart

## Outcome

Permit the accepted `public-classic-v1` game service to return after a planned
host reboot without turning a missing or drifted runtime into an unattended
start. The game-event agent and automatic host reboot remain disabled.

This is a host-operations slice. It does not add remote host control to the API
or Web application, change the accepted game rules, activate plugins, or alter
the RCON credential boundary.

## Policy

`ops/gameserver/guarded-autostart.sh` is plan-only by default and exposes three
fixed operations:

- `--enable --apply` installs the reviewed script as a read-only systemd
  `ExecCondition` guard and enables only `goldsrcops-gameserver.service`;
- `--verify` checks the installed boot policy and active profile without
  changing state;
- `--disable --apply` restores the exact pre-policy marker bytes, removes only
  the boot-policy files, and disables the game service without stopping it.

Enable requires the game service to be active and boot-disabled, the game-event
agent to be inactive and boot-disabled, and the fixed managed profile to be
active. The workflow serializes with managed-profile transitions, preserves an
owner-only exact marker backup, and proves that enablement did not change the
current systemd invocation or restart count.

The installed guard fails before `ExecStart` unless all of these remain true:

- prepared host, runtime, base unit, public configuration, private
  configuration, and accepted-profile files have their reviewed owner and mode;
- runtime, base-unit, public-configuration, profile, mapcycle, drop-in, and guard
  hashes match their chained markers;
- the runtime marker records `service_autostart=enabled`, exact-source RCON, and
  stdin-only credential transport;
- the public configuration loads `public-classic-v1` exactly once and the
  profile retains its exact `mapchangecfgfile` hook;
- all five accepted maps exist and the runtime remains plugin-free.

Guard rejection uses exit status `78`, which `ExecCondition` treats as a clean
start skip before any `ExecStartPre` or `ExecStart` command. The existing
`Restart=on-failure`, `StartLimitIntervalSec=300`, and `StartLimitBurst=5`
continue to cover unexpected runtime failures after a successful guarded start.

## Apply And Rollback Boundary

Review the non-mutating plans:

```bash
bash ./ops/gameserver/guarded-autostart.sh
bash ./ops/gameserver/guarded-autostart.sh --disable
```

Apply from the operator identity recorded by host bootstrap:

```bash
sudo --preserve-env=SSH_CONNECTION \
  bash /tmp/goldsrcops-gameserver-guarded-autostart.sh --enable --apply
```

The apply changes only marker files, one installed guard, one systemd drop-in,
and the game service enablement symlink. It does not stop or restart the active
game. Any failed or interrupted transition invokes the corresponding exact
rollback path.

Profile replacement or rollback remains interlocked while the service is
boot-enabled. Disable guarded autostart first, then perform the separately
reviewed profile transition from its restored active/disabled boundary.

## Target Acceptance

Repository smoke proves plan-only behavior, marker rebinding, drop-in rendering,
guard-rejection start suppression, mutation order, interrupt rollback, agent
isolation, and the prohibition on start, stop, or restart commands.

Target acceptance remains incomplete until one reviewed revision passes:

1. hash-bound enable apply with the current game invocation and restart count
   unchanged;
2. a controlled host reboot with operator access retained;
3. installed `--verify`, systemd `active/enabled`, agent `inactive/disabled`, and
   zero game-service restarts after boot;
4. external A2S with the accepted name/map and zero bots;
5. authenticated read-only RCON inspection of all eleven managed-profile
   invariants and the exact-source policy.

Failure at the reboot gate disables autostart and restores the recorded
active/disabled policy before further profile work. Acceptance does not enable
automatic host reboot or claim long-term uptime.
