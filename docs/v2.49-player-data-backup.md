# v2.49 - Резервное копирование игровых данных

Статус на 2026-10-08: ручной R3 recovery baseline принят. Product PR и полный CI
прошли, закрытый production-снимок сохранен в существующем зашифрованном off-host
backend. Отдельный Recover и проверка его копии настоящим AMXX завершились успешно.

## Область изменения

Класс R3: recovery-процесс для двух игровых nVault и их журналов. Addon 0.18.0,
его словарь, форматы записей, PostgreSQL, API/Web, игровой агент и конфигурация
сервера не меняются. Механика игры вдвоем остается отложенной на неопределенный
срок. Описание процедуры: [backup и восстановление](game-player-data-backup.md).

Перед capture read-only проверка обнаружила оба vault и пустые журналы на
работающем игровом хосте. В проверенных systemd/cron расписаниях игровых backup
нет; найденный backup timer обслуживает базу пакетов ОС. Это не утверждение об
отсутствии provider snapshots или копий вне проверенных путей. Доступность
существующего restic backend отдельно проверена до остановки игры.

## Реализация

- Capture требует остановленный процесс и принятый persistent baseline,
  сериализует операции и создает только новый приватный архив.
- Manifest связывает точный состав, наличие журналов, размеры и SHA-256.
- Off-host архивирование использует существующий restic backend без переноса
  credentials на игровой хост, отдельные host/tag/path и точный snapshot ID.
- Readback и восстановление сверяют архив целиком и распаковывают его только
  в новый каталог. Рабочие vault не являются целью восстановления.
- Автотесты добавлены в полный CI. Набор включает unit/adversarial проверки,
  capture guards и настоящий encrypted restic roundtrip без сети. Engine
  rehearsal запускается отдельно; его синтаксис проверяется в CI.

## Локальные проверки и CI

- 14 Python-проверок: побайтовое восстановление, присутствующий/отсутствующий
  журнал, повреждение, изменение исходников, отсутствие vault, дубликаты,
  неизвестная схема, traversal, ссылки, размеры и запрет перезаписи.
- Capture guards отклоняют active/failed service, ненулевой PID, отдельный
  процесс, ошибку проверки процессов, неверный baseline и занятый transition lock.
- Закрепленные fixtures статистики и preferences компилируются без предупреждений.
- AMXX в контейнере без сети восстановил статистику, язык, оружие и HUD из
  архива между отдельными процессами. Исходная копия сохранила хеши; новых
  AMXX error logs нет.
- Настоящий restic на локальном тестовом repository прошел шифрование, backup,
  exact-snapshot readback и отдельный Recover. Неверная привязка hash/tag,
  существующая цель и конкурирующая операция отклонены. Исходный архив неизменен.
- Полный локальный Quality Gate прошел: restore, format, build без предупреждений,
  875 успешных тестов, 22 штатно пропущенных browser tests, dependency audit без
  известных уязвимых пакетов. Отдельный локальный браузерный прогон не выполнялся;

## Приемка production-копии

1. Независимые A2S/RCON и host preflight подтвердили пустой сервер, addon 0.18.0,
   отсутствие ошибок storage, принятый baseline и пустые queue/spool.
2. Выполнена одна остановка игрового сервиса. Capture проверил отсутствие
   процесса, создал новый архив и сравнил его байты с закрытыми vault.
   Прежний runtime запущен сразу после capture.
3. Независимые A2S/RCON и host postflight прошли. Baseline, plugin/dictionary,
   map payload и игровой агент остались неизменны; новых AMXX error logs нет.
4. Архив передан по доверенному SSH с проверкой SHA-256 на обоих переходах.
   Одна попытка Archive создала snapshot в существующем encrypted restic
   backend; проверка repository и readback точного snapshot прошли.
5. Отдельный Recover по этому snapshot восстановил архив в новый приватный
   каталог. Совпали host/tag/path, полный SHA-256, manifest и все файлы.
6. Именно readback из Recover передан в контейнер без сети и опубликованных
   портов с AMXX 1.10.0.5481 и fixture на исходнике addon 0.18.0. Настоящий
   nVault прочитал все записи; продуктовая загрузка подтвердила статистику,
   язык, primary/pistol и HUD. Попыток записи при загрузке и ошибок storage нет.
   После завершения движка все ключи, значения и timestamps совпали с копией;
   исходные архивы не изменились.
7. Итоговый host postflight подтвердил активный прежний runtime, неизменный
   baseline и агент. Snapshot ID, игровые записи и подробные доказательства
   сохранены только в закрытой записи оператора вне Git.

## Границы результата

Ручной backup и изолированная проверка конкретной production-копии приняты.
Восстановление поверх рабочих vault, потеря хоста целиком, аварийное завершение
с непустым журналом, RPO/RTO, расписание и retention остаются вне этой приемки.
Автоматический backup не включен: возраст последней копии контролирует оператор.

Production restore, удаление snapshot, новые credentials, теги/образы и
control-plane rollout не выполнялись. Игровой процесс остановлен один раз;
повторных попыток Archive не было. Следующий отдельный этап можно выбрать по
продуктовым приоритетам; расписание backup требует отдельного решения о частоте
и допустимых остановках игры.
