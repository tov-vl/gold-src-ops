# v2.49 - Резервное копирование игровых данных

Статус на 2026-10-08: реализация и локальная проверка подготовлены. Публикация PR,
required CI, остановка игрового сервиса, production backup и приемка его копии
пока не выполнены.

## Область изменения

Класс R3: recovery-процесс для двух игровых nVault и их журналов. Addon 0.18.0,
его словарь, форматы записей, PostgreSQL, API/Web, игровой агент и конфигурация
сервера не меняются. Механика игры вдвоем остается отложенной на неопределенный
срок. Описание процедуры: [backup и восстановление](game-player-data-backup.md).

Свежая read-only проверка обнаружила оба vault и пустые журналы на работающем
игровом хосте. Единственный найденный backup timer обслуживает базу пакетов ОС;
в проверенных systemd/cron расписаниях игровых backup нет. Это не утверждение
об отсутствии provider snapshots или копий вне проверенных путей. Существующий
control-plane restic image и защищенные файлы конфигурации доступны; доступность
backend и recovery конкретных игровых данных этой проверкой не доказывалась.

## Реализация

- Capture требует остановленный процесс и принятый persistent baseline,
  сериализует операции и создает только новый приватный архив.
- Manifest связывает точный состав, наличие журналов, размеры и SHA-256.
- Off-host архивирование использует существующий restic backend без переноса
  credentials на игровой хост, отдельные host/tag/path и точный snapshot ID.
- Readback и восстановление сверяют архив целиком и распаковывают его только
  в новый каталог. Рабочие vault не являются целью восстановления.
- Автотесты добавлены в полный CI. Набор включает unit/adversarial проверки,
  capture guards и настоящий encrypted restic roundtrip без сети. Engine
  rehearsal запускается отдельно; его синтаксис проверяется в CI.

## Подтвержденные локальные результаты

- 14 Python-проверок: побайтовое восстановление, присутствующий/отсутствующий
  журнал, повреждение, изменение исходников, отсутствие vault, дубликаты,
  неизвестная схема, traversal, ссылки, размеры и запрет перезаписи.
- Capture guards отклоняют active/failed service, ненулевой PID, отдельный
  процесс, ошибку проверки процессов, неверный baseline и занятый transition lock.
- Закрепленные fixtures статистики и preferences компилируются без предупреждений.
- AMXX в контейнере без сети восстановил статистику, язык, оружие и HUD из
  архива между отдельными процессами. Исходная копия сохранила хеши; новых
  AMXX error logs нет.
- Настоящий restic на локальном тестовом repository прошел шифрование, backup,
  exact-snapshot readback и отдельный Recover. Неверная привязка hash/tag,
  существующая цель и конкурирующая операция отклонены. Исходный архив неизменен.
- Полный локальный Quality Gate прошел: restore, format, build без предупреждений,
  875 успешных тестов, 22 штатно пропущенных browser tests, dependency audit без
  известных уязвимых пакетов. Отдельный браузерный прогон не выполнялся.
- ShellCheck, actionlint 1.7.12, PowerShell parser и CI fast-path smoke прошли.

Первый Windows restic smoke обнаружил различие creation-time метаданных между
path stat и handle stat после Docker restore при совпадающих байтах. Проверка
исправлена для Windows; Unix ctime остается в guard. Повторный полный smoke
прошел на новом синтетическом repository. Production попыток не было.

## Следующая граница приемки

После проверки окончательной ревизии: публикация одного product PR и required
CI, затем согласованное пустое окно игры, один закрытый снимок, немедленный
запуск прежнего runtime и независимый postflight. Передача архива и restic
readback выполняются после запуска игры. Изолированная проверка конкретного
production snapshot и измерение времени закрывают R3-приемку. Удаление snapshot,
расписание, восстановление поверх рабочих vault, теги образов и control-plane
rollout не включены. При неясном результате retry запрещен до сверки состояния.
