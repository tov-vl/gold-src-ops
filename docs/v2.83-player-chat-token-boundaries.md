# v2.83 - Границы цветовых акцентов в чате

Состояние на 2026-10-20: addon 0.30.0 принят в main; required PR CI
и post-merge CI прошли. Подготовлен план установки 0.29.0 -> 0.30.0,
ожидающий согласования владельца. Класс риска R1: меняется только оформление
приватных сообщений общего `PlayerChat`; механизм установки и форматы
сохраняемых данных прежние. Production staging и установка не выполнялись.

## Причина и изменение

Владелец при проверке 2026-10-19 в 17:30-17:35 МСК заметил зеленый `/weapons`
внутри `language/weapons` и отдельные зеленые цифры в `AK-47` и `M4A1`.
Форматтер распознавал slash-команду и число без проверки границ слова.

Теперь акцент применяется к самостоятельной команде или целому числу.
Пробелы, табуляция, скобки, двоеточие, точка с запятой и вертикальная черта
отделяют элементы; точка, запятая, восклицательный и вопросительный знаки
могут завершать их перед разделителем или концом строки. Фрагменты слова,
slash-разделенных пояснений, названий оружия и дробного числа не выделяются.

`language/weapons`, `MP5`, `AK-47` и `M4A1` остаются обычным цветом целиком.
Префикс, `/menu`, `/rank`, `/help` и самостоятельные числовые значения
сохраняют акценты. Переведенный текст, UTF-8 и прежний fallback без цветовых
кодов при превышении 190 байт сохранены. Версия metadata/status повышена
с 0.29.0 до 0.30.0 по согласованию владельца.

Обработчики настроек, выдача оружия, cooldown, vault, lookup, API/Web
и словарь не меняются. Новые замечания не закрывают оставшуюся проверку
приветствия RU/EN из [v2.82](v2.82-player-welcome-color.md).

## Локальные проверки

  состояния сохранения и три названия оружия в настоящих переводах RU/EN;
  команды и числа рядом с пунктуацией; отсутствие акцентов внутри других
  слов и токенов. Прежняя проверка fallback на границе 190 байт сохранена.
- Три изолированных ReHLDS 3.15.0.896 / ReGameDLL 5.30.0.814 сценария прошли
  за 37.713 секунды: menu/help/HUD, spawn/loadout (девять наборов),
  persistent stats/rank с настоящим nVault. Assertion failures и AMXX errors
  отсутствуют. Контейнер работал без сети и опубликованных портов, входы
  монтировались read-only.
- Dictionary smoke проверил 74 ключа RU/EN. Package smoke подтвердил schema 2,
  четыре payload, SHA-256 и отказ перезаписи пакета.
- Сравнение с локальным пакетом 0.29.0 подтвердило изменение только plugin.
  Dictionary, loader и config побайтно совпадают; lookup остается включенным.

Полные .NET/browser suites, остальные движковые сценарии и installer/recovery
rehearsals локально не повторялись: их код и контракты не менялись.
Локальный движок подтверждает выдаваемые байты, но не внешний вид в клиенте.

## Установка и техническая приемка

1. После согласования сверить frozen inputs, актуальные baseline/payload,
   workflow, runtime, отсутствие pending и пустой сервер. При drift или
   занятости остановиться до изменений.
2. Создать staging с обоими package, hook и plan; выполнить штатный host dry run
   и отдельную приемку predecessor через control-plane.
3. Выполнить один apply [штатного addon workflow](v2.64-addon-upgrade-workflow.md).
   Непосредственно перед остановкой повторяется empty-server gate.
   Останавливается только игра; закрытые vault/journal сверяются до и после
   записи addon. Агент остается запущенным.
4. После запуска проверить 0.30.0, manifest/payload, AMXX errors, A2S,
   диагностические статусы и приемку через control-plane. Прямой RCON
   с game host не используется. Workflow согласует baseline и завершает журнал.
5. Независимо проверить terminal `accepted`, отсутствие pending, guards
   и сохранность данных. Заново вывести baseline из предыдущего состояния
   и candidate manifest: из 24 записей могут измениться только plugin
   и installation receipt.
6. Проверить неизменность агента и девяти контейнеров, public online и свежий
   backup monitor. После cooldown проверить exact/contains двумя запросами
   отсутствующего ника с интервалом 11 секунд, без повторов и создания записей.
7. Сохранить технические evidence отдельно от клиентской проверки; обновить
   этот документ и backlog. В согласованный bundle включить обычный push ветки
   `docs/v2.83-readiness`, PR в main, required CI, squash merge и post-merge CI.

API, Web, агент, образы, теги, конфигурация мониторинга и расписание backup
в изменение не входят. Миграции данных и новая публикация образов не требуются.

## Откат и границы

Подтвержденный отказ внутри операции допускает штатный возврат на точный
package 0.29.0 после повторной проверки пустого сервера. Приемка должна
подтвердить предыдущий runtime и согласованный baseline; текущие vault
сохраняются. Восстановление старых игровых данных не предусмотрено.

Timeout, потеря связи, неизвестный артефакт, drift закрытых сохранений или
неудачный откат требуют reconciliation. Повтор apply и снятие pending
автоматически запрещены. При занятом сервере остановка для отката
не выполняется. Отказ после terminal `accepted` требует отдельного решения
и нового reverse plan; завершенную операцию нельзя повторять.

## Клиентская приемка после установки

Проверить на RU и EN:

1. Вызвать `/help`: пять строк целиком; в пояснении `language/weapons`
   и его RU-варианте нет частично зеленого слова. Команды и префикс
   сохраняют цветные акценты.
2. Через `/guns` выбрать MP5, AK-47 и M4A1: в подтверждении каждое название
   окрашено одинаково целиком, без отдельных зеленых цифр.
3. Вызвать `/rank`: самостоятельные числа продолжают выделяться цветом.
4. Для закрытия оставшегося gate v2.82 выбрать язык, переподключиться
   и проверить цветную подсказку `/menu`, `/guns`, `/help`. При следующем
   возрождении подсказка не повторяется. Повторить на втором языке.

Сохранить снимки и время окончания проверки по МСК. Игра вдвоем не требуется.
Следующий gate - согласование подготовленного плана установки владельцем.
