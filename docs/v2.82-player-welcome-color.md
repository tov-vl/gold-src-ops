# v2.82 - Цветная подсказка при входе

Состояние на 2026-10-19: addon 0.29.0 принят в main, required PR CI и
post-merge CI прошли. План установки подготовлен и проверен локально;
read-only production preflight прошел. Установка еще не выполнялась.
Класс риска R1: меняется оформление существующей приватной подсказки;
штатный механизм установки и форматы сохраняемых данных не меняются.

## Изменение

На снимке после клиентской проверки v2.81 первая подсказка с `/menu`, `/guns`
и `/help` оставалась одноцветной, хотя следующая строка ранга уже использовала
цветовые акценты. Причина - вызов `client_print` в `ShowWelcome`.

Подсказка переведена на существующий `PlayerChat`: зеленые префикс и команды,
обычный цвет пояснений. Общий форматтер соблюдает лимит 190 байт и сохраняет
переведенный текст при недостатке места для цветовых кодов. Для приветствия
EN занимает 86 байт с цветами, RU - 107; запас достаточен для обеих локализаций.

Тексты и словарь не менялись. Показ один раз за подключение, проверки живого
игрока, отмена таймера, поведение активного меню и последующая строка ранга
сохранены. Код vault, схемы данных, выдача оружия, поиск и API/Web не меняются.
Версия plugin и диагностических статусов повышена с 0.28.0 до 0.29.0.

## Установка и техническая приемка

1. Сверить frozen inputs, актуальные baseline/payload, workflow, runtime,
   отсутствие pending и пустой сервер. При drift или занятости остановиться.
2. После согласования создать staging с обоими package, hook и plan;
   выполнить штатный host dry run и приемку predecessor через control-plane.
3. Выполнить один apply штатного [addon workflow](v2.64-addon-upgrade-workflow.md).
   Непосредственно перед остановкой повторяется empty-server gate. Останавливается
   только игра; закрытые vault/journal сверяются до и после записи addon.
4. После запуска проверить 0.29.0, manifest/payload, AMXX errors, A2S,
   диагностические статусы и приемку через control-plane. Прямой RCON с game host
   не используется. Штатный workflow согласует baseline и завершает журнал.
5. Независимо проверить terminal `accepted`, отсутствие pending, guards и
   сохранность данных. Заново вывести baseline из предыдущего и candidate manifest:
   из 24 записей могут измениться только plugin и installation receipt.
6. Проверить неизменность агента и девяти контейнеров, public online и свежий
   backup monitor. После cooldown проверить exact/contains двумя запросами
   отсутствующего ника с интервалом 11 секунд, без повторов и создания записей.
7. Сохранить технические evidence отдельно от клиентской проверки; обновить
   этот документ и backlog, затем выполнить согласованные push, PR, required CI,
   squash merge и post-merge CI.

## Откат и границы

Подтвержденный отказ внутри операции допускает штатный возврат на точный package
0.28.0 после повторной проверки пустого сервера. Приемка должна подтвердить
предыдущий runtime и согласованный baseline; текущие vault сохраняются.
Восстановление старых игровых данных поверх текущих не предусмотрено.

Timeout, потеря связи, неизвестный артефакт, drift закрытых сохранений или отказ
отката требуют reconciliation. Повтор apply и снятие pending автоматически
запрещены. При занятом сервере остановка для отката не выполняется.
Отказ после terminal `accepted` требует отдельного решения и нового reverse plan;
завершенную операцию нельзя повторять.

Staging, host dry run, execution claim, установка и откат еще не выполнялись.
Следующий gate - согласование исполнения этого конкретного плана.
После установки достаточно одной короткой проверки RU/EN: при подключении
префикс и `/menu`, `/guns`, `/help` выделены цветом, пояснения не обрезаны;
подсказка не повторяется при следующем возрождении. Для второго языка нужно
выбрать его и переподключиться. Повторять принятую проверку настроек v2.81
или сценарий игры вдвоем для этой правки не требуется.
