# v2.25 Public Server Join

## Goal

Give a visitor one clear, bounded path from the public GoldSrcOps status page
to the accepted `public-classic-v1` Counter-Strike 1.6 server. The page should
show current A2S state, map, occupancy, freshness, a Steam deep link, and a
copyable console command without exposing private inventory or operator data.

## Scope

- Add anonymous `GET /api/public/server`.
- Select one existing enabled inventory server by configured ID.
- Project only status, map, players, capacity, and observation time from A2S.
- Supply the public display name, advertised host, and game port from a
  separate deployment configuration.
- Render a responsive public join section with `steam://connect/...` and
  `connect host:port` actions.
- Keep the current aggregate status and 24-hour/seven-day A2S history intact.

This slice does not add a database migration, expose inventory addresses,
create DNS, enable another worker, or alter the accepted game-server profile
and guarded-autostart policy. Target acceptance additionally requires the
separate public game-boundary workflow because the original host foundation
deliberately restricted UDP 27015 to the control plane.

## Configuration Boundary

The feature is disabled when all four `PublicServerJoin` settings are absent:

- `ServerId`
- `Name`
- `Host`
- `Port`

Once any setting is present, the complete set is required. The server ID must
be a non-empty GUID, the display name is bounded text, the host must be a DNS
name or IPv4 address without URL syntax, and the port must be between `1` and
`65535`. Invalid or partial configuration fails startup instead of silently
advertising a wrong endpoint.

An absent configuration or a configured server that is missing or disabled
returns `404`; the public page then omits the join section while retaining the
other public status surfaces. A stale online observation is shown as unknown,
not current online state.

## Data-Safety Contract

The endpoint may return only:

- configured public name, host, and port;
- normalized state (`online`, `offline`, or `unknown`);
- current map;
- current and maximum player counts;
- last observation time.

It must not return the inventory name, inventory host or query port, notes,
RCON metadata, provider identifiers, raw responses, incident details, command
history, credentials, or any secret reference.

## Verification

Repository evidence requires:

- configuration parsing tests for disabled, complete, partial, and unsafe
  values;
- application tests for enabled selection, stale state, and disabled exclusion;
- anonymous API integration coverage proving the exact response shape and
  absence of private inventory values;
- Web client and static-render integration coverage for configured and absent
  projections;
- browser coverage for desktop/mobile overflow, Steam link, and copy feedback;
- the standard repository quality gate on the final revision.

## Target Gate

The application behavior is additive and read-only, but the complete v2.25
release is R3 because it also publishes the existing game UDP endpoint. After
merge, configure one reviewed public DNS name or IPv4 address and the existing
inventory server ID, then deploy immutable API and Web digests and apply the
reviewed public game-boundary workflow. Acceptance requires:

1. anonymous API response contains only the documented fields;
2. the public page shows the expected name, endpoint, current map, and
   occupancy without private values;
3. external A2S reaches the advertised endpoint;
4. Steam deep link and copied console command resolve to the same endpoint;
5. one operator connection succeeds and the displayed occupancy updates on a
   later observation.

A multi-player session is not required. Target configuration and acceptance
evidence remain outside this implementation commit until the advertised
endpoint is explicitly selected.

The firewall transition, rollback, RCON isolation, and target checks are
defined in [v2.25 Public Game Boundary](v2.25-public-game-boundary.md).

## Implementation Result

The local API, Web, configuration, and test changes are complete. Focused
Application/API/Web coverage, the full repository test suite, opt-in desktop
and mobile browser checks, production Compose rendering, formatting, build,
and the transitive vulnerable-package audit passed on 2026-09-22. The first
candidate was rolled back after its external A2S gate exposed the restricted
host firewall. The repository now includes the separate plan-first
remediation; no target firewall state is changed by this commit.
