# v2.131 - Operator command dispatcher health

## Scope and interpretation

Expose the existing [v2.130 observations](v2.130-command-dispatch-liveness.md)
through the Operator-only API, detail page, eighth overview card and eighth
source in the bounded UTF-8 health report. No command is created, retried,
replayed or requeued by this read flow.

Running means recent completed cycle progress, including an empty queue. An
individual failed RCON response is not a cycle failure. Running does not prove
command delivery or an empty queue. Error, Disabled, Stale and Unknown retain
their distinct meanings; missing, invalid or ambiguous observations never
establish healthy progress.

## Read contract

`GET /api/operator/command-dispatch-health` requires the existing Operator
policy. `/operator/command-dispatch-health`, `/operator/health` and the existing
health-report download use the server-side BFF. Unauthorized responses and
rendered health content use `no-store`. No tokens, command contents, private
endpoints, source labels or raw errors reach the browser or report.

The API reads twelve fixed gauges and three existing rules independently, with
two bounded requests and no retry. Each read has a five-second deadline and a
32 KiB response limit; the BFF has a seven-second deadline and a 16 KiB response
limit. Caller cancellation propagates. The report remains below 32 KiB in the
maximum fixture and reads each of eight configured sources once. Failure of
one source leaves the other seven available; a disabled incident receiver is
not queried.

Worker observation time, API evaluation time and warning evaluation time remain
separate. Observations must be nonfuture and no older than 120 seconds; API and
rule evaluations must be no older than 60 seconds. Completion age is recalculated
at rendering/download time. The existing observation budget is validated in
the range 300-4,295,148 seconds; it does not change command execution timeouts.
Exactly one fresh enabled source is required for an active observation.

The page and report show start, finish, success and failure times, duration,
consecutive failures, in-progress state and the three existing warning states.
Fixed first checks link to the existing runbook. Refresh is explicit; no polling,
acknowledgement, silence, threshold change or recovery control is added.

## Delivery and acceptance boundary

R1, additive API/Web read flow. Recreate only API and Web using verified immutable
digests. Preserve the other thirteen containers, configuration, monitoring
rules/routes, worker behavior, credentials, game/agent and hourly Archive cadence.
No migration, new permission or provider change is required. An old API yields
an unavailable new source rather than fabricated progress during mixed versions.

Rollback restores the exact prior API/Web digests and environment bytes. Existing
volumes and monitoring state are preserved. Required gates are focused projection,
authorization, failure-isolation, cancellation and browser tests; the full local
quality gate; scoped InspectCode; required PR/main and publication CI; independent
runtime continuity; and authenticated detail/overview/UTF-8 download acceptance.
Stable promotion must reuse accepted candidate bytes without rebuilding.

## Local verification

The full restore, format, build, test and vulnerability-audit gate passed:
2,313 ordinary tests and 70 opt-in browser tests. Desktop and mobile fixtures
were visually reviewed. All 256 source-failure combinations retain available
sections; caller cancellation and a stalled response body are bounded.

After a test-only disposal/style correction, all 54 focused command-dispatch
unit tests passed. Scoped InspectCode completed with zero errors, 11 warnings
and 105 notes. Findings were reviewed: nullable guards intentionally reject
malformed input; Razor path warnings refer to registered server routes;
remaining notes are established style, bounded collection suggestions or
unrelated existing code. No inspection setting was suppressed or weakened.

Read-only production query and Compose preflight passed. PR/main CI,
publication, deployment and independent target acceptance remain pending.

The first candidate passed runtime checks, but actual browser acceptance found
that the overview introduction still said seven sources above eight cards.
It was rolled back to the exact prior API/Web images; the other thirteen
containers were preserved. The corrected candidate updates that sentence and
extends the existing browser check before repeating independent acceptance.
