# v2.54 - Сохраненный рекорд серии убийств

Статус на 2026-10-09: addon 0.21.0 установлен и принят после независимых
A2S/RCON/host проверок. Продуктовый PR #283 слит; required PR и post-merge CI
прошли. Клиентская проверка остается отложенной владельцем.

## Граница

R2: сохранять максимальную серию подходящих убийств между подключениями,
картами и процессами. `/stats` выводит три приватные RU/EN строки: сохраненный
рекорд, текущую/лучшую серию подключения на карте и прежние totals. Общий cooldown
действует на весь ответ. Отсутствующая запись означает ноль с пояснением
"с начала учета рекордов"; неизвестная identity или отказ хранилища имеют явный
недоступный статус. Прошлые рекорды не выводятся из накопленных kills/deaths.

Новый рекорд объявляется только после точного readback. Если он совпал с
порогом 3/5/10, одно сообщение о рекорде заменяет сообщение о текущей серии.
Повторение или меньший результат запись не меняет. Убийства ботами/ботов,
HLTV, своей команды, после собственной смерти и вне игрового состояния
не увеличивают рекорд. Любая смерть сбрасывает счетчик текущей жизни.

## Хранение и совместимость

Точная запись `1 N` по ключу `streak:<canonical player key>` находится в
существующем preferences nVault. Максимум N равен 1000000000. Отдельный namespace
не меняет stats, language/weapons, HUD, name и leaderboard. Дополнительный файл,
миграция или изменение backup allowlist не нужны. Вход и чтение не создают
нулевую запись; новая запись появляется при первом подтвержденном рекорде.

Используются существующие Steam identity и connected-owner guards preferences.
До доступности уникальной identity серия остается только в текущем подключении.
После поздней авторизации счетчик для сохраненного рекорда начинается с нуля;
предыдущие неизвестные убийства в него не переносятся. Смена карты, reconnect
и перезапуск также завершают активную серию, но восстанавливают ее рекорд.

Поврежденная запись сохраняется без перезаписи. Ошибка readback блокирует
дальнейшие записи рекорда до reconnect; неизвестный side effect не повторяется.
При следующем входе читается фактическое значение. Ошибка только рекорда не
отключает остальные настройки и статистику; blocked base preference не обходится.
Status `PLAYER_STREAK_RECORD_STATUS` показывает схему, доступность и число ошибок
без раскрытия идентичностей или содержимого записей.

Обратная замена plugin и matching dictionary на принятую 0.20.0 оставляет
новые записи на месте. Во время работы старой версии рекорды не обновляются.
Повторный переход на 0.21.0 загружает сохраненный максимум и начинает новую жизнь.
Существующий backup обеих vault покрывает новую запись. Production restore
и сброс данных не являются частью установки или отката.

## Проверки

Focused engine smoke прошел на закрепленных AMXX 1.10.0.5481 и ReAPI 5.24.0.300
с настоящим nVault и native damage. Проверены RU/EN, новый/равный/меньший рекорд,
порог серии без дублирования сообщения, неизвестная и поздняя identity,
переподключение, duplicate owner, поврежденная запись, отсутствующий vault,
неуспешный и неопределенный readback без retry, насыщение счетчика и сохранность
значений/timestamps существующих preferences/HUD. Просмотр не создает рекорд;
ошибка рекорда не мешает отдельной записи preferences.

Продукт и все пять fixtures скомпилированы закрепленным toolchain. Общая
регрессия меню/справки, HUD, сохранения настроек, первой выдачи, девяти комплектов
оружия, рангов и уведомлений о повышении, рейтинга и личной позиции прошла.
Отдельная проверка правил боя сохранила исключения для team/bot/HLTV, поведение
лечения, боеприпасов и локальной серии. Все runtime markers имеют `failures=0`;
новых AMXX error logs нет. Контейнеры без сети и опубликованных портов завершены;
входные mounts оставались read-only.

Fresh-process seed/reload на другой карте восстановил рекорд 7 без переноса
активной серии. Отдельный rehearsal выполнил seed 0.21.0, остановку, создание
bundle существующим `player-data-bundle.py`, restore в новый каталог, побайтовое
сравнение, запуск принятой 0.20.0 и возврат на 0.21.0 на другой карте.
Предыдущие source, dictionary и fixture взяты из
`95e54a225fdaf862c114446020978ceecf5065ee`. После всей цепочки ключи, значения
и timestamps обеих vault совпали с закрытым источником, включая новый рекорд.
Исходная копия тоже сохранила хеши. Использовались только синтетические данные.

Package smoke проверил точный состав manifest/payload/archive, SHA-256,
62 ключа RU/EN dictionary и отказ перезаписать существующий output. Loader и
включенная configuration совпали с принятым пакетом 0.20.0 побайтово.

## Пакет публикации и установки

Владелец подтвердил пакет v2.54: push, продуктовый PR, squash merge после

## Установка и независимая приемка

[Продуктовый PR #283](https://github.com/tov-vl/gold-src-ops/pull/283) слит
из подписанного reviewed head `a71c48e2349abd44227d75921f00850ef8d0ae1f`
в `main` как `d05370ded28fe58aa5a6ce3e6c045c55fbcc2af8`; деревья совпали.
[Required PR CI](https://github.com/tov-vl/gold-src-ops/actions/runs/37929416524)
и [post-merge CI](https://github.com/tov-vl/gold-src-ops/actions/runs/37929675325)
прошли по addon-only маршруту. Это отдельное подтверждение компиляции,
dictionary/package и installer/rollback checks, без запуска .NET/Playwright.

Перед установкой проверены принятая 0.20.0, доступность хранилищ и рейтинга,
пустой сервер, SHA-256 исходников/пакета/operator wrappers и синтаксис wrappers.
Пакет перенесен без пересборки с проверкой точного состава и хешей. Повторный
A2S непосредственно перед остановкой подтвердил `players=0`, `bots=0`.
Установка выполнена один раз; сохраненный exit code равен 0. Через замену
до старта сверены закрытые vault/journal и прежний baseline. Служба агента
не перезапускалась; остановка и запуск затронули только игровой процесс.

Отдельный внешний A2S/RCON probe подтвердил пустой сервер, три работающих
AMXX plugins, weapon addon 0.21.0, map addon 0.2.0, доступные stats/preferences
schema 1 и готовый leaderboard без ошибок. Статус личной позиции сохранил
общий cache contract. Новый `PLAYER_STREAK_RECORD_STATUS` подтвердил
`storage=nvault`, `schema=1`, `errors=0`, `feedback=private_after_readback`.

Независимый SSH postflight подтвердил точные payload SHA-256, прежние
map/loader/configuration и baseline, owner-only права vault, обе службы
active/enabled, прежний agent invocation и `NRestarts=0` у обеих служб.
Очередь и spool опустели, новых AMXX error logs нет. Откат не потребовался.
Сырые логи, контрольные суммы закрытых данных и операторские файлы сохранены
только в закрытой записи владельца вне Git.

Приемка на пустом сервере подтверждает установку и готовность хранилища,
но не отображение сообщений в реальном клиенте. Записи игроков для проверки
не создавались. Поведение нового рекорда, RU/EN сообщения, reconnect,
fresh-process и обратная совместимость подтверждены локальными engine
проверками на синтетических данных. Клиентская проверка и игра вдвоем
остаются отложенными; прежние ограничения v2.53 также сохраняются.

Этот addon этап не выпускал tags/images и не менял API/Web, PostgreSQL,
расписание backup или доставку предупреждений. Первый weekly backup
2026-10-11 в 04:00 МСК остается самостоятельной приемкой.
