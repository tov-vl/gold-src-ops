# v2.35 Player Ranks

Status as of 2026-10-04: addon 0.6.0 is implemented and focused local checks
passed and the addon package is frozen. PR CI and pilot installation are
pending. The running pilot has not been changed by this slice.

## Behavior

Private `/rank`, team-chat `/rank` and console `rank` show a progress tier
computed from existing saved human enemy kills, plus kills remaining to the
next tier. This is accumulated progression, not a skill rating or a global
leaderboard. Deaths do not subtract progress. The highest tier explicitly has
no next tier. The initial MVP thresholds are:

| Tier | Saved Kills |
| --- | --- |
| Recruit | 0 |
| Fighter | 25 |
| Veteran | 100 |
| Elite | 250 |
| Legend | 500 |

`/rank` has its own two-second per-client cooldown, reset on reconnect. It
does not consume the existing `/stats` or `/top` cooldown. Those commands,
scoring rules, inventory and first-spawn menu behavior remain unchanged; the
existing welcome hint also mentions `/rank`. No public promotion broadcast,
chat prefix, HUD, menu, XP counter or weapon/armor reward is introduced.

Rank is a read-only projection of the schema-1 totals introduced in
[v2.34](v2.34-persistent-stats.md). No rank is persisted separately, no record
is created on a rank query, and no existing record is reset or migrated.
Pending/shared identity, a concurrent duplicate, rejected data or unavailable
storage gives an explicit unavailable response, never a rank based on
nickname, IP or unsaved map scores. Existing authorization, bot/HLTV filters
and counter saturation still apply. Operator status reports only policy,
thresholds and enabled state, not identities or player records.

## Rollout Boundary

Treat this as an additive read-only R1 gameplay surface. Before a later pilot
upgrade, verify the frozen addon/package and exact predecessor receipt.
Preserve the existing vault/journal, ownership and permissions; do not rerun
the v2.34 absent-vault creation step. Use the stopped-game binary upgrade and
one short independent addon/A2S/host check. Rollback restores the accepted
0.5.0 binary/receipt and leaves the same schema-1 data intact.

There is no API/Web deployment, new module, agent restart, queue rewrite,
Auth0 prompt, boot-policy change or data deletion in this scope. Ordinary
required PR CI supplies broad repository coverage. Target mutation remains
pending explicit authorization of this named upgrade.
