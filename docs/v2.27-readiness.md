# GoldSrcOps v2.27 Release Readiness

Status as of 2026-09-25: product revision merged, the fixed profile active on
the public pilot game host, and quick respawn observed by one player. Candidate
and stable publication have not occurred. The gameplay mode remains an
experiment, not a completed Deathmatch or availability claim.

## Scope And Risk

This is an R3 game-host profile transition. It adds native ReGameDLL fast
respawn settings, a versioned map-change hook, schema-2 hash binding for the
active profile, and an exact classic-profile restore path. It changes no API,
Web, AlertReceiver, database, authentication, firewall, or control-plane
worker. The existing persistent game-event agent and its durable state remain
in place. `public-classic-v1` is the retained known-good rollback profile.

The accepted claim is narrow: a player can join the pilot server and return
to play quickly after a controlled death. It is supported by one live solo
session, not by a measured latency distribution. The configured two-second
protection and attack-unset settings passed read-only RCON checks, but their
visual and damage behavior were not proved on the pilot host. Objective-round
endings, spawn fairness, multiplayer balance, and sustained play are outside
the claim. A defect found later should be fixed in a new reviewed revision;
unknown behavior must not be reported as a passed test.

## Publication Boundary

- Proposed tag names are `v2.27.0-rc.1` and `v2.27.0`; neither is published.
  Freeze the final candidate source revision only after this documentation is
  reviewed and merged into `main`. Verify both tag names are still unused.
- Use the existing signed-tag publication workflow and independent immutable
  image checks. The common workflow may publish API, Web, and AlertReceiver
  images, but this slice does not deploy or restart those unchanged runtimes.
- Do not repeat the R3 profile switch, local map-change check, rollback
  rehearsal, reboot, or player session solely because a documentation commit
  or release tag is new. Before promotion, check read-only that the selected
  profile, installed guard, external A2S/RCON result, and settled aggregate
  still match the accepted target. If the host or reviewed bytes drift, stop
  and reassess rather than reuse the old acceptance.
- Promote the stable tag only from the accepted candidate revision, with the
  same immutable image digests and no rebuild. Record CI, tag, and claim-limit
  results in one short sanitized evidence update after publication.

No fixed soak window, second player, objective-round exercise, or return to
classic is a gate for this bounded MVP release. A future feature that changes
protection, scoring, round semantics, or spawn safety needs its own focused
test and claim boundary. The public pilot has no uptime or SLO promise, but
that does not relax rollback, secret, durable-state, or uncertain-side-effect
rules.
