# v2.120 - Archive health in the Operator report

## Scope and compatibility

Production remains R1, Web only. The existing Operator-only
`/operator/game-host-health/report` attachment adds a fixed Archive section
through the existing v2.118 API and BFF client. Its path, filename, UTF-8 plain
text content type, no-store and nosniff headers stay compatible. No migration,
API contract, permission, secret, monitoring policy or schedule change is needed.

The release also includes an isolated R3 CI recovery: the existing audited SDK
restore/build stays on the disposable runner, then the complete browser group
runs from its built assembly in the official Playwright .NET 1.62.0 Noble image.
The version matches the project package and its immutable digest is pinned.
The test container has loopback only, explicit shared memory and no host IPC or
extra privilege. There is no runtime APT/browser installation, resolver edit,
trust change, production host change or omitted test. Reduced CI paths stay
on the host and do not pull the browser container.

Two earlier Browser Smoke attempts failed before tests when APT could not
resolve the Azure mirror. The upstream runner
[configuration](https://github.com/actions/runner-images/blob/main/images/ubuntu/scripts/build/configure-apt-sources.sh)
uses that mirror before the two existing Ubuntu fallbacks. A guarded mirrorlist
repair passed its Linux rehearsal and hosted-runner preparation, but a bounded
HTTPS probe then timed out resolving the canonical Ubuntu archive too. The
mirror repair was discarded in favor of the official prepared test image. This
removes runtime Ubuntu repository DNS dependence; it does not claim to establish
the provider's internal DNS cause or repair DNS globally.

Each download reads each source once, concurrently, with its existing bounded
transport and no retry. Expected transport, timeout or invalid-JSON failures
make only that source Unknown. Caller cancellation propagates to both reads
and does not produce an Unknown attachment instead of cancellation.

## Projection

Generation time, game-host evaluation and Archive evaluation remain separate.
The report is a static collection of independent observations, not an atomic
snapshot or a live dashboard. Archive retains the v2.118 projection rules:

- API evaluation must be nonfuture and no older than 60 seconds.
- Observer time must be nonfuture and no older than 30 minutes. Unknown or
  Stale observations mask retained success data.
- Scheduled-success age starts at creation of the latest accepted first-attempt
  schedule run on main. Manual runs and reruns do not refresh it. Zero is valid;
  no accepted success keeps age Unknown.
- Rule evaluations are independent, require all four known rules and must be
  nonfuture and no older than 60 seconds. Missing, duplicate, invalid or stale
  rule data does not establish absence of warnings.

The section includes fixed first checks for the four existing rules and the
existing Archive runbook. Only validated timestamps, finite values, fixed names
and states appear. Provider messages, credentials and arbitrary strings are not
reflected. Output remains below 32 KiB, including all 17 game-host warnings and
the four Archive rules.

A firing delay warning can coexist with an Available observation. A successful
workflow is not independent object Recovery, complete source coverage,
notification delivery or an achieved SLO. The report does not dispatch, retry,
acknowledge or silence anything.
