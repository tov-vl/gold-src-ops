# v2.129 - Retention in the Operator health report

## Scope and compatibility

Extend the existing Operator-only health attachment from six sources to seven
using the accepted retention API and BFF client. Keep the route, fixed filename,
plain-text UTF-8, no-store and nosniff. The overview download text describes all
seven independent sources.

The new section reuses the validated retention view for worker state, start,
completion, success and failure times, completion age, last duration, consecutive
failures, in-progress state and existing operational budget. The three existing
warning states and their evaluation time remain independent. Unknown, Disabled
and Stale never establish healthy cleanup. Freshness is checked at generation;
generation time never replaces the source observation time. Successful empty
or full-batch cycles do not establish backlog size or cleanup exhaustion.

Each configured source is read once concurrently through its existing bounded
transport and the request cancellation token. Expected HTTP, timeout, JSON and
invalid-data failures isolate one source as Unknown. Caller cancellation stops
the download. Disabled receiver access remains unqueried. The fixed projection
stays below 32 KiB with maximum accepted values and all 27 existing warnings;
raw provider text, identifiers, addresses, credentials and secret references
are excluded.

## Delivery boundary

R1, install only Web. Reuse the accepted v2.128 API. API/receiver publication
does not imply their installation. Preserve all fourteen other containers and
protected configuration. No schema, durable state, worker, retention setting,
warning policy, credential, permission, provider, game/agent or Archive cadence
change. Rollback restores only the prior Web digest and its exact environment
bytes. Stable promotion reuses accepted candidate digests without rebuilding.

## Verification and readiness

Local verification passed all 128 source-failure combinations, authorization
with zero reads, disabled receiver, concurrency/cancellation, retention freshness
and malformed-input cases, and maximum UTF-8 output. The complete local quality
gate passed 2,068 tests; its 69 opt-in browser cases were exercised separately
and all passed with zero skips. The initial explicit browser invocation used an
incorrect opt-in value and skipped all cases; it is not acceptance evidence.
Final 229 focused cases and the two affected desktop/mobile JavaScript-disabled
browser cases passed after two test-style review fixes. Scoped InspectCode
completed with zero errors/warnings and 32 reviewed notes; cancellation completion
checks retain their independent deadline and established style is preserved.
No suppression, severity or CI routing change was made.

Required PR/main CI, immutable publication, independent Web-only runtime and
actual authenticated seven-source download acceptance passed. Stable promotion
reused accepted digests without rebuilding. Fixture verification is separate
from production acceptance.
