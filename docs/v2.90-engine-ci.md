# v2.90 - Required gameplay engine smoke

Status on 2026-10-21: released in `main`; full required product PR CI and
post-merge CI passed. Hosted engine evidence independently verified.

## Scope and release boundary

The existing `Container Smoke` check executes the gameplay fixtures instead of
relying on compilation and shell syntax alone. Its dependency on successful
`Map Menu Compile` is unchanged. Documentation-only and stable-promotion runs
retain their lightweight confirmations. Shared runner and workflow edits select
full CI; no branch-protection change is required.

Risk is R3 for the changed CI policy. Acceptance requires the routing matrix,
result-rejection tests, an actual failing engine fixture, a clean hosted runner
and green required PR/main checks. The approved delivery consists of ordinary
push, product PR, squash merge and evidence PR. No application tag, container
publication, addon package or production rollout is applicable. Addon 0.36.0
remains unchanged. Reverting this CI change restores the preceding workflow;
no player-data restore is involved. The owner deferred v2.89 client acceptance.

## Reproducible inputs

- `Map Menu Compile` uses the existing AMXX 1.10.0.5481 / ReAPI 5.24.0.300
  Windows compiler, including the deliberate failure fixture.
- `engine-ci.py --package-fixtures` packages six binaries and records their
  hashes, product/fixture/dictionary inputs and compiler-script hashes.
- Linux downloads the exact artifact name emitted by the producer job and rejects
  a missing file, changed binary or checkout mismatch before starting Docker.
- `engine-ci-lock.json` pins the game-files image and the Steam-client image
  by digest, the extracted Linux32 Steam client by SHA-256, and six upstream
  archives by SHA-256. The archives contain ReHLDS 3.15.0.896, ReGameDLL
  5.30.0.814, AMXX 1.10.0.5481, Metamod-R 1.3.0.149 and ReAPI 5.24.0.300.
- The cache contains only verified archives. Every hit is hashed again;
  tampered cached content fails without automatic replacement. A cold cache
  downloads the pinned HTTPS inputs. Image pulls use exact digests.

The engine container has no network or published ports, two CPUs, 1 GiB memory
and a 256-process limit. Repository, extracted inputs and compiled fixtures are
read-only mounts. Game data lives in the disposable container; the only writable
host mount is a new evidence directory. The engine runs as an unprivileged user.
Each process has a 45-second deadline; the suite has a 600-second deadline and
an outer 630-second process bound. Only containers created by this invocation
are removed. The runner never uses live servers or credentials.

## Coverage and failure behavior

The 18 existing cases cover weapon selection and spawning; RU/EN settings,
HUD, help and rank guide; real nVault seed/reload on another map; saved stats,
rank boundaries, leaderboard/place, K/D, profile and saved streaks; leaderboard
reload; player lookup and its 4096-record load fixture. The selected-weapon
check includes 18 combinations and all 12 localized menu variants.

Every required marker must occur exactly once with `passed` and `failures=0`.
Assertions, native runtime errors, module/plugin load failures, missing language
keys and nonempty AMXX error logs are fatal. A separate fixture prints a
success-looking marker followed by an intentional assertion; the integration
test requires the real runner to exit unsuccessfully and preserve that evidence.
A missing marker, timed-out process or incomplete evidence cannot pass.

Compilation artifacts are retained for one day; synthetic engine logs and
result JSON are retained for seven days on success or failure. Inputs, game
files, vaults and private operator records are not diagnostic artifacts.
Each local invocation requires a new output directory and retains its evidence.

## Local command

With Docker available, run the existing pinned Windows compiler smoke into
a task-specific cache. Compile the product and `RuntimeFixture`,
`PersistentStatsFixture`, `PlayerMenuFixture`, `PlayerPreferencesFixture` and
`EngineFailureFixture`. Then use Python 3.12 or newer:

```text
python tools/smoke/engine-ci.py --package-fixtures --compiled <compiler-cache>/output --output <fixtures>
python tools/smoke/test-engine-ci.py --integration --compiled <fixtures> --cache <assets> --output <new-negative-output>
python tools/smoke/engine-ci.py --compiled <fixtures> --cache <assets> --output <new-positive-output>
```

On CI the workflow supplies these paths and transfers the compiled artifact.
The local command does not require Steam login, a second player or activity data.
Rendering in an actual RU/EN client is outside this automated coverage.

## Verification evidence

Local verification on 2026-10-21:

- The pinned Windows compiler built the product and all five fixture plugins.
- Eight runner tests passed, including changed binary/source rejection,
  mutable image rejection, cached-archive tampering and false success markers.
- The complete 18-case engine run passed in 151.801 seconds with no AMXX errors;
  owned-container cleanup passed. All six archives had been downloaded and
  hash-verified from an initially empty cache during this local verification.
- The actual negative fixture was rejected in 51.698 seconds and its synthetic
  assertion log retained; the integration harness confirmed failure propagation.
- The routing contract covers full/addon/docs/stable paths, fatal engine steps,
  bounded diagnostics and the producer-selected artifact identity.

Two initial container setups failed before gameplay: a file-size limit applied
before copying the base game, and a Linux compiler lacking a 32-bit library.
The limit now applies after setup; CI reuses the existing pinned Windows compiler
and transfers verified fixtures. A stale local compiler-source manifest was also
rejected before engine startup; a fresh package matched the reviewed source.
These failures affected only disposable local containers and synthetic data.

The complete .NET suite was not repeated locally for this CI-only change.
Hosted full CI ran restore with NuGet audit, formatting, build, tests and the
vulnerable-package report, plus all container and browser checks. No C# source,
addon behavior or production runtime is changed.

The first hosted [PR run](https://github.com/tov-vl/gold-src-ops/actions/runs/39615222702)
rejected container setup before any scenario: Linux refused opening an
unprivileged-owned FIFO under the sticky `/tmp` directory. The console FIFO now
lives inside the private game directory. Failed-run diagnostics were uploaded
and owned containers were removed. Required CI was not waived.
