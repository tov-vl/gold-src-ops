# v2.25 Public Game Boundary

## Goal

Make the accepted `public-classic-v1` Counter-Strike 1.6 endpoint reachable by
players without publishing SSH, widening the RCON source list, changing the
game profile, or restarting the active game process.

## Boundary

`public-game-firewall.sh` is a separate plan-first host policy transition. It
derives every host-specific value from the already accepted host and runtime:

- the game and SSH ports come from `host-prepared`;
- the only approved RCON source comes from the exact ReHLDS
  `rcon_adduser <IPv4>/32` line in `server-public.cfg`;
- the current SSH source must equal that RCON source;
- `public-classic-v1` and `guarded-autostart-v1` must remain active;
- the game service must be active/enabled and the event agent
  inactive/disabled;
- UFW must begin with default-deny incoming and exactly the two original
  control-plane rules.

Enable adds one IPv4 `ALLOW IN` rule for the existing game UDP port from
`0.0.0.0/0`. It retains the original exact-source game rule because that rule
is also part of the reviewed host foundation. SSH remains restricted by UFW,
while RCON remains restricted by the non-empty ReHLDS source list and its
existing password. No IPv6 rule is added.

The workflow accepts no address, credential, or secret argument. Its tracked
marker contains only hashes, policy identity, port, and an owner-only backup
reference; the source address and raw UFW baseline remain outside Git. Apply
and rollback share the existing game-host policy lock.

## Rollback

Disable verifies the marker, every bound input hash, current ReHLDS source
policy, public UFW shape, and owner-only baseline before deleting only the
IPv4 public game rule. It does not stop, start, reload, or restart the game.

A failed enable removes the added rule and owned marker. If rollback inputs or
current policy drift, the workflow fails closed instead of guessing at a
firewall edit.

## Repository Verification

Run:

```bash
bash ./tools/smoke/gameserver-public-game-firewall.sh
```

The smoke covers plan sanitization, argument conflicts, non-root apply refusal,
restricted and public UFW shapes, duplicate or unrelated rule rejection, exact
IPv4 add/delete ownership, hashed source binding, and the prohibition on
credential input or game-process control.

## Target Gate

This is an R3 infrastructure-policy change even though it does not restart a
process. Target acceptance requires, in order:

1. an owner-only restricted-boundary baseline and game invocation identity;
2. hash-verified execution of the reviewed workflow from the control-plane SSH
   session;
3. external A2S success from a source outside the control-plane allowlist;
4. proof that the same external source cannot execute RCON, while authenticated
   control-plane RCON still passes;
5. unchanged SSH restriction, game invocation, restart count, profile,
   autostart guard, and disabled event agent;
6. one operator connection and a later occupancy observation;
7. a rollback rehearsal that restores the exact restricted UFW shape without
   restarting the game, followed by one final apply and repeated checks.

Exact addresses, raw firewall output, RCON responses, and rollback inputs stay
in the owner-controlled operator record. Short acceptance does not prove DDoS
resilience, long-term availability, regional latency, or a sustained SLO.
