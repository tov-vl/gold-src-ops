## Scope

Add `/stats` and `/top` to the already installed addon rather than add a second
score plugin or a persistence service. Commands also accept team chat and the
console forms `stats`/`top`. The unchanged `goldsrcops_weapons_enabled` switch
controls inventory, welcome and statistics together; disabled mode does not
count deaths or answer these commands. First-spawn welcome includes the new
commands without changing the one-time menu/inventory behavior.

Statistics belong to the current connection and map/plugin lifetime. Disconnect,
client-slot reuse and map/plugin reload start at zero. A team change does not
reset the connection's score; spectators may read their own score and appear
among leaders if they previously played. No Steam identity, cross-map rank,
database, API, export, telemetry event, file or raw player log is added.

The native `DeathMsg` handler awards a kill only for connected human T/CT
opponents. World deaths, suicide and teamkill count a victim death but award no
kill. An encounter with a bot or HLTV client is ignored entirely. Disconnected,
invalid or spectator death participants are rejected. Headshots and objective
points have no separate scoring weight, and the engine scoreboard is untouched.

`/stats` returns kills, deaths and K/D to the requester. K/D is
`kills / max(deaths, 1)`, including before the first death; this convention is
shown in the response. `/top` returns at most five connected human players with
a nonzero score, ordered by kills descending, deaths ascending, then client-slot
order for exact ties. It is not a persistent leaderboard or a skill rating.
An empty table has an explicit response. Both commands have separate two-second
per-client cooldowns and print only to the requester. Names are bounded and
control characters are removed before formatting chat output.

The handler uses the pinned engine event API; see
[register_event](https://www.amxmodx.org/api/amxmodx/register_event) and
[read_data](https://www.amxmodx.org/api/amxmodx/read_data).
