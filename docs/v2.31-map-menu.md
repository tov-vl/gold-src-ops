# v2.31 Map Menu

Status as of 2026-10-04: product, packaging and installer PRs are merged with
required CI green. The bounded active-host addon installation and independent
A2S/plugin/configuration acceptance passed. Human menu/quorum remains untested.
No release tag or published control-plane image is required for this slice.

## Scope

Add a small optional `/maps` voting menu and chat `/timeleft` bridge to native
ReGameDLL commands. The menu uses the existing five-map managed cycle without
editing it, disables the current map and rejects stale or unsupported cycle
contents. Connected human team players may request votes; spectators may query
remaining time. The normal plugin is default-off and has its own config name.

Vote counting, cooldown, minimum elapsed time, required player count and quorum
remain owned by the pinned engine. The plugin submits a request and does not
claim that the request passed. It never forces `changelevel`, extends the
current map, lowers voting thresholds or implements a second voting system.
An accepted native vote may immediately change maps, interrupting the round.

See [the plugin instructions](../samples/amxmodx-map-menu/README.md) and the
pinned upstream [command handling](https://github.com/rehlds/ReGameDLL_CS/blob/5.30.0.814/regamedll/dlls/client.cpp)
and [map vote counting](https://github.com/rehlds/ReGameDLL_CS/blob/5.30.0.814/regamedll/dlls/multiplay_gamerules.cpp).

Spawn points remain stock. Random spawning, navigation files, custom spawn
coordinates, custom maps, new rounds/ranks, database/API work, boot-policy
changes and another telemetry activation are outside this slice. This does
not adopt a deathmatch mode or claim spawn fairness on an empty server.

## Focused Evidence

The product and separately compiled fixture passed the pinned offline Windows
compiler without warnings. The normal product also compiled with the pinned
Linux compiler. A network-isolated cached ReHLDS/ReGameDLL fixture loaded the
map source fixture alongside the accepted weapon-selection 0.2.0 addon.

The engine reported `MAP_MENU_SMOKE=passed failures=0 synthetic_clients=2`.
Checks covered exact cycle validation, changed/reordered/truncated/extra
entries, alternate cycle name, menu cancellation, out-of-range and foreign
menu IDs, current-map exclusion, disabled plugin/policy, spectator/bot
eligibility, time-left forwarding and one-based native vote mapping.

The synthetic fixture alone shortened the elapsed-time gate. With one team
player, the native engine refused the vote; with two, it recorded the first
player's vote for map ID 2 without forcing a map change. No AMXX error log was
created. Existing offline Steam and engine-CRC warnings remain separate.

A second isolated startup loaded the normal product binary, not the fixture,
alongside weapon selection 0.2.0. Both plugins were running; map status reported
enabled=1, cycle_ready=1, voting_enabled=1 and maps=5. The weapon status retained
three primary/pistol choices and armor/helmet. This is local loading evidence,
not active-host acceptance. PowerShell parsing and Bash syntax also passed.

This is not a human menu-rendering result, real-player quorum/map-change
acceptance or spawn-balance test. Those remain explicit MVP limitations.
No full local .NET suite, owner game session, long soak, reboot or Auth0 prompt
was required. PR CI additionally compiles product and fixture using verified
AMXX/ReAPI archives. A bounded host installation uses the supplemental package
and rollback/removal boundary below, then one loading/configuration check;
no separate stable publication is needed for this small gameplay experiment.

## Package And Rollout Boundary

The no-overwrite package builder ships only the product binary, enabled config,
separate loader and manifest. It checks the ZIP entry set and content hashes.
The accepted product source is unchanged from
[PR #236](https://github.com/tov-vl/gold-src-ops/pull/236); the pinned binary's
SHA-256 is `990acc92adc53f35951ef7c0883ac2bd4338f877b5db4032132dcff41e4e130b`.

The existing addon workflow now has a fixed `--map-menu` mode, with its own
paths, package purpose and receipt. Default weapon-addon behavior and schema
remain unchanged. Installation requires the stopped game, reviewed SSH
operator, persistent MP5 baseline, exact package and normal transition locks.
Removal additionally requires the expected installed manifest digest, keeps
an owner-only predecessor copy and restores all four owned files on failure.
Removal never starts a service and works with either loader state.

Local filesystem fixtures passed ordinary weapon and map-addon install,
toggle, upgrade, reverse upgrade, active-game/identity/drift refusals and
partial-copy/final-guard rollback. The map fixture additionally checked partial
removal/final-guard recovery and removal in enabled/disabled states while
keeping weapon and telemetry sentinels unchanged. Package hash/content and
no-overwrite checks passed. These are not live-host results.

Treat the host change as bounded R3 addon installation: one empty-game preflight,
one game stop/install/start, unchanged-baseline/agent-invocation checks, and one
external A2S/plugin/configuration postflight. If installation or the target
gate fails, restore/remove only this addon and preserve queue/spool. An unknown
outcome requires read-only reconciliation, not another installation attempt.
No agent restart, identity prompt, reboot, long soak or repeated player session
is part of this boundary. Human menu/quorum and addon boot-time hash binding
remain explicit limitations, not passing claims.
