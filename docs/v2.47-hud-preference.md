# v2.47 Persistent HUD Preference

Status as of 2026-10-08: addon 0.17.0 implemented, packaged and verified locally.
Product PR CI, merge and runtime installation remain separate gates.
The accepted game-host version remains 0.16.0.

## Reason And Scope

In the accepted addon 0.16.0, `/settings` toggles HUD for the current connection only.
`client_putinserver` and disconnect reset `g_hud_disabled`; the toggle does not
save a preference. Language and primary/pistol choices already persist by
canonical SteamID in the separate schema-1 preferences nVault described in
[v2.39](v2.39-player-preferences.md).

Addon 0.17.0 retains an explicit HUD on/off choice after reconnect and
map/plugin restart. Players without a stored choice keep the current
enabled default, without writing defaults on join. The accepted HUD timing,
position, menu coexistence and alive/player filters remain unchanged.

This is a settings improvement with focused automated acceptance independent
of the two-player combat scenario. The owner deferred that scenario indefinitely
on 2026-10-08. Combat rewards, streak milestones and multiplayer balance remain
unverified by human play; this slice makes no claim about them.

## Compatibility And Storage Boundary

Existing language/weapon preference and statistics records keep their formats.
HUD uses the same canonical identity and connected-owner guard as preferences.
Bots/HLTV, shared/unknown identities and duplicate connected SteamIDs cannot
persist HUD. Late authorization restores untouched HUD state but preserves and
saves an explicit toggle already made in this session. Unavailable identity or
storage leaves a usable session-only toggle.

The existing preferences vault stores a separate `hud:<canonical preference key>`
record. Only exact `1 0` (enabled) and `1 1` (disabled) values are valid.
HUD-only selection writes no language/weapon defaults. Rendering, menu inspection
and joins do not write records. The format and reverse-upgrade boundary are
recorded in [Decision 36](architecture-decisions.md#decision-36-persist-hud-in-a-separate-preference-record).

Corrupt HUD records are retained without replacement. Failed exact readback
blocks HUD writes until reconnect, even when a write may have persisted; the
session toggle still works. Separate language/weapon choices remain writable.
If the underlying identity/preferences record is blocked, HUD cannot bypass it.
Settings show independent RU/EN saved/session messages for HUD and for
language/weapons, based on exact current records. Menu labels no longer claim
that HUD is always unsaved.

No scoring, streak, heal/ammo reward, weapon application, rank, global leaderboard,
VIP/payment, map addon or control-plane change is included. No PostgreSQL
migration, credentials, new external service or installer-driven vault migration
is needed for this boundary.

## Local Verification

all five existing gameplay fixtures. The network-disabled disposable engine,
with read-only input mounts and no published ports, passed real-nVault checks:

- Explicit off/on selection, exact readback, reconnect, slot reuse and a fresh
  process on another map; joining without a selection must not write defaults.
- Late authorization preserving the current-session toggle, canonical identity
  normalization and refusal of duplicate/shared/unknown identities.
- Invalid records retained, unavailable storage and readback failure falling
  back to session behavior without retry; disabled-addon, bot and stale menu

- Existing language/weapon records and the statistics sentinel remaining intact.
- Fresh-process sequence 0.17.0 seed -> 0.16.0 predecessor -> 0.17.0 recovery:
  the predecessor restores its old records, ignores HUD state, and retains the

  periodic HUD/menu and loadout regressions.

## Delivery Boundary And Remaining Gate

This is an R2 addon-only player-state change. The owner authorized merging the
documentation PR, implementation, checks and preparation of a product PR and
package. Product merge and game-host installation are not part of that request.

The game-host package changes the plugin and RU/EN dictionary together; loader
and enabled configuration stay byte-identical. Retain the accepted 0.16.0 package
for plugin/dictionary rollback. Neither direction installs, restores, deletes or
rewrites vaults. Any later authorized installation must preserve stopped-game
vault/journal hashes and independently verify package, storage, plugin and A2S
state. No tag/image publication, API/Web rollout, reboot or two-player combat
session is required for this settings boundary.
