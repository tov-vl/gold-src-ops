# v2.69 - Keyboard navigation and readable public pages

Accepted on 2026-10-12 as stable v2.69.0 from the verified v2.69.0-rc.1.

## Scope

R1, Web only: `/`, `/play` and `/leaderboard`, RU/EN. Preserve anonymous
bounded reads, refresh timing, connection controls and static SSR. No API,
database, game, backup, authentication or scoring changes.

## Behavior

- The first keyboard stop is a localized skip link. Enter moves focus to main
  content using a normal same-document anchor with the full current path and
  query, preserving language and history period even with the HTML base URL.
  Unsupported or duplicate query values use the bounded canonical page link.
  The link works without JavaScript; main is outside the ordinary tab order.
- Document language follows the public RU/EN selection. Operator and other
  routes keep English. Existing page-level language boundaries remain.
- Public content wraps long words and the mobile navigation uses shrinkable
  columns. Main links and buttons have a visible keyboard focus outline.
- A stable, initially empty atomic status region announces the final manual
  refresh result and semantic availability changes. Routine successful timer
  reads, every-second age updates and tab pause/resume do not announce.
  Repeated failures in the same state are quiet; recovery and expiry can
  announce once. Clipboard feedback retains its separate live region.
- Visual refresh feedback remains available. It is not also the live region
  or a changing accessible description of the focused refresh control.

## Evidence plan and limits

Three browser scenarios cover keyboard skip and refresh in both languages,
with and without scripts, keyboard copy, double text at 1440/720/320 CSS pixels,
and controlled automatic success/failure/recovery without repeated live-region
mutations. Existing browser tests cover expiry, request bounds and focus.

Production baseline reproduced 108px horizontal overflow on the Russian home
page and 119px on the Russian player guide at 320px with doubled root text.
The changed pages must have no document overflow or clipped control/headline
text under the same check. Inspect representative screenshots separately.

Doubled root text tests text resizing; a 720 CSS-pixel viewport additionally
checks the layout width of a 1440-pixel desktop at 200% zoom. These are explicit
browser-layout checks, not a claim of complete browser-zoom equivalence or
WCAG conformance. DOM/accessibility semantics and announcement mutations do
not replace listening with a real screen reader. No NVDA/JAWS/VoiceOver
listening session is claimed. Game visual acceptance remains deferred.
