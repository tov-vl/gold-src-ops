# GoldSrcOps v2.23 Managed Game-Server Profile

## Status

Local implementation complete. The repository defines and tests one fixed,
credential-free Counter-Strike 1.6 server profile. Two target acceptance runs
have failed closed and restored the baseline: the first exposed a startup
observation race, while the second proved that ReGameDLL's `game.cfg` overrides
managed cvars after a map transition. Target acceptance remains pending and the
live game host is restored to baseline.

## Goal

Move product development back to the controlled ReHLDS runtime by managing one
reviewed set of public match rules and map rotation with an exact rollback
boundary. This slice improves the playable server itself without turning the
control plane into an SSH client or arbitrary file manager.

## Profile

The first profile is `public-classic-v1`:

- 25-minute map limit;
- 2.5-minute rounds and 5-second freeze time;
- default starting money and bounded buy time;
- friendly fire off;
- team balance and two-player team limit enabled;
- 35-second C4 timer;
- `de_dust2`, `de_inferno`, `de_nuke`, `de_train`, and `cs_office` rotation.

The profile also assigns itself as ReHLDS `mapchangecfgfile`. ReGameDLL executes
its shipped `game.cfg` while activating a map, so this late map-change hook
re-applies the reviewed values after those defaults without modifying vendor
files or the systemd unit.

The profile intentionally excludes passwords, RCON policy, plugins, bots,
downloads, advertisements, VIP entitlements, and payment behavior.

## Apply Boundary

`ops/gameserver/managed-profile.sh` is plan-only by default. Apply requires the
reviewed active, boot-disabled runtime and the operator identity recorded by
host bootstrap. It:

1. verifies the public configuration and exact-source RCON contract;
2. acquires a non-blocking host transition lock and verifies the recorded
   runtime-marker and systemd-unit hashes before stopping the service;
3. preserves an owner-only exact rollback copy;
4. renders the fixed profile and map cycle without accepting values or secrets;
5. stops the game before changing runtime files;
6. installs root-owned, service-readable files and a hash-bound marker;
7. starts the service once and waits within a bounded gate for both public and
   profile load markers from the same systemd invocation, failing immediately
   if the service stops, restarts, or changes invocation;
8. leaves the service disabled across boot;
9. invokes the same baseline restoration after any failed transition or lost
   controlling session.

Rollback requires the recorded marker and all active hashes to match. It
restores the exact pre-profile public configuration and removes only files
owned by this workflow. Retained owner-only backup material remains deployment
evidence outside Git.

## Evidence And Claim Limits

On 2026-09-22, a target preflight confirmed the active, boot-disabled,
plugin-free baseline, all five required maps, and the exact-source RCON policy.
The first apply reached the post-start verification before either load marker
was observable and therefore invoked the automatic baseline restoration. A
read-only follow-up confirmed an active, boot-disabled service with zero
restarts, no managed-profile residue, and the baseline public marker loaded.
No apply retry was attempted. The workflow now polls the same invocation for a
bounded interval while preserving the original fail-closed checks; its smoke
reproduces load markers arriving on a delayed observation.

A second reviewed apply passed external A2S, authenticated RCON inspection,
zero-bot, and exact-source gates on `de_dust2`. One audited transition to
`de_inferno` succeeded, but the post-transition RCON gate observed
`mp_timelimit=20` instead of the managed value `25`. Read-only inspection tied
the value to ReGameDLL's shipped `game.cfg` and the stock `server.cfg`. The
workflow was actively rolled back once; the baseline then passed its service,
profile-residue, plugin, map, and exact-source checks. The profile now uses the
fixed ReHLDS map-change hook and must repeat the same bounded target acceptance.

The deterministic smoke proves rendering, the exact map-change hook, plan-only
behavior, fail-closed marker insertion, apply ordering, rollback traps,
credential exclusion, and the boot-disable invariant. It does not prove that
the maps exist on the target, that ReHLDS accepts every rule, that clients can
connect, or that rotation advances after `mp_timelimit`.

Target acceptance therefore still requires, after a separately reviewed apply:

- external A2S reachability and the expected server name;
- authenticated read-only RCON inspection of the managed cvars;
- zero bots and unchanged exact-source RCON policy;
- one bounded map transition from the managed rotation;
- successful active rollback rehearsal before unattended use is considered.

Until those gates pass, `public-classic-v1` is locally verified deployment
logic, not a production-accepted server profile.
