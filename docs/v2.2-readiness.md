## Owned-server Evidence

On 2026-08-28, the guarded workflow ran against an ephemeral loopback-only
Counter-Strike 1.6 server using ReHLDS 3.14.0.857 and ReGameDLL_CS 5.28.0.756.
The server image source was pinned, release checksums and signature were
verified, and runtime containers had no source or Docker-socket mount.

The normal guarded `say` command succeeded. The read-only `cvarlist` command
then exercised the multi-datagram path through the authenticated API and durable
dispatcher:

| Observation | Result |
| --- | ---: |
| Command terminal status | `Succeeded` |
| Command-response datagrams | `12` |
| Aggregate command-response wire bytes | `16549` |
| Command send to first response | `9.999 ms` |
| First-to-last response span | `75.615 ms` |
| Maximum observed inter-datagram gap | `8.206 ms` |
| Dispatcher lifecycle duration | `212.225 ms` |

The payload-free capture retained only timing, direction, datagram length, and
response type. It did not retain command output, credentials, RCON passwords,
bearer tokens, or secret references. This single controlled sample supports the
100 ms default but is not a completeness guarantee for other engines, paths,
loss, reordering, or production load.

## Compatibility And Rollout Evidence

- Public HTTP contracts, DTOs, JWT policies, command types, metrics, and
  database schema are unchanged.
- No EF Core migration, backfill, or coordinated database rollout is required.
- Omitted settings use validated compatible defaults; invalid explicit values
  fail startup.
- Existing single-datagram responses remain supported.
- Application rollback to v2.1.0 changes no persisted data but restores the
  known one-datagram limitation.
- Automatic command retry remains forbidden because an ambiguous timeout can
  follow successful remote execution.

## Accepted Boundaries

- Ordinary GoldSrc RCON chunks have no response identity, fragment count,
  ordering metadata, or explicit completion marker.
- A quiet interval is necessarily heuristic. A later datagram may be missed
  after successful completion.
- UDP loss and reordering cannot be detected or repaired.
- A connected socket filters by resolved endpoint but does not authenticate the
  datagram source. The RCON credential and trusted network remain the security
  boundary.
- The owned-server result covers one pinned ReHLDS build and one loopback path;
  target-environment timing and engine compatibility require deployment
  evidence.
- Complete console output is not persisted. The existing bounded sanitized
  command result summary remains the durable contract.
