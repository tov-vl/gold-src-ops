# v2.123 - Polling health in the Operator report

## Scope and compatibility

R1, Web only. The existing Operator-only attachment
`/operator/game-host-health/report` adds a fixed polling section through the
accepted v2.122 API and BFF client. Its path, filename, UTF-8 plain text,
no-store and nosniff contract remain compatible. API, receiver, database schema,
monitoring policy, permissions, providers, game/agent and Archive cadence are
outside this slice. The existing image set is published canonically; only Web
is installed.

Every download starts the game-host, Archive and polling reads once and in
parallel through their existing bounded transports. Expected HTTP, timeout,
invalid-data or JSON failures make only the affected source Unknown, without
retry. Request cancellation propagates to all three reads and does not return
an invented Unknown attachment. The report is a static collection of independent
snapshots, not an atomic observation or a refreshed copy of the displayed page.

## Projection and claim limits

The new section reuses the existing polling projection. It includes its API
evaluation and observer times, cycle start/completion, completion age and
operational budget. Three fixed warning states retain their separate evaluation
time, first checks and the accepted runbook. The generated report time never
refreshes the upstream observations.

Unknown, Running, Error, Disabled and Stale retain their v2.122 meanings.
Observer freshness remains 120 seconds; API and rule evaluations remain at most
60 seconds old and nonfuture. Old/malformed data masks retained activity as
before. Completion age is independently recomputed at generation and can cross
the existing budget even if the source still says Running. Missing or stale
warning data does not establish absence of warnings.

Only validated finite values, timestamps, known names and fixed text appear.
The combined report remains below 32 KiB with all 17 game-host warnings, four
Archive rules and three polling rules. Provider messages, credentials, arbitrary
strings and private source identities are not reflected.

Empty completed passes and failed A2S replies are worker progress. HTTP health,
server availability, notification delivery, Archive object Recovery, full source
coverage and an achieved SLO remain separate evidence. This download cannot
restart, replay, dispatch, retry, acknowledge, silence or change thresholds.

## Verification and release readiness

Focused report and endpoint cases cover all eight combinations of unavailable
sources, independent timestamps/states, stale/future data, completion-budget
crossing, malformed payloads, output bounds and denied roles. A three-source
barrier verifies that all reads start before any completes and that cancellation
reaches all three without retry. The existing script-disabled browser download
case now checks the polling section and server-side bearer boundary too.

The audit-enabled local quality gate passed restore, format, a warning-free
build, 1,703 tests and the vulnerability audit. Its 66 opt-in browser cases are
reserved for hosted CI. Final focused checks passed 79 cases; the actual local
script-disabled browser download also passed after the last source changes.
Scoped InspectCode completed without errors or warnings. Reviewed notes retain
independent cancellation-test deadlines, xUnit await conventions, established
file style and the existing fluent map signature. No suppression was added.

Required PR/main CI, immutable candidate checks and independent runtime/download
acceptance remain release gates. Fixtures are separate from production state
and do not establish provider delivery or player rendering.

Rollback restores the exact prior Web image slot and recreates only Web with
its accepted digest. API and thirteen other captured containers, volumes,
monitoring files and the deployment model are preserved. No database restore,
monitoring reload or Archive write is needed. Stable promotion must reuse the
three candidate digests without rebuilding.
