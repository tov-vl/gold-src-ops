# v2.51 - Мониторинг backup игровых данных

Статус на 2026-10-09: локальная реализация и проверка завершены; публикация и установка
еще не выполнены. Предупреждения остаются в Prometheus/Grafana, личная доставка
отложена по решению владельца.

## Scope и совместимость

R3: read-only наблюдатель control-plane, отдельный минутный systemd timer,
OTLP/HTTP receiver на внутреннем 4318, пять правил Prometheus и provisioned
Grafana dashboard. Существующие pinned telemetry images сохраняются; новых
application images, addon packages или migrations нет.

API/Web/PostgreSQL, игра, агент, форматы vault, weekly runner и его доступ
не меняются. Возраст копии считается от capture, занятая игра сама по себе
не является ошибкой. Недостоверный журнал и потеря наблюдений видны отдельно.
См. [процедуру установки, проверки и отката](game-player-data-monitoring.md).

## Доказательства

- 20 offline Python tests наблюдателя и 19 regression tests weekly backup прошли.
- 19 promtool scenarios прошли: healthy/busy, in-progress, pending/error,
  timer/missed slot, missing/stale copy, invalid observation, lost/frozen/future
  heartbeat, debounce и recovery.
- Реальный pinned Collector -> Prometheus -> Grafana: OTLP JSON принят,
  значения и rule health проверены; invalid observation переходит в pending,
  подавляет зеленые панели и возвращается в healthy. Новый dashboard
  provisioned/non-editable; все его PromQL queries исполнились.
- Systemd 255 на Ubuntu 24.04 проверил оба units. Compose contract preflight,
  actionlint, PowerShell syntax, документация и full CI classification прошли.
- Полный локальный Quality Gate прошел: restore, format, build без warnings/errors,
  875 успешных тестов, 22 штатно пропущенных browser tests, dependency audit без
  известных уязвимых пакетов. Отдельный полный application Container Smoke
  и браузерный прогон локально не повторялись; они остаются в required CI.
- Read-only проверка target systemd подтвердила loaded/active/enabled timer,
  Persistent=no, точное воскресное расписание и неактивный успешный service.
  Наблюдатель, переданный через stdin без записи файлов и публикации, прочитал
  действующий ledger: observation_success/copy_present/fresh/timer_enabled=1,
  без pending/error. Это проверка совместимости, не приемка нового service.
- CI, публикация и target acceptance v2.51 пока pending.

## Пакет публикации и установки

После фиксации reviewed revision один пакет включает обычный push, продуктовый
PR, squash merge после required full CI, перенос exact reviewed files,
установку нового monitor timer и config на control-plane, применение только
измененных telemetry configurations на прежних pinned digests, bounded target
acceptance с проверкой исчезновения/возврата heartbeat и итоговый evidence PR.

Application release tags и пересборка images для host/config-only границы
не требуются. Откат возвращает прежнюю telemetry configuration и отключает
только новый monitor. Он не меняет weekly backup policy или приватный журнал.

Публичные порты, новые credentials, прямые уведомления, запуск backup вне
расписания, restore и игровая остановка не входят в пакет. Первый реальный
воскресный cycle v2.50 ожидается отдельно; игра вдвоем отложена на
неопределенный срок.
