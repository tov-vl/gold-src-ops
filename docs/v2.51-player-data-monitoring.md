# v2.51 - Мониторинг backup игровых данных

Статус на 2026-10-09: мониторинг установлен и принят, timer включен.
Проверка потери наблюдения и восстановления прошла. Предупреждения остаются
в Prometheus/Grafana, личная доставка отложена по решению владельца.

## Scope и публикация

R3: read-only наблюдатель control-plane, отдельный минутный systemd timer,
OTLP/HTTP receiver на внутреннем 4318, пять правил Prometheus и provisioned
Grafana dashboard. Существующие pinned telemetry images сохранены; новых
application images, addon packages или migrations нет.

API/Web/PostgreSQL, игра, агент, форматы vault, weekly runner и его доступ
не меняются. Возраст копии считается от capture, занятая игра сама по себе
не является ошибкой. Недостоверный журнал и потеря наблюдений видны отдельно.
См. [процедуру установки, проверки и отката](game-player-data-monitoring.md).

## Приемка установки

Владелец подтвердил единый пакет публикации, установки и итогового evidence PR.
Наблюдатель, config и units установлены на control-plane; production preflight
и sandbox publish прошли. Collector и Prometheus пересозданы на прежних digests.
Grafana также пересоздана после подтверждения устаревшего bind mount, описанного
ниже. Новые credentials и публичные порты не добавлялись.

Проверки непосредственно на control-plane подтвердили:

- совпадение source bytes и units с одобренной ревизией, root ownership,
  отсутствие group/other write, config 0600;
- эффективные sandbox properties: read-only filesystem, пустой capability set,
  NoNewPrivileges, лимиты 30 секунд, 64 MiB и 16 tasks, отсутствие drop-ins;
- успешный service и enabled/active monitor timer;
- два последовательных автоматических heartbeat нового минутного timer;
- свежую успешную observation, наличие молодой копии и включенное weekly
  расписание без ошибок или незавершенных попыток;
- семь healthy правил: две recording rules и пять alert rules;
- provisioned/non-editable dashboard `goldsrcops-player-backup`, исправный
  Prometheus datasource и исполнение всех panel queries;
- внутреннюю telemetry network без опубликованных портов;
- прежние образы всех контейнеров, ID остальных контейнеров, рабочие API/Web
  health endpoints, неизменный deployment environment и закрытый журнал;
- прежние свойства weekly timer/service, включая последнее выполнение
  и ближайший воскресный слот.

Для проверки потери наблюдения остановлен только monitor timer. Заранее
установлен страховочный возврат через 12 минут. После устаревания heartbeat
правило перешло в pending; панель наблюдения показала неизвестное состояние,
панели backup скрыли прежние значения. Полное исчезновение серии также
сохранило предупреждение. Затем зафиксирован `PlayerBackupMonitorUnavailable`
в состоянии firing, других предупреждений не было.

После включения timer предупреждение снялось, актуальные панели восстановились,
получены два новых автоматических heartbeat. Страховочный timer остановлен.
Firing наблюдался через 507,217 секунды от последнего heartbeat, первое healthy
наблюдение в приемке - через 30,313 секунды после возврата timer. Это границы
одного измерения с интервалами scrape/evaluation и операторской проверки,
не обещание точного времени доставки предупреждения.

Финальная сверка в 09:16 UTC подтвердила enabled/active monitor, healthy rules,
исправный dashboard и отсутствие предупреждений. Остальные контейнеры,
weekly timer/service, deployment environment и журнал сохранили исходное
состояние. Backup, игровой stop/start и откат не выполнялись.

## Уточнения установочной проверки

Прежний preflight отличался от Git переносами CRLF/LF; содержимое после
нормализации совпало. Перед установкой прошла прежняя проверка, после - новая.
Установленные новые файлы проверялись по точным байтам одобренной ревизии.

Первоначальная проверка baseline остановилась до записи конфигурации из-за
другого порядка массива mounts в Docker inspect. После сравнения по Destination
подтвердилась неизменность состояния; уточнен только операторский проверочный
скрипт. Исходный baseline и опубликованная реализация не менялись.

Grafana сначала не увидела новый dashboard: контейнер удерживал inode прежнего
каталога, хотя текстовый путь bind mount оставался тем же. Host-каталог содержал
новый файл, контейнерный - нет. После сверки effective Compose и mounts Grafana
пересоздана в предусмотренной пакетом границе: тот же digest, configuration,
network и сохраненный named data volume. Dashboard загрузился, datasource
и все запросы прошли. Исходная причина и оба состояния сохранены в закрытой
операторской записи; baseline не переписывался.

## Оставшаяся приемка

Первый фактический weekly cycle v2.50 ожидается **2026-10-11 в 04:00 МСК**
(01:00 UTC), только при пустом сервере. Он и его off-host snapshot остаются
отдельной приемкой. Вне расписания backup не запускался; stop/start игры,
restore, prune и изменение игровых данных не выполнялись.

Мониторинг не заменяет проверку восстановления каждой будущей копии и не
обнаружит отказ всего Prometheus/Grafana средствами того же стека. Личная
доставка и игра вдвоем остаются отложенными. Приватные адреса, идентификаторы
и журналы хранятся вне Git.
