# Client updater inbox recovery

## Boundary

R3 recovery of the existing client-lab trust engine. The previous weapons
trial remains held and unaccepted. No addon, production, account, credential,
firewall, worker source, pinned dependency or task definition changes here.
Only `Update.Engine.ps1`, `Gateway.ps1` and their existing trusted hashes change.
The existing SYSTEM task performs bounded maintenance with its existing rights.

The gateway previously counted every file left in its 16-entry inbox, including
successful packages. The engine skipped these packages but did not retire them.
Sequence 16 and a subsequent gateway preflight refusal exposed this capacity
boundary. The previous fixed status did not expose an actual inbox count; the
capacity explanation remains an inference until the local migration reads it.

## Preservation and failure behavior

Each idle tick may retire at most eight successful packages. A candidate needs
an administrator-controlled `installed` receipt with the same ID, sequence,
revision and SHA-256, a non-future timestamp, `gameLaunched=false`, and a valid
signature for the same target/session. Expiration does not erase historical
success. Old package pins are not evaluated against today's runner: no historical
package is executed, and its complete bytes must match the trusted receipt.

The package is copied with create-new semantics into the existing protected
private tree, flushed, hash-checked and checked for administrator-only ownership
and write access. Only then is the matching inbox copy retired. Public receipts
remain unchanged as permanent used-ID claims, so old IDs remain unavailable.
The retained package, receipt and runner rollback inputs remain available.
No evidence is overwritten. The protected archive is bounded at 128 entries.

Pending, failed, legacy digest-less, changed, future and otherwise unconfirmed
entries stay in the inbox. A private active transaction blocks maintenance.
An archive collision or uncertain retirement leaves both available copies and
a permanent reconciliation marker. Subsequent ticks report blocked and do not
retry retirement or process another update. No automatic queue drain or replay
is introduced. Active client requests/results/images are outside this operation.

The published updater state adds only aggregate inbox/archive counts. It does
not expose package payloads, paths, signing material or host configuration.
Gateway capacity rejection has the distinct phase `inbox-capacity`.

## Local adoption

The current gateway cannot replace its own privileged code, and a full inbox
also prevents ordinary signed runner staging. Use the reviewed local migration
generated by `New-UpdaterRecovery.ps1`; do not resend the refused rollback.

Inputs are the private lab profile, a fresh saved updater status and the previous
reviewed local trust-migration record. The builder creates a fresh package with
an exact file manifest and target/session/sequence/nine-runner-hash pins. Raw
inputs and package remain outside tracked source. The local installer validates
its file manifest, installed administrator-owned trust paths, exact six-file
trust set, signing-key pin, runner and policy, current user/session and unchanged
task definitions before mutation. An old, changed or previously attempted
migration is rejected.

One local `Start-Update.cmd` invocation requests UAC. It records a permanent
claim, saves the two previous binaries and config, disables only the existing
updater task, installs the two replacements and restores the task. A fresh
successful SYSTEM tick must complete. Failure restores the recorded binaries
and config when safe; uncertain retirement remains blocked for reconciliation.
No general shell, new task, account, permission, service or network rule is added.
The installer never starts Steam or the game. Return its `update-result.json`;
do not rerun a failed installer.

After adoption, independently read `update-status`, verify sequence, all nine
runner hashes, enabled/unblocked state, actual capacity and retained public
results/images. Only then prepare a new signed runner package. Baseline timing
repair and fresh RU/EN weapons trials remain separate gates; maintenance does
not accept the four loading screens or authorize replay of their request.
