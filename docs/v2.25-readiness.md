# GoldSrcOps v2.25 Release Readiness

Acceptance date: 2026-09-23. Status: stable `v2.25.0` published from accepted
`v2.25.0-rc.2`. The first candidate failed external A2S and was rolled back;
its tag remains rejected evidence.

## Scope

The v2.25 release scope is Public Server Join:

- one anonymous, bounded projection for the accepted managed game server;
- deployment-owned public name, advertised host, and game port;
- current A2S state, map, occupancy, and observation freshness without an
  inventory projection;
- a Steam deep link and copyable `connect host:port` command on the public
  status page;
- fail-closed startup for partial or unsafe configuration and omission of the
  join surface when the feature is not configured;
- one plan-first, reversible IPv4 UFW transition that publishes only the
  existing game UDP port while retaining exact-source SSH and ReHLDS RCON.

The candidate also carries the already accepted v2.23 managed-profile and
v2.24 guarded-autostart repository artifacts. The public firewall workflow
hash-binds and verifies those inputs but does not replace the profile, guard,
credential, or active game process.

## Rejected Candidate Record

Candidate `v2.25.0-rc.1` at revision `6d03d8a6263c068447abe0f42690089e2e4ed42a`
passed publication and immutable API/Web image verification. Its digest-pinned
API/Web rollout then produced three healthy samples over at least three
minutes. The first external A2S probe timed out because the accepted host
foundation still restricted UDP 27015 to the control-plane source.

The failure gate stopped acceptance. API and Web were restored to the accepted
v2.22 digests and owner-only environment. The game process, profile, autostart,
database, and every unaffected container remained unchanged. The published
candidate tag is retained as rejected evidence and must never be replaced.

## Claim Boundary

Candidate acceptance can show that the exact API and Web artifacts advertise
one deliberately configured endpoint, expose only the documented public
fields, agree on the Steam and console targets, retain current A2S state, and
allow one operator to connect to the accepted server. The R3 gate can also show
external IPv4 A2S and player traffic, control-plane-only RCON, exact firewall
rollback, image identity, healthy unchanged dependencies, and no unexpected
container or game-host restart.

Acceptance cannot prove discoverability in every Steam browser, sustained
player traffic, multi-player gameplay, long-term availability, high
availability, latency from other regions, or an achieved SLO. It must not
project the inventory host or query port, expose credentials or provider
topology, change the managed game profile, reboot the game host, or enable a
worker to manufacture evidence.
It cannot prove immunity to spoofing or denial-of-service traffic.

## Compatibility Review

- No v2.23, v2.24, or v2.25 database migration, model change, backfill, or data
  correction exists.
- API and Web must roll out together because the new Web reads the additive
  anonymous API response.
- With all four `PublicServerJoin` settings absent, API and Web retain the
  previous public behavior and the join section is omitted.
- Once any setting is present, incomplete or unsafe configuration stops API
  startup instead of advertising an ambiguous endpoint.
- The advertised host and game port are separate deployment inputs. Inventory
  host, query port, notes, credentials, and provider identifiers remain out of
  the response.
- A stale online observation is normalized to `unknown`; it cannot be rendered
  as current online state.
- Rollback restores the accepted v2.22 API and Web digests and their owner-only
  environment, then removes only the owned public IPv4 UFW rule. It requires no
  database, receiver, queue, identity, telemetry, profile, autostart, credential,
  or game-process action.

The public API observed one of four player slots occupied on `de_inferno` on
2026-09-23. An independent external A2S query confirmed one player, zero bots,
and the same map. A later public sample still showed one player. This proves a
single real operator connection, not sustained or multiplayer traffic.

The external RCON challenge is reachable before source authorization in the
pinned ReHLDS protocol. Acceptance therefore used the runtime's exact
`rcon_users` source entry and successful authenticated RCON from the control
plane; a challenge response alone was not counted as authorization evidence.

Do not repeat the complete application suite on the unchanged product revision
merely to duplicate the green product and post-merge workflows. The candidate
tag workflow remains the required independent publication gate.

## Release Sequence

### 1. Merge Readiness And Freeze

1. Merge the public-boundary remediation through protected `main`.
2. Record its exact merge SHA and retain product workflow `#35747517220` and
   post-merge workflow `#35748824441` as the application gates.
3. Confirm `v2.25.0-rc.2` and `v2.25.0` remain unused; retain `rc.1` unchanged.
4. Retain the accepted v2.22 API/Web digests, restricted UFW baseline,
   deployment environment, and both rollback commands in the owner-only record.
5. Select one existing public endpoint and matching enabled inventory server.
   Keep the exact address and server ID outside Git.

### 2. Publish And Verify The Candidate

1. Create, locally verify, and push signed annotated tag `v2.25.0-rc.2` at the
   exact remediation merge revision.
2. Require the complete tag workflow and independent published-image checks.
3. Record exact API and Web digests and verify source, revision, version,
   license, and immutable digest identity before any target mutation.

### 3. Capture Baseline And Roll Out

1. Capture sanitized public health, accepted API/Web identity, restart counts,
   current A2S state, game-service continuity, and dependent runtime state.
2. Verify the restricted game-host UFW shape, exact ReHLDS RCON `/32`, accepted
   profile/guard hashes, service invocation, restart count, and disabled agent.
3. Apply the hash-verified public firewall workflow. Prove external A2S,
   unauthorized-source RCON rejection, and authenticated control-plane RCON.
4. Rehearse its exact rollback and final apply without restarting the game.
5. Add the complete reviewed `PublicServerJoin` configuration to the owner-only
   API deployment environment.
6. Replace API and Web only, pinned to the independently verified candidate
   digests. Preserve every unaffected component.

### 4. Accept Or Roll Back

1. Collect three healthy read-only samples spanning at least three minutes for
   public health, exact API/Web identity, restart counts, and dependent runtime
   continuity.
2. Verify the anonymous API contains only the documented fields and the public
   page renders the expected public name, endpoint, map, occupancy, and
   freshness without inventory or credential data.
3. Repeat external A2S, unauthorized-source RCON rejection, authenticated
   control-plane RCON, and the exact public-firewall marker gate. Verify the
   Steam deep link and copied command resolve to that same endpoint.
4. Complete one operator connection and verify a later A2S observation updates
   occupancy. A multi-player session is not required.
5. On failure, restore API and Web to the accepted v2.22 digests and owner-only
   environment and disable only the reviewed public firewall overlay. Do not
   alter game configuration, restart the game, or mutate durable data to make a
   check pass.

### 5. Promote And Close

After target acceptance, create signed stable tag `v2.25.0` at the exact
candidate revision. Require digest-preserving promotion and independent stable
smoke, then update this record, release notes, backlog, and README in one short
evidence pull request.

## Failure Rules

- Stop on the first unexplained CI, artifact, configuration, health, response,
  endpoint, A2S, join, identity, restart, or continuity failure.
- Never retry an uncertain mutation, replace a published tag, rebuild an
  accepted image, project an inventory address, or change the game server to
  make acceptance pass.
- Stop for a new decision if the advertised endpoint differs from the reviewed
  game server or if rollback cannot restore both the recorded API/Web and
  restricted UFW boundaries.
