# GoldSrcOps v2.25 Release Readiness

Review date: 2026-09-22. Status: readiness pending merge; candidate not yet
published or deployed.

## Scope

The v2.25 release scope is Public Server Join:

- one anonymous, bounded projection for the accepted managed game server;
- deployment-owned public name, advertised host, and game port;
- current A2S state, map, occupancy, and observation freshness without an
  inventory projection;
- a Steam deep link and copyable `connect host:port` command on the public
  status page;
- fail-closed startup for partial or unsafe configuration and omission of the
  join surface when the feature is not configured.

The candidate also carries the already accepted v2.23 managed-profile and
v2.24 guarded-autostart repository artifacts. Those game-host changes passed
their own target acceptance before this release and are not applied, repeated,
or reconfigured by the v2.25 container rollout.

## Claim Boundary

Candidate acceptance can show that the exact API and Web artifacts advertise
one deliberately configured endpoint, expose only the documented public
fields, agree on the Steam and console targets, retain current A2S state, and
allow one operator to connect to the accepted server. It can also show exact
image identity, healthy unchanged dependencies, and no unexpected container or
game-host restart.

Acceptance cannot prove discoverability in every Steam browser, sustained
player traffic, multi-player gameplay, long-term availability, high
availability, latency from other regions, or an achieved SLO. It must not
project the inventory host or query port, expose credentials or provider
topology, change the managed game profile, reboot the game host, or enable a
worker to manufacture evidence.

## Compatibility Review

- No v2.23, v2.24, or v2.25 database migration, model change, backfill, or data
  correction exists.
- API and Web must roll out together because the new Web reads the additive
  anonymous API response.
- With all four `PublicServerJoin` settings absent, API and Web retain the
  previous public behavior and the join section is omitted.
- Once any setting is present, incomplete or unsafe configuration stops API
  startup instead of advertising an ambiguous endpoint.
- The advertised host and game port are separate deployment inputs. Inventory
  host, query port, notes, credentials, and provider identifiers remain out of
  the response.
- A stale online observation is normalized to `unknown`; it cannot be rendered
  as current online state.
- Rollback restores only the accepted v2.22 API and Web digests and their
  owner-only environment. It requires no database, receiver, queue, identity,
  telemetry, game-host, profile, or autostart action.

## Release Sequence

### 1. Merge Readiness And Freeze

1. Merge this documentation-only readiness record through protected `main`.
2. Record its exact merge SHA and retain product workflow `#35747517220` and
   post-merge workflow `#35748824441` as the application gates.
3. Confirm `v2.25.0-rc.1` and `v2.25.0` remain unused.
4. Retain the accepted v2.22 API and Web digests, deployment environment, and
   rollback commands in the owner-only record.
5. Select one existing public endpoint and matching enabled inventory server.
   Keep the exact address and server ID outside Git.

### 2. Publish And Verify The Candidate

1. Create, locally verify, and push signed annotated tag `v2.25.0-rc.1` at the
   exact readiness merge revision.
2. Require the complete tag workflow and independent published-image checks.
3. Record exact API and Web digests and verify source, revision, version,
   license, and immutable digest identity before any target mutation.

### 3. Capture Baseline And Roll Out

1. Capture sanitized public health, accepted API/Web identity, restart counts,
   current A2S state, game-service continuity, and dependent runtime state.
2. Do not run a migration, backup/restore rehearsal, game-host apply, reboot,
   profile transition, queue operation, worker activation, or identity change.
3. Add the complete reviewed `PublicServerJoin` configuration to the owner-only
   API deployment environment.
4. Replace API and Web only, pinned to the independently verified candidate
   digests. Preserve every unaffected component.

### 4. Accept Or Roll Back

1. Collect three healthy read-only samples spanning at least three minutes for
   public health, exact API/Web identity, restart counts, and dependent runtime
   continuity.
2. Verify the anonymous API contains only the documented fields and the public
   page renders the expected public name, endpoint, map, occupancy, and
   freshness without inventory or credential data.
3. Verify external A2S reaches the advertised endpoint and the Steam deep link
   and copied console command resolve to that same endpoint.
4. Complete one operator connection and verify a later A2S observation updates
   occupancy. A multi-player session is not required.
5. On failure, restore only API and Web to the accepted v2.22 digests and
   owner-only environment. Do not alter the game host or durable data to make
   the check pass.

### 5. Promote And Close

After target acceptance, create signed stable tag `v2.25.0` at the exact
candidate revision. Require digest-preserving promotion and independent stable
smoke, then update this record, release notes, backlog, and README in one short
evidence pull request.

## Failure Rules

- Stop on the first unexplained CI, artifact, configuration, health, response,
  endpoint, A2S, join, identity, restart, or continuity failure.
- Never retry an uncertain mutation, replace a published tag, rebuild an
  accepted image, project an inventory address, or change the game server to
  make acceptance pass.
- Stop for a new decision if the advertised endpoint differs from the reviewed
  game server or if rollback cannot restore the recorded API/Web boundary.
