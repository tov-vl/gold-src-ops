# v2.128 - Snapshot retention health in the Operator portal

## Scope and compatibility

R1, API and Web only. The additive Operator-only
`GET /api/operator/retention-health` feeds the static BFF page
`/operator/retention-health` and a seventh card on `/operator/health`.
The existing six-source download stays unchanged and the overview states its
scope. No cleanup request, worker, retention policy, batch/delay, rule, threshold,
Grafana, IRM, provider, credential, permission, schema, game/agent or Archive
cadence change is introduced. Public and Reader projections stay unchanged.

The trusted private Prometheus origin is reused. Exactly two requests read
twelve raw worker gauges and the existing three-alert group. Each request has
a five-second header/body deadline and 32 KiB response bound; metrics are
limited to 48 samples, at most four complete sources. No retry, redirect,
arbitrary query, historical aggregation or raw provider payload is added.
Source identity is only used internally to detect duplicates.

The BFF keeps bearer tokens server-side. Its seven-second, 16 KiB read
independently validates the result before static rendering. Endpoint, page and
denied responses are no-store. An older API yields an unavailable page/card;
mixed deployment does not invent healthy data. Manual Refresh reads each
configured source once, with failure isolation and request cancellation.

## Interpretation

Running, Error, Disabled, Stale and Unknown are distinct. One valid enabled
source observed within 120 seconds is required. Multiple current enabled
sources are Unknown. A disabled replica cannot hide an active error or old
active observation. Query samples and rule evaluations must be nonfuture and
at most 60 seconds old. Missing or malformed sections fail independently.

The page displays last cycle start/completion/success/failure, last duration,
consecutive failures, in-progress and completion age. The existing observation
budget is 300..172860 seconds (660 seconds at production defaults), not a query
timeout or latency SLO. Empty and full-batch successful passes are progress;
they do not prove backlog size or completion of all eligible cleanup. Startup
has no invented completion. Restart does not reuse process history. Gauge
callbacks are independent, so timestamps are bounded against the query time
without requiring an atomic export or ordering completion before observation.

Warnings retain their own snapshot time and Inactive, Pending or Firing state.
A healthy worker does not clear or reinterpret warnings. The page cannot
restart, replay, acknowledge, silence or change policy. First checks link to
the existing [retention runbook](v2.127-retention-liveness.md).

## Verification and release gates

Focused source/service/API/BFF/page, overview isolation and desktop/mobile
browser fixtures cover stale/future/malformed data, duplicate sources,
independent rules, role denial, bounded reads and server-side bearer transport.
Audit-enabled restore, format, warning-free build, tests and vulnerability audit
passed: 1,985 tests succeeded; 69 opt-in browser cases were skipped in that
suite. A separate installed-Chrome run passed 41 focused Web cases, including
the desktop/mobile retention and overview fixtures with JavaScript disabled.
Fifty-two source/service/API cases passed again after review fixes. Final scoped
inspection is running; findings and exceptions will be recorded before merge.

Required PR/main CI, immutable candidate verification, digest-pinned API/Web
rollout, independent runtime and authenticated Operator acceptance, stable
promotion without rebuild and final documentation CI remain pending.

Rollback restores the previous API and Web digests with unchanged configuration.
No database migration or monitoring-policy rollback is needed. The Archive
schedule remains hourly at minute 53; irregular hosted schedule delivery is a
separate open question, not a gate for this release.
