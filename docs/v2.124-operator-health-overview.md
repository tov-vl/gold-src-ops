# v2.124 - Operator operations health overview

## Scope and claim

The Operator-only static SSR page `/operator/health` combines four existing
read-only sources: game-host health, Archive health, polling health and recorded
credential expiry. A navigation link and fixed detail links make it a starting
point for triage. Refresh obtains a new composition without JavaScript.

Each source is read exactly once, concurrently, using the existing server-side
BFF clients and their current response/deadline limits. Expected transport,
timeout and invalid-response failures affect only that source. Caller
cancellation reaches all four reads and aborts rendering without a retry.
Operator authorization runs before source reads; Reader and anonymous users do
not receive the overview or its navigation. All route variants retain no-store,
including authorization redirects. Existing detailed pages and downloads remain
compatible.

## Independent state and bounded presentation

Generated time describes this composition. Each card separately retains its
valid source evaluation timestamp and API snapshot freshness. Available means
an available API snapshot, not global health. Missing, future or invalid data
is Unknown; old snapshots are Stale. There is no combined healthy status.

Game-host cards use their existing three-minute observation boundary and the
fixed five component labels. The existing 17 warning names, active states,
unique names and independent one-minute rule time are validated before rendering.
Raw provider descriptions and component strings are not reflected.

Archive and polling reuse the accepted Web projections and existing freshness
boundaries. Their warning snapshots remain independent of observer state or
worker progress. The overview lists only validated Pending/Firing warnings;
an empty list establishes absence only within a fresh, available rule snapshot.
Unavailable or stale rules never become an empty healthy list.

Recorded credential purposes reuse the existing four-entry validator, exact
state/date rules and minute-precision labels. Due and recorded-expired states
are visually distinguished. These are metadata observations, not provider
validity probes or evidence that a credential works. Detail links retain actual
verification times and precision. Existing credential warning delivery is not
re-evaluated or changed by viewing this page.

All labels, paths and interpretation text are fixed. The composition is bounded
to four cards, five host components, four credential purposes and at most 24
active warning entries. No arbitrary provider text, secret value, credential
identifier, source identity or private endpoint is projected. The existing
download link performs a separate read of game-host, Archive and polling; it
does not include credential metadata or promise equality with this page.

## Delivery and rollback

R1, Web-only. Reuse existing API contracts and running API/receiver identities.
No schema, worker, rule, threshold, permission, provider, secret, game/agent,
Archive schedule or storage write changes. Archive scheduling investigation
remains an independent operational follow-up.

Freeze the reviewed source, immutable candidate digests and previous Web image.
Install only the verified Web digest and recreate only Web. Preserve the exact
previous deployment.env bytes and fourteen other container identities, images,
restart counts, mounts, configured networks and protected monitoring files.
Known-boundary rollback restores only the prior Web image slot/runtime; unknown
drift or uncertain side effects require reconciliation, not automatic retry.
Stable promotion must reuse accepted candidate digests without rebuilding.

## Verification and readiness

Focused cases cover all 16 source-availability combinations; exact freshness,
future, duplicate, malformed and oversized data; source/rule independence;
recorded expiry semantics; role denial without upstream reads; and concurrent
request cancellation through the static SSR page. The browser fixture uses
JavaScript disabled, server-held bearer tokens, desktop/mobile layouts, partial
failure Refresh and detail/return navigation.

The audit-enabled local quality gate passed restore, format, a warning-free
build, 1,742 tests and the dependency audit. Its 67 opt-in browser cases are
reserved for hosted CI. Final focused checks passed 39 cases and the actual
script-disabled desktop/mobile browser fixture after inspection fixes.
Scoped InspectCode completed with zero errors. Its four existing Razor path
warnings concern unchanged mapped /auth/login and /auth/logout endpoints,
which the HTML inspection resolves as wwwroot files. Introduced findings were
fixed; reviewed notes preserve xUnit cancellation semantics, existing host and
file conventions, and already bounded enumeration. No suppression was added.

Required PR/main CI, immutable publication, independent Web-only runtime and
authenticated overview acceptance passed. Released and installed as v2.124.0.
Test fixtures do not prove live failure handling, notification delivery, complete source coverage,
Archive Recovery or an achieved availability SLO.
