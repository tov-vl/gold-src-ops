# v2.80 - Полная справка в пяти сообщениях чата

Состояние на 2026-10-19: addon 0.27.0 принят в main через PR #367 и установлен
на production. Согласованный plan завершен как `accepted`; независимая
техническая приемка, поиск exact/contains и backup monitor прошли. Откат
не потребовался. Класс риска - R1, только игровой addon. Владелец завершил
проверку `/help` в реальном клиенте RU/EN, включая повтор после cooldown.
Execution claim и закрытые evidence хранятся в записи владельца; ниже приведены
только безопасные идентификаторы.

## Причина и изменение

Визуальный проход 2026-10-17 подтвердил оформление RU/EN, но на обоих снимках
`/help` видны только последние пять сообщений. Первая строка с `/menu`,
`/profile` и `/settings` отсутствует. Addon 0.26.0 посылает четыре строки команд
и две строки состояния сохранения. В [исходнике чата Valve](https://github.com/ValveSoftware/halflife/blob/master/cl_dll/saytext.cpp)
`MAX_LINES` равен 5; при заполнении истории новая строка вытесняет старую.
Это объясняет наблюдение. Перенос длинных строк также занимает место, поэтому
число сообщений само по себе не доказывает отображение на любом разрешении.

Addon 0.27.0 оставляет четыре строки команд и объединяет статусы сохранения
в пятую. Независимо отражаются все четыре сочетания: ничего не сохранено,
сохранен только HUD, сохранены только язык/оружие, сохранены оба набора.
Используются прежние проверки точного readback nVault; pending, ошибки чтения,
недоступное хранилище и несовпадение записи не объявляются сохранением.

Ответ остается приватным, с прежними цветами и cooldown 5 секунд. `/settings`
сохраняет отдельные сообщения. Форматы vault, записи статистики, HUD, меню,
выдача оружия и поиск v1/v2 не меняются. API, Web, агент и backup policy
не входят в изменение. Чтение справки не записывает и не сбрасывает настройки.

## Локальная проверка

- На исходном 0.26.0 новый лимит пяти сообщений дал ровно два ожидаемых отказа,
  по одному для RU и EN. Других assertion failures в этом проходе не было.
- Продукт и все пять существующих fixtures скомпилированы AMXX 1.10.0.5481 /
  ReAPI 5.24.0.300. Словарь прошел проверку 70 ключей на двух языках.
- На исправлении прошли 17 сценариев в изолированном ReHLDS 3.15.0.896 /
  ReGameDLL 5.30.0.814 за 118,502 секунды. Контейнер не имел сети и опубликованных
  портов; входы были read-only. Нет assertion failures и AMXX error logs.
- Проверены пять сообщений и первая строка команд, RU/EN и цветной byte budget,
  cooldown, отсутствие замены меню и потери welcome. Real-nVault fixture
  проверяет четыре сочетания сохранения на обоих языках, независимые ошибки
  чтения, pending и отсутствие записей при чтении справки.
- Прежние сценарии подтверждают reconnect/map reload, сохранность статистики,
  профиль/рейтинг, HUD, девять наборов оружия и поиск v1/v2 с общим cooldown.
  Поисковая нагрузка на 4096 синтетических записей также прошла.
- Проверены состав и хеши package, отказ перезаписи существующего результата
  и сохранение включенного поиска. Loader и конфигурация побайтно совпали
  с сохраненным package 0.26.0; меняются только plugin и словарь.

Полный локальный .NET/browser suite и прежние installer/recovery fixtures
не повторялись: их реализация этим срезом не меняется. Required CI прошел
по предусмотренному [addon-only маршруту](release-process.md).
Техническая production acceptance и последующая проверка исправленного `/help`
реальным игровым клиентом описаны отдельно ниже.

## Production acceptance

Независимая приемка подтверждена 2026-10-17 16:26:55 MSK. Выполнен именно согласованный
plan `ef13597729a1e3e67147cf8c050c6bdbc03c0431a80935980f48d5e485205615`,
одна попытка `apply`, результат `accepted`. Staging сверил два manifest,
восемь payload и hook; штатный host dry run завершился `verified-plan`.
Перед остановкой workflow подтвердил отсутствие игроков.

- Внешняя приемка через control-plane приняла обе версии: прежнюю 0.26.0 и
  установленную 0.27.0. Подтверждены загруженная версия, `PLAYER_HELP_STATUS`
  с `lines=5`, RU/EN, private scope, cooldown, отсутствие storage writes,
  готовность nVault и штатный lookup v1. AMXX errors отсутствуют.
- Workflow сверил четыре позиции закрытых vault/journal до и после установки,
  до запуска игры; данные не восстанавливались и не сбрасывались. Журнал
  подтверждает переход через runtime acceptance без failed/rollback phases.
- Независимая сверка заново вывела ожидаемый baseline из сохраненного прежнего
  baseline и live payload/receipt, затем сравнила его с текущим baseline и
  accepted evidence. Все 24 записи согласованы. Изменились ровно три записи:
  plugin, dictionary и installation receipt; loader/config и остальные
  invariants совпали. Все 23 workflow-файла остались прежними.
- Игра запущена с новой invocation; агент и все девять контейнеров control-plane
  сохранили runtime fingerprint. Running/baseline guards прошли, очередь/spool
  в штатном состоянии, local A2S и public online подтверждены, pending нет.
- Два API lookup дали `fresh` с пустым результатом: exact без нового поля match
  и contains с явным match. Между запросами выдержаны 11 секунд, повторов нет.
  Синтетический ник не создавал записей игроков.
- Backup monitor: observation success, timer enabled и copy present равны 1;
  reconciliation, service failed и missed cycle равны 0. Возраст наблюдения
  при проверке - 52,5 секунды. Все семь recording/alert rules здоровы,
  активных backup warnings нет. Backup вручную не запускался, расписание
  и monitoring configuration не менялись.

По журналу от фазы stopping до запроса запуска прошло 25,59 секунды, до
runtime acceptance - 40,74 секунды. Это интервалы workflow, не отдельный
замер сетевой недоступности. API, Web, агент, базы, образы и теги не обновлялись.
Откат не потребовался. Перед любым будущим откатом нужен отдельный reverse plan;
повтор уже принятого operation запрещен.

## Клиентская приемка

2026-10-19 владелец завершил проверку измененного `/help` в реальном клиенте
примерно в 11:34 МСК. В сообщении приложены отдельные снимки RU и EN; успешный
повторный вызов после пяти секунд подтвержден владельцем отдельно.

- На обоих снимках одновременно видны все пять строк, включая первую с `/menu`,
  `/profile` и `/settings`, остальные команды и объединенный статус сохранения.
- Цветное оформление отображается; обрезания текста на присланных кадрах нет.
- Повтор после cooldown также прошел успешно по подтверждению владельца.

Клиентский gate v2.80 закрыт. Это свидетельство текущего измененного `/help`,
отдельное от прежнего визуального прохода addon 0.26.0 и технической приемки.

При проверке владелец также отметил три нецветных сообщения при каждом открытии
`My Settings`. В addon 0.27.0 `OpenPlayerSettings` отправляет их безусловно, включая
повторный показ меню после переключения HUD. Это отдельный предложенный
срез: показывать текущие значения и статус сохранения внутри меню, открывать
настройки без сообщений в чат и отправлять короткое цветное подтверждение только
при изменении настройки. Состояние "только на это подключение" должно оставаться
явным. Изменение настроек в v2.80 не реализовывалось.

## Установка, приемка и откат

1. Source delivery завершен через PR #367 и успешный post-merge CI. Использовать
   проверенные байты package без пересборки. Новые container images и release
   tags для этого addon-only среза не нужны.
2. Перед установкой свежим read-only preflight сверить принятый 0.26.0, его
   package/receipt, backup baseline, отсутствие pending, состояние vault и
   игры/агента. Зафиксировать новый operation ID, полные хеши входов и bounded
   acceptance hook в закрытой записи владельца по
   [штатному workflow](v2.64-addon-upgrade-workflow.md). Проверить этот конкретный
   plan локально, согласовать frozen production bundle, затем выполнить
   staging и штатный host dry run перед единственной попыткой apply.
3. Непосредственно перед остановкой потребовать пустой сервер. Выполнить одну
   установку 0.26.0 -> 0.27.0 штатным claimed workflow: остановить только игру,
   сверить закрытые vault/journal hashes, заменить plugin и словарь вместе,
   сохранить loader/config и текущие данные, запустить игру.
4. Независимо подтвердить live payload hashes, версию 0.27.0,
   `PLAYER_HELP_STATUS` с `lines=5`, готовые vault без ошибок, A2S, public online,
   прежний поиск exact/contains и состояние очереди/spool. RCON использовать
   только через существующий control-plane. Сверить неизменность агента,
   прочих runtime, отсутствие AMXX errors и pending. Завершить reconciliation
   backup baseline по сохраненным previous/accepted evidence, проверить
   schedule guards и monitor.
5. При отказе использовать сохраненный package 0.26.0 штатным rollback hook,
   сохранив текущие vault/journals без restore. Если откат нужен после принятой
   установки, оформить отдельный reverse plan с новым operation ID. Не повторять
   неопределенную мутацию и не удалять pending без reconciliation.
6. В реальном клиенте на RU и EN вызвать `/help` после завершения welcome:
   видны первая строка `/menu` / `/profile` / `/settings`, остальные команды и
   единый статус сохранения. Проверить цвета, отсутствие обрезания в режиме
   OpenGL 1920 x 1200 и повтор после cooldown. Оформить итоговую приемку отдельно
   от движковых доказательств. Игра вдвоем для этого среза не требуется.
