# v2.80 - Полная справка в пяти сообщениях чата

Состояние на 2026-10-17: addon 0.27.0 реализован, проверен и упакован локально.
Review, PR CI, merge и установка еще не выполнены. Класс риска - R1, только
игровой addon. Этот документ задает план поставки, но не execution claim.

## Причина и изменение

Визуальный проход 2026-10-17 подтвердил оформление RU/EN, но на обоих снимках
`/help` видны только последние пять сообщений. Первая строка с `/menu`,
`/profile` и `/settings` отсутствует. Addon 0.26.0 посылает четыре строки команд
и две строки состояния сохранения. В [исходнике чата Valve](https://github.com/ValveSoftware/halflife/blob/master/cl_dll/saytext.cpp)
`MAX_LINES` равен 5; при заполнении истории новая строка вытесняет старую.
Это объясняет наблюдение. Перенос длинных строк также занимает место, поэтому
число сообщений само по себе не доказывает отображение на любом разрешении.

Addon 0.27.0 оставляет четыре строки команд и объединяет статусы сохранения
в пятую. Независимо отражаются все четыре сочетания: ничего не сохранено,
сохранен только HUD, сохранены только язык/оружие, сохранены оба набора.
Используются прежние проверки точного readback nVault; pending, ошибки чтения,
недоступное хранилище и несовпадение записи не объявляются сохранением.

Ответ остается приватным, с прежними цветами и cooldown 5 секунд. `/settings`
сохраняет отдельные сообщения. Форматы vault, записи статистики, HUD, меню,
выдача оружия и поиск v1/v2 не меняются. API, Web, агент и backup policy
не входят в изменение. Чтение справки не записывает и не сбрасывает настройки.

## Локальная проверка

- На исходном 0.26.0 новый лимит пяти сообщений дал ровно два ожидаемых отказа,
  по одному для RU и EN. Других assertion failures в этом проходе не было.
- Продукт и все пять существующих fixtures скомпилированы AMXX 1.10.0.5481 /
  ReAPI 5.24.0.300. Словарь прошел проверку 70 ключей на двух языках.
- На исправлении прошли 17 сценариев в изолированном ReHLDS 3.15.0.896 /
  ReGameDLL 5.30.0.814 за 118,502 секунды. Контейнер не имел сети и опубликованных
  портов; входы были read-only. Нет assertion failures и AMXX error logs.
- Проверены пять сообщений и первая строка команд, RU/EN и цветной byte budget,
  cooldown, отсутствие замены меню и потери welcome. Real-nVault fixture
  проверяет четыре сочетания сохранения на обоих языках, независимые ошибки
  чтения, pending и отсутствие записей при чтении справки.
- Прежние сценарии подтверждают reconnect/map reload, сохранность статистики,
  профиль/рейтинг, HUD, девять наборов оружия и поиск v1/v2 с общим cooldown.
  Поисковая нагрузка на 4096 синтетических записей также прошла.
- Проверены состав и хеши package, отказ перезаписи существующего результата
  и сохранение включенного поиска. Loader и конфигурация побайтно совпали
  с сохраненным package 0.26.0; меняются только plugin и словарь.

Полный локальный .NET/browser suite и прежние installer/recovery fixtures
не повторялись: их реализация этим срезом не меняется. Required CI должен
подтвердить предусмотренный [addon-only маршрут](release-process.md).
Свежая проверка реальным игровым клиентом и production acceptance еще не пройдены.

## Установка, приемка и откат

1. Провести review, ordinary push/PR, required CI и squash merge. Сверить дерево
   merge с проверенным head и дождаться post-merge CI. Новые container images
   и release tags для этого addon-only среза не нужны.
2. Перед установкой свежим read-only preflight сверить принятый 0.26.0, его
   package/receipt, backup baseline, отсутствие pending, состояние vault и
   игры/агента. Зафиксировать новый operation ID, полные хеши входов и bounded
   acceptance hook в закрытой записи владельца по
   [штатному workflow](v2.64-addon-upgrade-workflow.md). Проверить этот конкретный
   plan локально и штатным dry run, затем согласовать frozen production bundle.
3. Непосредственно перед остановкой потребовать пустой сервер. Выполнить одну
   установку 0.26.0 -> 0.27.0 штатным claimed workflow: остановить только игру,
   сверить закрытые vault/journal hashes, заменить plugin и словарь вместе,
   сохранить loader/config и текущие данные, запустить игру.
4. Независимо подтвердить live payload hashes, версию 0.27.0,
   `PLAYER_HELP_STATUS` с `lines=5`, готовые vault без ошибок, A2S, public online,
   прежний поиск exact/contains и состояние очереди/spool. RCON использовать
   только через существующий control-plane. Сверить неизменность агента,
   прочих runtime, отсутствие AMXX errors и pending. Завершить reconciliation
   backup baseline, проверить schedule guards и monitor.
5. При отказе использовать сохраненный package 0.26.0 штатным rollback hook,
   сохранив текущие vault/journals без restore. Если откат нужен после принятой
   установки, оформить отдельный reverse plan с новым operation ID. Не повторять
   неопределенную мутацию и не удалять pending без reconciliation.
6. В реальном клиенте на RU и EN вызвать `/help` после завершения welcome:
   видны первая строка `/menu` / `/profile` / `/settings`, остальные команды и
   единый статус сохранения. Проверить цвета, отсутствие обрезания в режиме
   OpenGL 1920 x 1200 и повтор после cooldown. Оформить итоговую приемку отдельно
   от движковых доказательств. Игра вдвоем для этого среза не требуется.
