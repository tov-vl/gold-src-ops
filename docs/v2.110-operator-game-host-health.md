# v2.110 - Operator game-host health

## Scope

Add a read-only `/operator/game-host-health` page and
`GET /api/operator/game-host-health` for the existing Operator role with a
stable subject. Reader and anonymous access stay denied. The BFF forwards its
server-held access token; the browser receives only a sanitized projection.
Both surfaces use `Cache-Control: no-store`.

The five cards cover agent/queue, player backup, disk/inodes, RAM/swap and
sampled CPU. Measurements include the four fixed storage roles and retain
valid zero values. Missing values remain unknown. Backup source and weekly
outcome are separate. No new warning threshold or write control is introduced.

## Data ownership and limits

Infrastructure embeds the canonical v2.107 dashboard JSON at build time and
uses its fixed panels 1-21. This is deliberate reuse of the accepted PromQL,
including its source freshness gates, pending/firing priority, complete-storage
requirement and independent RAM/CPU validity. A change to that dashboard must
therefore include the API projection tests and its existing PromQL rehearsal.
Application owns the bounded, sanitized projection. No raw provider response,
host label, private address or secret appears in the HTTP contract.

One fixed instant-query batch is sent per authorized page read. Its evaluation
time comes from the application clock. The request has a five-second total
deadline, a three-second Prometheus query timeout, a 64 KiB response limit and
a 64-sample limit. Redirects, partial-warning results, malformed responses and
transport failures produce unknown data. Request cancellation propagates.
There is no automatic retry or background poller.

Query samples must be no older than 60 seconds and not future-dated. Monitor
observations must be no older than 180 seconds and not future-dated before a
card can assert a current policy state. Duplicate card/metric identities do
not select an arbitrary winner. CPU is observational, without a utilization
warning threshold. A static page is a timestamped snapshot; the Refresh link
performs another authorized server read without JavaScript.

## Configuration

The API feature defaults to disabled. Set `GameHostHealth:Enabled=true` and
`GameHostHealth:PrometheusBaseUrl` to an existing trusted private Prometheus
origin. The reference Compose uses `GOLDSRCOPS_GAME_HOST_HEALTH_ENABLED` and
the existing telemetry network; it opens no new port. The origin cannot contain
credentials, a path, query or fragment. Configuration is checked at startup.

Optional Web `GameHostHealth:GrafanaBaseUrl` creates only fixed dashboard links.
Use HTTPS or an existing loopback HTTP tunnel, without credentials, query or
fragment. Grafana retains its own access and sign-in. If not configured, the
page explains how to use existing private Grafana access and links the runbook.
The Web container receives no Prometheus credentials or raw Prometheus response.

## Delivery boundary

R1 additive read-only application release, version `2.110.0`. Deploy only API
and Web by independently verified candidate digests. Preserve previous API/Web
digests and the deployment configuration; there is no database migration or
durable-state change. Rollback recreates only these two services with their
previous immutable images and restores the feature setting. Game host, agent,
backup journal, rules, Alertmanager, Grafana and identity provider are unchanged.

Required evidence: focused protocol/freshness/authorization tests, complete
.NET quality gate, scoped InspectCode, browser token/no-JavaScript check,
required PR CI, immutable publication, changed-surface deployed smoke and
same-digest stable promotion. Local and remote results are recorded separately.

464 Web and 54 receiver tests, 33 focused health cases and the Chromium
no-JavaScript/token-boundary scenario. One existing concurrent agent test
failed in the initial broad pass, then passed isolated and in the complete

Scoped InspectCode 2026.2.3.1 completed. Applicable new findings were corrected;
the final three-file follow-up has no errors or warnings. Existing bootstrap
and route-file lookup diagnostics, the deprecated static-method suggestion for
a dependency-using service, and opposing trailing-comma style notes remain
explicit inspection limitations. No inspection policy was suppressed.

Isolated API/Web container checks passed before the final disposal/await
cleanup; the final revision subsequently passed the required container CI. A
read-only query rehearsal on the existing private path returned all five cards
and 38 bounded samples.
This pre-deployment query is not acceptance of an installed new API.

The signed `v2.110.0-rc.1` tag is retained. Its
[workflow](https://github.com/tov-vl/gold-src-ops/actions/runs/42247791407)
failed in the existing player-search responsive browser test before all six
publication/verification jobs, which were skipped. The product PR and
post-merge CI passed on the same application tree. No candidate image was
deployed.

A controlled slow-stylesheet fixture reproduced the failure: the test measured
the postback document while its ready state was still `interactive`, before
the responsive stylesheet arrived. The test now waits for the document's load
event before the unchanged geometry assertion; it retains one deliberately
delayed stylesheet response to cover that race. Product CSS, search behavior
and health projection are unchanged. RC1 was not moved or replaced. The same
delayed scenario and all 63 browser cases passed after the correction.
