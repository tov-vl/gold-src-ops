# GoldSrcOps v2.58 - Свежесть публичного рейтинга

## Граница

API наблюдает существующий минутный read-only worker рейтинга. Метрики через
существующий Collector поступают в внутренние Prometheus/Grafana. Публичный
HTTP-контракт, BFF, scoring, addon, vault, схема и расписание backup не меняются.
Личная доставка предупреждений пока не настроена.

## Метрики

Meter `GoldSrcOps`; ресурс API `service_name="GoldSrcOps"`. Метрики не содержат
имена игроков, ключи, адреса, credential references или текст исключений.

| Prometheus series | Значение |
| --- | --- |
| `goldsrcops_leaderboard_enabled` | Настроенный флаг 0/1 |
| `goldsrcops_leaderboard_started_timestamp_seconds` | Запуск экземпляра наблюдения |
| `goldsrcops_leaderboard_observed_timestamp_seconds` | Время observable collection; контроль пути экспорта |
| `goldsrcops_leaderboard_last_attempt_timestamp_seconds` | Последний завершенный проход; 0 до первого |
| `goldsrcops_leaderboard_last_success_timestamp_seconds` | Последний успешный прием снимка; сохраняется при ошибке |
| `goldsrcops_leaderboard_snapshot_available` | Доступный снимок, включая успешный пустой |
| `goldsrcops_leaderboard_snapshot_age_seconds` | Возраст capture источника; 0 при отсутствии снимка, поэтому всегда проверяется availability |
| `goldsrcops_leaderboard_rows` | Число доступных строк, максимум десять |
| `goldsrcops_leaderboard_state` | One-hot `fresh`, `stale`, `unavailable`, `disabled` |
| `goldsrcops_leaderboard_last_result` | One-hot исход последнего прохода |
| `goldsrcops_leaderboard_poll_attempts_total` | Завершенные проходы с фиксированным `result` |
| `goldsrcops_leaderboard_poll_duration_seconds` | Histogram длительности с тем же `result` |

Исходы: `none`, `success`, `operator_busy`, `source_unavailable`,
`credential_unavailable`, `timeout`, `authentication_failed`, `invalid_frame`,
`failed`, `disabled`. `none` существует только до первого прохода; shutdown
cancellation не записывает ошибку или попытку. Отключенный worker не делает
сетевых чтений, но экспортирует флаг и heartbeat. Пустой успешный снимок
доступен. Cache исчезает через прежний однодневный предел; последнее успешное
время остается диагностическим, а не доказательством доступности данных.

## Предупреждения

Четыре правила warning с `for: 5m`, scoped на singleton API, без внешней доставки:

- `PublicLeaderboardMonitorUnavailable`: нет свежего export heartbeat в пределах
  180 секунд, heartbeat из будущего более чем на 30 секунд или обязательные
  gauges отсутствуют/некорректны. Это неизвестность наблюдения.
- `PublicLeaderboardRefreshDelayed`: включенный worker не завершал проход более
  180 секунд, хотя экспорт жив. Наблюдение и работа worker проверяются отдельно.
- `PublicLeaderboardDataUnavailable`: включен рейтинг, но снимка нет. При
  начальном `operator_busy` допускаются 15 минут с запуска, затем пять минут
  pending. Отсутствующий источник или credential не получает этот допуск.
- `PublicLeaderboardSnapshotStale`: доступный снимок старше 180 секунд. Если
  последний исход `operator_busy`, допускается возраст до 900 секунд, затем
  пять минут pending. Постоянная занятость не скрывает предупреждение.

Перед агрегацией выбирается один API resource по последнему heartbeat через
`service_instance_id`. Удержанные gauges прежнего экземпляра после перезапуска
не могут подставить его availability, enabled или busy исход в новое наблюдение.
Счетчики и histogram сохраняют историю проходов разных экземпляров.

Отключенный рейтинг не создает предупреждений о данных или worker. Успешный
пустой снимок не создает warning. Короткая ошибка и восстановление раньше
пятиминутного pending не создают firing. Потеря всего Prometheus/Grafana не
обнаруживается средствами того же стека; uptime/SLO не заявляется.

Dashboard `goldsrcops-public-leaderboard` provisioned/non-editable. Панели
показывают возраст, доступность, последние времена, исходы, счетчики и p95
чтения. Запросы данных требуют живого наблюдения, чтобы удержанные Collector
series не выглядели текущими. Timestamp переводится в миллисекунды для Grafana.

## Развертывание и восстановление

R3: изменение policy и конфигурации мониторинга. Выполняются focused worker,
метрики, 25 сценариев promtool, изолированный OTLP/Grafana цикл ошибок и
восстановления, полный Quality Gate и required CI. На целевом стеке отдельно
проверяется новая policy через bounded synthetic observation в изолированном
контейнерном упражнении; действующий рейтинг не ломается для проверки warning.

Замена только API digest и добавление одного rule_files entry, нового rules
файла и dashboard. Prometheus пересоздается на прежнем digest с прежним named
volume, чтобы atomic replacement bind-файла не оставлял старый inode. Grafana
обычно подхватывает файл через существующий provider; если контейнер удерживает
старый inode каталога, допускается только Grafana recreation на прежнем digest,
configuration и data volume. Collector, Web, PostgreSQL, Caddy и игра сохраняются.

Private record хранит baseline, точные hash-bound inputs, исходную конфигурацию,
predecessor digest и single execution claim. Recovery восстанавливает API,
Prometheus configuration и rules; новые данные и история не удаляются. Существующий
Grafana provider запрещает удаление provisioned dashboard: read-only панель
сохраняется при rollback и показывает неизвестность, без новых активных правил.
Это явно ограниченная recovery boundary, без изменения Grafana database вручную.
Неопределенный side effect требует сверки, а не автоматического повтора.
