# v2.109 - Renderer evidence in the client campaign controller

## Boundary

Status: accepted on 2026-11-06 after required PR/main CI and one new EN
`/profile` native trial through the ordinary controller. This is an R2
controller-only change, with no runner update, protected policy edit, new
permission, addon or production rollout.

New campaigns use `rendererPolicy=required-v1`. The controller invokes the same
process-bound OpenGL parser as `Test-LabRenderer.ps1` and creates a separate,
create-only `campaign-renderer.json` receipt. It binds the exact raw result hash,
job ID, frame hash and bounded identity. Receipt validation independently
reparses the current result; a receipt alone cannot prove renderer identity.
The result's positive game session must match the fresh idle worker's session.

The existing evidence digest includes the renderer receipt alongside native
frames and fixture/cleanup evidence. Explicit visual review still requires all
five frames and the exact collected digest. A new review receipt additionally
binds the renderer receipt hash. UI acceptance is not inferred from a renderer
receipt, and neither raw worker flags nor historical results are rewritten.

The normal campaign report now separates UI acceptance, required/identified
renderer state, bounded engine identity, game/worker session and cleanup.
Prepared or unconfirmed evidence cannot report overall acceptance. This does
not attest hardware acceleration, performance or operation on a locked desktop.

## Compatibility and failure behavior

Campaigns without `rendererPolicy` retain their original UI-only evidence digest
and receipt format. They report `not_required_legacy`, never renderer acceptance.
Read-only inspection can verify their existing evidence without creating a new
receipt, migrating source pins or accepting an old failed request. Existing
source pins continue to block mutation with a changed controller. Unknown
policies and missing/repeated required verifier pins are rejected.

New campaigns pin the shared reviewer and both fixed parser dependencies.
Missing, stale, ambiguous or changed renderer output prevents acceptance. A
changed or deleted receipt after evidence collection is not automatically
recreated. Same-ID resume reconciles an existing attempt without redispatch.
Existing locks, Steam hold, cancellation, deadlines and bounded cleanup remain.

One preserved failed renderer request may remain in the bounded queue after an
independently accepted log archival. Preflight allows that exact terminal class
only when the ready worker confirms its archive and preserved result, and an
existing read-only result command confirms game/config cleanup and the retained
renderer failure. Unknown extra requests, multiple exceptions, changed shapes
or a full queue remain blocked. No result is removed, accepted or made eligible
for archival by this read-only check.
