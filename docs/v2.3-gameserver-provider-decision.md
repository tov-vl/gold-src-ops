# GoldSrcOps v2.3 Game-Server Provider Decision

## Status

Conditionally selected on 2026-08-28 for v2.3 Slice 2. The preferred target is a
self-operated MyArena KVM game VDS, with Timeweb Cloud as the first fallback.
The non-deferred gates and approved checkout completed, and one paid trial host
was provisioned on 2026-09-01. Its provider-independent foundation and
controlled reboot passed. External source-address preservation has also passed;
trial-period public-address stability is the only deferred network check still
open, so the trial is not yet full provider approval.

Credentials, addresses, provider identifiers, exact plans, prices, stock,
checkout details, and provider correspondence are transient procurement or
deployment records and are not versioned in this repository.

## Decision

Operate the first external ReHLDS and ReGameDLL_CS baseline on a self-managed
Linux KVM VDS. Select the smallest current high-frequency resource class that
passes the controlled runtime and no-bot evidence requirements, rather than
binding the repository to a catalog SKU.

MyArena is the conditional first choice because its public material describes
root-operated KVM hosting, game-aware UDP protection, and source/port firewall
controls. Timeweb Cloud is the fallback because it documents portable backups,
public IPv4 allocation, and conventional cloud-server controls. The exact
commercial offer must be selected only at an approved checkout.

The provider-managed Counter-Strike 1.6 product is not selected for the first
baseline because its public contract does not prove that the operator can pin
and retain exact upstream ReHLDS and ReGameDLL_CS artifacts independently of
provider-managed updates.

This is an operational choice, not an application architecture decision. The
provider name, plan, and management API must not enter GoldSrcOps contracts or
domain models.

## Decision Drivers

- Root access and inspectable process ownership are required to verify pinned
  runtime artifacts, systemd behavior, logs, and firewall policy.
- The host must expose the same public A2S and guarded RCON boundary that the
  control plane will use in production.
- RCON must remain restricted to an approved source even when gameplay and A2S
  use the public GoldSrc UDP endpoint.
- Configuration and verified runtime artifacts must be recoverable without a
  provider-specific application integration.
- Moving to another Linux host must require operational work but no GoldSrcOps
  code change.

## Alternatives

- **MyArena managed CS 1.6:** rejected for the first baseline because artifact
  ownership and update behavior are not sufficiently explicit.
- **MyArena KVM game VDS:** conditionally selected because it best combines
  guest ownership with game-oriented network controls.
- **Timeweb Cloud VPS:** first fallback when MyArena cannot satisfy the network,
  ownership, or recovery gate.
- **General-purpose cloud VPS:** reserve fallback when neither shortlisted
  provider can meet the gate without weakening RCON isolation.

The shortlist records durable trade-offs only. Current catalog comparisons and
support conversations belong to private procurement notes.

## Acceptance Gate

Do not order or provision a candidate until all of the following are confirmed
for the exact offer, except for the two empirical checks explicitly deferred by
the bounded trial below:

1. The final one-period price and commitment are understood and separately
   approved.
2. The region is disclosed and one stable dedicated public IPv4 is available
   without CGNAT.
3. The DDoS profile accepts the intended GoldSrc UDP port and preserves the
   original client source address required by the ReHLDS RCON allowlist.
4. The provider does not replace or automatically update files installed inside
   the guest operating system.
5. A supported x86-64 Linux image, KVM virtualization, root SSH, and
   operator-managed systemd services are available.
6. SSH can be restricted to an approved source IPv4 and the game UDP port can
   be registered with the provider's protection controls.
7. Configuration can be exported and restored independently, and cancellation
   has a predictable customer-data deletion path.
8. Strong account login and recovery controls can be enabled before purchase.

A negative answer keeps purchase blocked and moves evaluation to the fallback
without weakening the gate. An ambiguous answer does the same unless it is one
of the two uncertainties explicitly covered by the bounded trial below.

## Bounded Trial Exception

The initial MyArena order may cover one paid period as a small, reversible
validation environment after the final checkout receives separate approval.
This exception defers only these questions:

1. Whether the assigned public IPv4 remains unchanged across guest restarts and
   throughout the continuously paid trial period.
2. Whether the enabled DDoS path preserves the original external client IPv4 in
   UDP packets observed by the guest operating system and ReHLDS.

All other acceptance conditions remain pre-purchase gates. The trial must not
carry a production dependency or irreplaceable data. Immediately after
provisioning:

1. Record the assigned address in private deployment records, restart the guest,
   verify that the address is unchanged, and monitor it for the trial period.
2. Enable protection for the GoldSrc UDP port, send a controlled probe from a
   known external source, and verify the observed source address without
   recording endpoint or credential material in the repository.
3. Exercise the guarded RCON allowlist from the approved source before enabling
   any persistent control-plane polling or command workflow.

The source-address preservation check has passed from the production control
plane. Public-address stability must still pass across the bounded trial before
the host receives final provider approval. A failed check stops the rollout,
must not be compensated for by weakening RCON isolation, and moves the baseline
to the Timeweb fallback. Record only the sanitized pass or fail result in the
repository.

## Records Boundary

The public repository may retain:

- the decision date and sanitized pass or fail status;
- the selected provider, region, and resource class after purchase;
- the accepted network and recovery controls;
- runtime versions, artifact hashes, sanitized firewall shape, and measured
  baseline results.

Keep the following outside the repository:

- changing SKUs, prices, stock snapshots, and checkout captures;
- account, order, invoice, ticket, and management-endpoint identifiers;
- provider correspondence and unsanitized support answers;
- credentials, public endpoints, and secret-bearing recovery material.

Continue the trial-period public-address stability check without recording the
endpoint. The host foundation, source-address path, guarded RCON boundary,
runtime activation, and short post-restart restore check have passed. Keep the
provider decision conditional until the remaining empirical check completes,
